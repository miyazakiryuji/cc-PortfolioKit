# `hearing` コマンド ── カテゴリ別ヒアリング詳細

このファイルは [`hearing-command.md`](./hearing-command.md) の付録として、**本業・副業・活動の各カテゴリで何をどう聞くか** の詳細を切り出したものです。元仕様書 §6〜§8 に相当します。

`hearing` の実装プロンプト ([`commands/hearing.md`](../../commands/hearing.md)) が Step 2 のループメニューで「本業を追加 / 副業を追加 / 活動を追加」のいずれかを選ばれたタイミングで、このファイルを `Read` して該当節のヒアリングを実行する想定です。

§番号は元の `hearing-command.md` のものをそのまま維持しています ── 相互参照と読みやすさのため。

## 6. 本業 1 件分のヒアリング (二段構造)

本業は **「会社単位」と「プロジェクト単位」の二段構造** です。会社の中で複数の PJ を担当して、PJ ごとにツールも成果も違う ── という現実に合わせています。

### 6.1 会社単位の質問 (5〜6 問)

1 つずつ短く、温かいトーンで聞きます。下に書いてあるのは **そのまま画面に出す質問文の確定形** です。仕様メモ ── たとえば「内部で `YYYY-MM` に正規化」のようなもの ── は **絶対に画面に出さない**。

```
1. 会社の名前を教えてください
   → 自由記入。空欄は不可

2. いつから働き始めましたか?
   たとえば「2020-04」「2020/04」「2020 年 4 月」みたいに、年月が分かれば書き方はお任せです。
   → 自由記入

3. そのお仕事、いまも続いていますか?
   1) はい、いまも続いています
   2) いいえ、もう辞めました
   → 2) を選んだ場合のみ次の質問

3-a. ちなみに、いつまで在籍していましたか?
   書き方は始めたときと同じで大丈夫です。
   → 自由記入

4. 肩書きや役職はありましたか?
   たとえば「ソフトウェアエンジニア」「マネージャー」「アートディレクター」「課長」など。
   特になければ「なし」と答えてもらえれば飛ばします。
   → 自由記入

5. その会社でふだんやっていたことを 3〜5 個くらいで教えてください
   1 つずつ言ってもらってもいいし、まとめて言ってもらっても OK。箇条書きに整理します。

6. 会社全体で言える代表的な成果があれば教えてください
   ここで聞いているのは「特定のプロジェクトではなく、その会社にいた期間全体で言える代表的な成果」です。
   このあと印象に残ったプロジェクトを別途聞くので、そちらでは PJ ごとの成果を伺います。
   思いつかなければ「特になし」で大丈夫です。
   たとえば「売上 2 倍」「受賞歴」「制度設計の主担当」「全社の DX 推進」のようなもの。
```

> **質問順序の番号と Markdown 見出し順序の関係**: 上の `1.〜6.` は「ユーザーに聞く順番」です。Markdown 上の `### 役職 / ### 業務内容 / ### 全体の成果` 見出しの並び順とは独立しています (書き出し形式は [`hearing-edit-and-write.md`](./hearing-edit-and-write.md) §11.2 参照)。
>
> **内部処理メモ (仕様書側だけで使う言葉)**: 日付の自由入力は内部で `YYYY-MM` に揃えてから記録する。ただし「正規化」「フォーマット」「YYYY-MM」のような語は **ユーザー画面の質問文には絶対に出さない**。
>
> **5. の質問文の補足**: 質問文上の表現は「ふだんやっていたこと」で本業・副業・活動とも統一する (§7 / §8 と整合)。書き出し時の Markdown 見出しは本業のみ `### 業務内容`、副業・活動は `### やったこと` ── これはパース都合で、ユーザーには見えない区別。

### 6.2 PJ ループへの誘導

会社単位の質問が終わったら、PJ ループへの導入を聞きます。

```
このお仕事の中で、印象に残ったプロジェクトや案件はありますか?
  1) はい、書きたい
  2) いいえ、スキップで
```

`1)` を選ばれたら PJ ループへ、`2)` を選ばれたらこの本業 1 件分の入力は完了。Step 2 (`hearing-command.md` §5.1 のメニュー) に戻ります。

### 6.3 PJ 単位のループ (3 問 × N 件)

PJ 1 件あたり次を聞きます。質問文は下の確定形をそのまま画面に出す想定。

```
PJ 1 件目について教えてください。

a. プロジェクト名や案件名を教えてください
   公開できないお仕事は「〇〇業界の決済システム PJ」のような匿名表記でも大丈夫です。
   → 自由記入

b. このプロジェクトで使ったツール・スキル、ぱっと思い出せるものがあれば教えてください
   思いつかなければ「特になし」で大丈夫です。
   職業によって言い回しが変わる場合があるので、デザイナーなら「使ったツール」、営業なら「扱った商材や業界」のような形でも OK。

c. このプロジェクトでの成果があれば教えてください
   数字で言えるもの、評価されたこと、学んだことなど、書きやすい形で。
   思いつかなければ「特になし」で大丈夫です。
```

1 件入力が終わったら、続けるか確認します。

```
このお仕事で、もう 1 件 PJ を追加しますか?
  1) はい、追加する
  2) いいえ、終わり
```

`1)` ならループ続行、`2)` なら本業 1 件分が完了して Step 2 のメニューに戻ります。

> b. と c. の **「思いつかなければ『特になし』で大丈夫」** の一文は、CLAUDE.md の「補足の書き方ルール」に沿って `(任意)` のような `( )` 表記を使わずに任意性を伝える書き方。`(任意)` を画面に出さないこと。

### 6.4 本業 1 件分のデータ構造 (メモリ上)

メモリ上ではこんな構造で保持します。

```yaml
type: "本業"
name: "株式会社サンプル"
period: "2020-04 〜 現在"          # 内部で正規化済み
role: "シニアソフトウェアエンジニア"  # 空欄可
業務内容:
  - "バックエンド開発リード"
  - "マネジメント"
全体の成果:                        # 任意。スキップなら null
  - "組織のリリース頻度向上"
projects:
  - name: "〇〇プロダクト開発"
    tools: "TypeScript, AWS"        # 任意
    achievements:                   # 任意
      - "レスポンス時間 50% 改善"
  - name: "△△ システム導入"
    tools: "Python, GCP"
    achievements:
      - "MAU 10 万達成"
```

## 7. 副業 1 件分のヒアリング (フラットな 6 問)

副業は **「案件単位 = 1 件」** がふつうなので、本業のような二段構造は不要。フラットに 6 問。下記が画面に出す確定形です。

```
1. 案件名やクライアント名を教えてください
   たとえば「〇〇社」「個人開発の △△」「IT スタートアップ A 社」のような形で。
   公開できないお仕事は匿名でも大丈夫です。
   → 自由記入

2. いつから関わっていましたか?
   書き方は「2022-04」「2022/04」「2022 年 4 月」みたいに、年月が分かれば OK。
   → 自由記入

2-a. それ、いまも続いていますか?
   1) はい、いまも続いています
   2) いいえ、もう終わりました
   → 2) を選んだ場合のみ次を聞く

2-b. (2-a で「いいえ」のとき) ちなみに、いつまで続けていましたか?
   → 自由記入

3. その副業、どんな立場で関わっていました?
   1) 個人で受けた仕事 (業務委託・フリーランス)
   2) 顧問・アドバイザー
   3) 社外取締役
   4) 個人開発・個人プロジェクト
   5) その他 (一言で書いてもらいます)

4. その案件でふだんやっていたことを 1〜3 個くらい教えてください
   1 つずつでも、まとめてでも OK。

5. 使ったツール・スキル、ぱっと思い出せるものがあれば教えてください
   思いつかなければ「特になし」で大丈夫です。

6. 公開できる成果があれば教えてください
   NDA などで書けないものは無理に書かなくて大丈夫。
   思いつかなければ「特になし」で大丈夫です。
```

> **質問文上の `(自由記入)` のような `( )` 補足は画面に出さない**。CLAUDE.md の補足の書き方ルールに沿って、ユーザーに見せる質問文・選択肢ラベルからは `( )` 表記を排除する。
>
> **「業務委託」と「フリーランス」を 1 つに統合**: 税務上ほぼ同じで、書く側がどっちで答えるか迷うのを防ぐため。差別化したい人は `5) その他` で「業務委託 (準委任)」のように書いてもらう。

### 7.1 副業 1 件分のデータ構造 (メモリ上)

```yaml
type: "副業"
name: "〇〇社 技術アドバイザー"
period: "2023-06 〜 現在"
role: "業務委託 (技術アドバイザー)"  # 選択肢のラベル + 自由記入の補足
やったこと:
  - "開発チームの設計レビュー"
  - "採用面接の技術評価"
tools: "Node.js, AWS"           # 任意
achievements:                   # 任意
  - "採用候補者のミスマッチ率を半減"
```

## 8. 活動 1 件分のヒアリング (フラットな 6 問)

活動も副業と同じくフラットに 6 問。聞き方を「活動」モードに調整します。下記が画面に出す確定形です。

```
1. 活動名やイベント名を教えてください
   → 自由記入

2. いつから関わっていましたか?
   書き方は「2021-01」「2021/01」「2021 年 1 月」みたいに、年月が分かれば OK。
   → 自由記入

2-a. それ、いまも続いていますか?
   1) はい、いまも続いています
   2) いいえ、もう終わりました
   → 2) を選んだ場合のみ次を聞く

2-b. (2-a で「いいえ」のとき) ちなみに、いつまで続けていましたか?
   → 自由記入

3. その活動、どんな立ち位置で関わっていました?
   1) 主催した
   2) 運営メンバーとして手伝った
   3) 人前で話した・発表した
   4) 作品やコードを世に出した
   5) 文章や記事を書いた
   6) その他 (一言で書いてもらいます)

4. その活動でふだんやっていたことを 1〜3 個くらい教えてください

5. 関連するスキル・道具があれば教えてください
   思いつかなければ「特になし」で大丈夫です。
   たとえば「イベント運営」「司会進行」「動画編集」「TypeScript」のようなもの。

6. 規模感や成果があれば教えてください
   思いつかなければ「特になし」で大丈夫です。
   たとえば「累計参加者 500 名」「GitHub Star 100」「開催 30 回」「読者 10 万人超」のような数字でも。
```

> **業界用語を排除**: もとの「OSS コミッター / メンテナ」「登壇者 / スピーカー」のような IT 業界寄りの言葉を、誰でも当てはめられる行動ベースの言葉 ── 「人前で話した・発表した」「作品やコードを世に出した」「文章や記事を書いた」── に置き換えた。
>
> **質問文上の `(自由記入)` のような `( )` 補足は画面に出さない**。`( )` 表記をユーザー画面から排除する CLAUDE.md ルールに沿わせる。

### 8.1 活動 1 件分のデータ構造 (メモリ上)

```yaml
type: "活動"
name: "〇〇 Meetup 運営"
period: "2021-01 〜 現在"
role: "主催 / 運営メンバー"
やったこと:
  - "月 1 回の勉強会企画・運営"
  - "スポンサー獲得"
tools: "イベント運営 / 司会進行"   # 任意
achievements:                     # 任意
  - "累計参加者 500 名超"
```
