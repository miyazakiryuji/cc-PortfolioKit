# `create` コマンド仕様

`/cc-portfoliokit:create` の機能仕様。実装プロンプトは [`commands/create.md`](../../commands/create.md) を参照。

---

## 1. 責務

`create` は **ふだん使いのコマンド**。状態を自動判定して 3 つのモードに分岐する。新仕様では `init` → (ユーザー手編集 + `hearing`) → `create` の流れになる。

| 状態 | 進む先 | 何をする |
|---|---|---|
| 素材なし (`init` 未実行 / ファイルが揃わない) | ブランチ A | `init` / `hearing` を促す案内のみ。書き換えない |
| 素材あり / HTML 無し | ブランチ B | テーマ方向性ヒアリング → HTML 生成 |
| 素材あり / HTML あり | ブランチ C | 編集メニュー (6 オプション) |

> 経歴 0 件 (= `work-history.md` にエントリが無い) の状態でも `create` は HTML を生成します。経歴セクションが空のポートフォリオになるだけ。経歴を入れる案内は `guide` の方が丁寧 ── `guide` のブランチ C-1 (経歴 0 件分岐) を参照。

設計の根本ルール:

- **テンプレートを勝手に作らない**。素材は必ず `init` 経由で生成させる。経歴のヒアリングは `hearing` 経由で。
- **生成物は `portfolio.html` の 1 ファイルだけ**。それ以外は明示的指示があったときだけ書き換える。
- **JavaScript / 外部 CSS / 外部フォントを使わない** (オフラインで表示できること)。
- **ファイル分割について**: 実装プロンプトは `commands/create.md` (エントリポイント 115 行) と `commands/create-branch-b.md` (B フロー 313 行) と `commands/create-branch-c.md` (C メニュー 115 行) の 3 ファイルに分かれている。AI が読むときはエントリポイントから対応する付録を `Read` する。

---

## 2. 状態判定 (Step 1)

`./config.md` / `./career/profile.md` / `./career/work-history.md` / `./portfolio.html` の 4 つの存在で状態を決める。前者 3 つがすべて揃っているとき `INPUTS_READY = true`。

```
INPUTS_READY = HAS_CONFIG && HAS_PROFILE && HAS_WORK

!INPUTS_READY             → ブランチ A (init 誘導)
 INPUTS_READY && !HAS_HTML → ブランチ B (初回 HTML 生成)
 INPUTS_READY &&  HAS_HTML → ブランチ C (編集メニュー)
```

---

## 3. ブランチ A: init / hearing 誘導

責務は **案内のみ**。テンプレートを置かない、`Edit` も `Write` もしない。

- 欠けているファイルを列挙
- 新仕様の流れ ── `/cc-portfoliokit:init` → `./assets/` に画像配置 → `config.md` / `profile.md` を手編集 → `/cc-portfoliokit:hearing` → `/cc-portfoliokit:create` ── を案内
- それ以上は何もせず終了

> `init` だけ実行済みで `hearing` 未実行 (= `work-history.md` がテンプレ初期状態のまま、エントリ無し) の場合も、`work-history.md` というファイル自体は存在するので `INPUTS_READY` は成立する → ブランチ B に進む。経歴 0 件の HTML が生成されるが、これは仕様内挙動。

---

## 4. ブランチ B: 初回 HTML 生成

### 4.1 フェーズ構成

```
B-1.   Markdown のパース (config / profile / work-history)
B-1.5. テーマ方向性のヒアリング       ← 配色辞書はスキルから取得
B-1.6. 反映確認 (config.md 再 Read)
B-2.   顔写真の処理
B-3.   HTML 生成 → cc-portfoliokit:portfolio-design スキルに委譲
B-4.   書き出し + 健全性チェック
B-5.   完了報告
```

### 4.2 テーマ方向性ヒアリング (B-1.5)

ユーザーに 3 つの選択肢を提示:

| 選択 | 挙動 |
|---|---|
| 1) このまま生成 | 何もせず B-2 へ |
| 2) 決め直し対話 | Step a〜f を順に実行 |
| 3) AI 提案 | `work-history.md` を読んで案 A/B/C を提示 |

#### Step a〜f (選択 2 の場合)

| Step | 内容 |
|---|---|
| a. 雰囲気 | 6 択 (落ち着き / カジュアル / クリエイティブ / シンプル / ダーク / その他) |
| b. カラー候補 | 雰囲気に応じた 3〜4 組の HEX 候補を提示 + 自由 HEX 入力 |
| c. サイトタイトル | `name` と最新の役職から 2〜3 案を生成 + 自由入力 |
| d. キャッチコピー | 役職・業務・成果から 2〜3 案を生成 + 自由入力 |
| e. セクション構成 | 現状を見せ、必要なら並び替え / 追加削除 |
| f. config.md へ反映 | 該当ブロック直下のみ `Edit` |

#### 雰囲気ごとの推奨カラー (Step b の参考辞書)

具体的な HEX のセット ── 各雰囲気で 3〜4 組 ── は **`skills/portfolio-design/SKILL.md` の §6** に集約してあります。`create.md` の B-1.5 Step b では、ここを参照してユーザーに候補を提示してください。

| 雰囲気 | 大まかな方向 |
|---|---|
| 落ち着き | 紺・濃灰・ダークブルー系 + 金・ベージュ系アクセント |
| カジュアル | 暖色寄りのオレンジ / コーラル + 黄・ターコイズ |
| クリエイティブ | 鮮やかなマゼンタ / パープル + 蛍光緑・サイバーピンク |
| シンプル | モノトーン (グレー・オフホワイト) + 1 色のアクセント |
| ダーク | 黒・濃紺 + 発色の良い水色・ライム |
| その他 | 自由記述に合わせて即興で組み立てる |

#### AI 提案 (選択 3)

`work-history.md` を読み、**3 案 + 「自分で決める」案** を提示。各案には雰囲気・色・タイトル・キャッチコピーをセットで含める。「もう少し明るく」のような要望が来たら、再提案するか Step a〜e に切り替える。

### 4.3 反映確認 (B-1.6)

`config.md` を `Edit` した直後に再 `Read` し、見出し / コメント / 空行を壊していないか確認する。

## 5. ブランチ C: 編集メニュー

### 5.1 トップメニュー (C-1)

6 オプション:

| # | ラベル | 進む先 |
|---|---|---|
| 1) | 細かい項目を変えたい | C-3 |
| 2) | テーマを決め直したい | C-4 |
| 3) | 色だけ変えたい | C-5 |
| 4) | 再生成だけしたい | C-2 |
| 5) | イメージがない、提案してほしい | C-6 |
| 6) | キャンセル | 終了 |

### 5.2 各サブブランチ

| ブランチ | 内容 | 既存/新規 |
|---|---|---|
| C-2 | 単純再生成 (B-1 以降を実行) | 既存 |
| C-3 | 9 項目の詳細編集メニュー (タイトル / カラー / About / 氏名 / 連絡先 / 顔写真 / 職歴追加・編集) | 既存 |
| C-4 | テーマ決め直しウィザード = B-1.5 の 2) を再利用 | 新規 |
| C-5 | 色だけ変更 (雰囲気→候補 or HEX 直接指定) | 新規 |
| C-6 | AI 提案 = B-1.5 の 3) を再利用 | 新規 |

### 5.3 メニュー設計の意図

- 「決められない」ユーザーには `5) イメージがない` を勧める動線を用意。
- 「全部変えたい」(=決め直し) と「ちょっとだけ変えたい」(=色だけ) を分けることで、対話の長さをユーザーが自分で選べる。
- いずれの分岐も最終的に C-2 (再生成) に合流する。中途半端な状態で終わらせない。

## 6. 共通制約

- **HTML 構造 / CSS / 配色 / Markdown 変換 / XSS 対策** はすべて `skills/portfolio-design/SKILL.md` に集約。`create.md` 側で再実装しない。
- `portfolio.html` 以外のファイルは、明示的な指示があったとき ── C-3 / C-4 / C-5 / C-6 ── だけ書き換える。
- 入力に書かれていない情報を勝手に作らない。経歴の捏造は厳禁。
- テンプレートを勝手に作らない。ブランチ A では `init` 誘導のみ。
- 空欄のフィールドはスキルに渡さない、または `null` を渡す。スキル側で「その項目ごと省略」する。
- 性別 `gender` は HTML 出力にも編集メニューにも含めない。スキルにも渡さない。
- 入力ファイルは **YAML フロントマターを使わない `## 見出し` 構造** が前提。パース・編集とも見出し / コメント / 空行を壊さない。
- **顔写真パスの検証**: `## 顔写真のファイル名` の値が `assets/` で始まる相対パスでない、または `..` を含む場合、写真を出さず警告。`<img src>` のホワイトリストはスキル側 §8.2 で再度ガードされる。
- **完了報告のユーザー周知**: 顔写真同梱 / EXIF / 印刷時の mailto 抑制 / PII 拡張項目 / スキル側フォールバック (HEX / lang) の発動 ── 該当する状況だけ B-5-1 のテーブルに沿って付記する。長文のセキュリティ説明にはしない。

## 7. 想定されるエラー / エッジケース

| 状況 | 対応 |
|---|---|
| パース失敗 (見出しが見つからない等) | 具体的なファイル名・原因を伝えて中断。空値で勝手に埋めない |
| HEX 形式不正 (対話入力) | `#` + 6 桁の英数字で再入力を促す |
| HEX 形式不正 (`config.md` 由来) | スキル側 §8.3 で `theme=#4F46E5` / `accent=#F59E0B` にフォールバックし、B-5-1 でユーザーに通知 |
| `language` が BCP 47 形式でない | スキル側 §8.4 で `ja` にフォールバックし、B-5-1 でユーザーに通知 |
| 顔写真ファイル不在 | 写真なしで生成 + 警告 |
| 顔写真 500KB 以上 | 警告 (圧縮推奨) を出しつつ生成 |
| 顔写真パスが `assets/` 配下でない / `..` を含む | 写真なしで生成 + B-5-1 で「パスが規約外」通知 |
| Contact が全空 | スキル側で `<section>` ごと省略。`<h2>Contact</h2>` だけ残らない |
| 入力ファイルが中途半端 (1〜2 個欠け) | ブランチ A に分岐 (init 誘導) |
| ユーザーが対話途中で「やめる」 | そこまでの変更を保持して中断、何が保存されたか報告 |
| 入力 Markdown の URL に `javascript:` / `data:` 等が混入 | スキル側 §8.2 でフィルタ。リンクごと出力しない |
