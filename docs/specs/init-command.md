# `init` コマンド仕様

`/cc-portfoliokit:init` の機能仕様。実装プロンプトは [`commands/init.md`](../../commands/init.md) を参照。

---

## 0. 適用前提

この仕様書は [`hearing-command.md`](./hearing-command.md) の追加と **同時に** 適用される前提で書かれています。`init` から「氏名・職業・経歴の対話ヒアリング」を撤去し、その責務は `hearing` に移管されます。`init` だけを先行変更すると、現行の対話的セットアップを期待しているユーザーが「何も聞かれずに終わった」と戸惑います ── `hearing` 仕様書と一緒に適用してください。

---

## 1. 責務

`init` は cc-PortfolioKit を **初めて使うとき (もしくはやり直したいとき)** に叩く **セットアップコマンド** です。やることは次の 3 つに集約されます。

1. プロジェクト側に **ファイルとフォルダを用意** する
2. **アイコン画像の配置とプロフィール記入** を促す
3. **これからの流れ** ── hearing → create ── を案内する

### 1.1 設計の根本ルール

- **ヒアリングしない**: 氏名・職業・経歴などの中身は一切聞かない。中身は `hearing` (経歴) と手編集 (プロフィール) に委ねる
- **HTML を生成しない**: HTML 生成は `create` の責務
- **既存ファイルを尊重**: すでに何かある場合は確認の上で進める。勝手に上書きしない
- **何度叩いてもおおむね安全**: 同じ場所で 2 回目以降叩いても、既存ファイルは保護される
- **温かい言葉**: 質問文・選択肢・完了メッセージは「親しい先輩がカフェで話しかける」基準。CLAUDE.md「文体のトーン」「補足の書き方ルール」に従う

---

## 2. 起動フロー

```
Step 1. 衝突チェック        — cwd にすでにファイルがあるか確認、必要なら同意を取る
Step 2. ベーステンプレート展開 — templates/ から Markdown 4 つをコピー
Step 3. 完了報告と流れ案内   — これからの流れを伝える
```

各 Step の詳細は §3 以降。

---

## 3. Step 1 — 衝突チェック

cwd に対して以下のパスの存在を `Bash` で確認します。

- `./config.md`
- `./career/`
- `./career/profile.md`
- `./career/work-history.md`
- `./assets/`

### 3.1 何も存在しない場合

何も尋ねず Step 2 に進みます。

### 3.2 1 件以上存在する場合

ユーザーに次の声がけをして、同意を取ります。

```
すでに次のファイルやフォルダが用意されているみたいです:

  <存在するパスを列挙>

どうしましょうか?

  1) 足りないものだけ作る ── おすすめ。既存のファイルには触りません
  2) すべて作り直す ── 既存の中身は捨てて、まっさらなテンプレに入れ替えます
  3) いったんやめる
```

| 選択 | 挙動 |
|---|---|
| 1) | 既存パスはスキップ、新規パスだけ作成して Step 2 に進む |
| 2) | 既存も含めて全部上書き。`templates/` から新しいファイルを書き出す。**ユーザーが書き込んだ内容は消える** ので 1 回目の確認とは別に「本当にいいですか?」を念のためもう一度尋ねる |
| 3) | 「では、また呼んでください」と一言伝えて終了 |

「やめる」「キャンセル」「戻る」などの文字列も `3)` 相当として扱います。

---

## 4. Step 2 — ベーステンプレート展開

プラグイン側 `templates/` から、プロジェクト側の対応パスへコピーします。

| プラグイン側 | プロジェクト側 |
|---|---|
| `templates/config.md` | `./config.md` |
| `templates/profile.md` | `./career/profile.md` |
| `templates/work-history.md` | `./career/work-history.md` |
| `templates/assets-README.md` | `./assets/README.md` |

### 4.1 取得元の解決

`CLAUDE_PLUGIN_ROOT` 環境変数があれば、`$CLAUDE_PLUGIN_ROOT/templates/` を起点に Read する。無い場合はプラグインがインストールされている既知のパスから取得する。

> **絶対ルール**: プラグイン側のファイル (`templates/*` / `commands/*` / `skills/*` / `docs/*` など) は **読むだけで、書き換えない**。コピー先は cwd 配下に限定する。

### 4.2 Step 1 で `1)` が選ばれた場合

既存パスはスキップ、新規パスだけコピーする。

### 4.3 Step 1 で `2)` が選ばれた場合

全パスを上書きで書き出す。

### 4.4 書き出しの順序

`./career/` ディレクトリと `./assets/` ディレクトリは、配下のファイルを書き出す前に存在確認 (無ければ `mkdir -p` 相当) を行う。

> **`Write` ツールの挙動メモ**: 書き出し先のディレクトリが無くても、`Write` が親ディレクトリを自動作成する場合と、エラーになる場合がある。安全のため Step 2 開始時に `Bash mkdir -p ./career ./assets` を 1 回叩く。

---

## 5. Step 3 — 完了報告と流れ案内

Step 2 が終わったら、ユーザーに **作ったもの** と **これからの流れ** を温かいトーンで伝えます。

### 5.1 完了報告の確定形

```
✅ ファイルとフォルダ、ひととおり用意できました。

  ./config.md             — サイト設定 (タイトル / 配色 / 連絡先 / 自己紹介など)
  ./career/profile.md     — プロフィール (氏名 / 職業 / 趣味など)
  ./career/work-history.md — 経歴 (本業 / 副業 / 活動)
  ./assets/               — アイコン画像を入れるおうち
  ./assets/README.md      — assets フォルダの使い方ガイド

このあとの流れはこんな感じです:

  ステップ 1: ./assets/ にアイコン画像を 1 枚入れる
     顔写真でも、似顔絵でも、お気に入りの 1 枚でも大丈夫です。
     ファイル名は何でも OK。あとで自動で拾います。

  ステップ 2: ./config.md と ./career/profile.md を開いて、プロフィールを書き込む
     お名前、職業、自己紹介、連絡先、趣味など。
     エディタやメモ帳で開いて、ファイル先頭のコメントに沿って書いていけば OK。

  ステップ 3: /cc-portfoliokit:hearing
     経歴 ── 本業・副業・活動 ── を対話で聞いていきます。
     1 件ずつ、書きたい分だけ。

  ステップ 4: /cc-portfoliokit:create
     ここまでの素材から、ポートフォリオの HTML を作ります。

迷ったら /cc-portfoliokit:guide が次の一手を教えてくれますよ。
```

### 5.2 Step 1 で `2)` (全上書き) が選ばれた場合の追記

完了報告の冒頭を次のように変える:

```
✅ まっさらなテンプレで入れ替えました。これまでの内容は消えています。
```

その後は同じく流れ案内を表示。

### 5.3 Step 1 で `1)` (足りないものだけ) が選ばれた場合の挙動

新規に作ったファイルだけを列挙する。既存だったファイルは「(すでにありました)」と注記する。

```
✅ 足りなかったファイルを補いました。

  ./config.md             (新しく作りました)
  ./career/profile.md     (すでにありました — 触っていません)
  ./career/work-history.md (新しく作りました)
  ./assets/               (すでにありました — 触っていません)
  ./assets/README.md      (新しく作りました)

そろそろ次へ進めそうです。
...
```

そのあとは §5.1 の流れ案内を続ける。

---

## 6. 共通制約

- **ヒアリングしない**: 氏名・職業・経歴などの中身は一切聞かない。
- **HTML を生成しない**: `portfolio.html` の作成は `create` の責務。
- **ユーザーが既に書き込んだ内容を勝手に上書きしない**: 既存ファイルの保護を最優先。`2)` 全上書きを選ばれたときのみ上書き、それ以外は触らない。
- **プラグイン側のファイルは書き換えない**: `templates/` や `commands/` を `Edit` しない。Read で読み取って cwd 側に Write するだけ。
- **入力 Markdown は YAML フロントマターを使わない `## 見出し` 構造**: テンプレ展開時に内容を改変しない。コメントや空行は維持。
- **対話文の温度感**: CLAUDE.md「文体のトーン」と memory `feedback_warm-tone.md` のルールを守る。事務的命令形を避け、`( )` で補足を書くスタイルを画面に出さない。
- **「フォルダ」を使う**: ユーザー向け対話文に「ディレクトリ」「サブディレクトリ」を出さない。
- **並行セッション対策**: 既存ファイルの存在確認は `Bash ls` か `Read` の試行で。会話前半の記憶を信用せず、その時点でもう一度確認する。

## 7. 想定されるエラー / エッジケース

| 状況 | 対応 |
|---|---|
| すべてのファイルが既存 (`1)` を選んでも何もコピーしない) | 「すでに全部そろっていました。`/cc-portfoliokit:guide` で次の一手を確認できます」と伝えて終了 |
| プラグインのテンプレートディレクトリが見つからない | エラー報告。「プラグインの再インストールを試してみてください」と案内して中断 |
| `Bash mkdir -p` が失敗 (権限など) | エラー報告。「フォルダを作れませんでした。書き込み権限のある場所で実行してください」と案内して中断 |
| 1 ファイルの `Write` が失敗 | そのファイルだけスキップ、残りは続行。最後の完了報告で「次のファイルだけ作れませんでした: 〜」と明示 |
| ユーザーが対話途中で「やめる」 | そこまでの作業は保持。「ここまで作りました」と短く伝えて終了 |

---

## 8. このコマンドが扱わないこと

- **ヒアリング (氏名・職業・経歴)** ── `hearing` の仕事
- **HTML 生成** ── `create` の仕事
- **既存ファイルの修復** ── `cleanup` の仕事
- **道案内** ── `guide` の仕事
- **アイコン画像の配置検証** ── これは `hearing` 起動時のチェックに任せる。`init` は「assets/ フォルダ」を作って `README.md` を置くだけ
- **プロフィールの記入** ── これは `init` 完了案内で「ファイルを開いて書いてね」と促すだけ。実際の書き込みはユーザー自身が手編集で行う
