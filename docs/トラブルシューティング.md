# 困ったときに見るページ — トラブルシューティング

ここは **エラーが出たとき・思うように動かないとき** のための駆け込み寺です。

「**やばい、なんか赤い字が出てる…**」と血の気が引いた方も、まずは深呼吸してください。**ほとんどのエラーはたった数手で元通りになります**。

---

## まず最初に: エラーが出たときの「動かない 3 つのルール」

慌てた状態で操作すると、たいてい状況が悪化します。以下 3 つを守りましょう。

1. **🌬️ 深呼吸する**
   ほぼ全てのエラーは、すぐに直さなくても大丈夫です。コーヒー 1 杯ぶんの落ち着きを取り戻してから読み始めてください。
2. **📷 画面をスクショする**
   今出ているエラーメッセージは、ほぼ確実に原因のヒントになります。**画面の写真を撮ってから** 操作を続けると、あとで Claude Code に状況を説明しやすくなります。
3. **❌ ファイルを削除しない**
   「とりあえず消してみるか」が、いちばん致命傷を作ります。**特に `config.md`・`career/` フォルダ・`assets/` フォルダ・`portfolio.html` は触らないで** ください。

## 言葉の確認 — ここでよく出てくる用語

| 言葉 | 意味 |
| --- | --- |
| **エラー** | アプリが「これはうまくいかなかったよ」と教えてくれるお知らせ。怒っているわけではありません。 |
| **エラーメッセージ** | エラーの内容を文章で説明したもの。たいてい英語ですが、Claude Code に聞けば日本語にしてくれます。 |
| **パス** | フォルダやファイルがある「場所の住所」。`/Users/ponchan/Desktop/...` のような書き方をします。 |
| **URL** | ユーアールエルと読みます。インターネット上の「住所」のことで、`https://...` から始まる文字列のこと。 |
| **Git** | ギットと読みます。プログラマがよく使う **「ファイルの履歴を管理する仕組み」**。GitHub などからプラグインをダウンロードするときにも使われています。 |
| **GitHub** | ギットハブと読みます。プログラムやプラグインを世界中の人と共有するための **倉庫サイト** のようなところ。今回のプラグインもここに置かれていることがあります。 |
| **HTTPS** | エイチティーティーピーエスと読みます。インターネット通信の方式のひとつで、**アカウントなしでも誰でも使える、開かれた通り道** だと思ってください。 |
| **SSH** | エスエスエイチと読みます。こちらもインターネット通信の方式ですが、**「合鍵」を事前に登録しておく必要がある裏口**。アカウントと鍵の登録が前提です。 |
| **コマンドが見つかりません** | 「打ち込んだ命令を私は知らないので動けません」というアプリの返事。スペルミスかインストール忘れがほとんどの原因。 |
| **Permission denied** | 「**許可がないので動けません**」という英語のエラー。フォルダやサーバーの権限まわりの問題のときに出やすい。 |

## A. Claude Code 自体が起動しない / 認識されない

### A-1. ターミナルで `claude` と打ったのに「コマンドが見つかりません」と出る

**症状の例 — Mac / zsh の場合**:

```
zsh: command not found: claude
```

**症状の例 — Windows / コマンドプロンプトの場合**:

```
'claude' は、内部コマンドまたは外部コマンドとして認識されていません。
```

**原因**: Claude Code がパソコンに正しく入っていないか、入っているけれど OS が場所を見失っている状態です。

**対処 — 共通**:

1. もう一度、公式ページの最新のインストール手順に沿って Claude Code を入れ直してみる
2. インストール中にエラーが出ていなかったかを思い出す。出ていたら、その内容をスクショして Claude Code に聞いてみてください
3. それでも直らないなら、CLI 版にこだわらず **[デスクトップアプリ版](./デスクトップアプリで使う.md)** に切り替えるのも全然アリ

**対処 — Mac の場合**:

- ターミナルをいったん **完全に終了** ── `Command` + `Q` ── して開き直す。インストール直後はこれだけで通ることが多いです
- それでもダメなら、シェルの設定ファイル `~/.zshrc` に Claude Code のパスが追加されているか確認。分からなければ Claude Code に「`~/.zshrc` にパスが通っているか確認したいです」と相談してください

**対処 — Windows の場合**:

- コマンドプロンプト / PowerShell を **完全に閉じて開き直す**
- それでも直らないなら **パソコンを再起動**。Windows は環境変数 PATH の変更を取り込むのに再起動が必要な場合があります

> **「再インストールしても直りません」**
> 再起動を一度試してみてください。インストール内容が反映されていないだけ、というオチがそこそこあります。

### A-2. デスクトップアプリが起動しない / アイコンを押しても何も起きない

**原因の候補**: アプリが壊れている / OS のバージョンが古い / セキュリティ機能にブロックされている

**対処 — 共通**:

1. **パソコンを再起動** → これでだいたい直ります
2. それでもダメなら、**アプリを一度アンインストールしてから入れ直す**
3. OS のバージョンが古すぎる場合、Claude Code が要求するバージョンに上げる必要があります。公式ページに必要バージョンが書いてあります

**Mac 特有**: 「**`Claude Code` は壊れているため開けません**」「**開発元が未確認のため開けません**」と表示されることがあります。これは macOS のセキュリティ機能 ── Gatekeeper という名前です ── が、ダウンロードしたアプリを慎重に扱おうとしているだけです。詳しくは [I-9. Mac 特有: 「開発元が未確認」 / 「壊れているため開けません」](#i-9-mac-特有-開発元が未確認--壊れているため開けません) を見てください。

**Windows 特有**: 「**WindowsによってPCが保護されました**」という SmartScreen の警告が出ることがあります。**「詳細情報」** をクリックすると **「実行」** ボタンが現れます。怪しいサイトからではなく公式サイトから入れたことを確認したうえで、実行を許可してください。

### A-3. ログイン画面で何度試してもサインインできない

**対処**:

- メールアドレス・パスワードが合っているか落ち着いて確認
- ブラウザの **キャッシュ** ── 一時保存データのことです ── が悪さしている可能性もあるので、Chrome / Safari / Edge など別のブラウザで試す
- パスワードを忘れた場合は、サインイン画面の「**パスワードを忘れた方**」リンクから再設定

### A-4. Claude Code が固まる / 突然落ちる

**症状**: 入力しても返事がない、画面が動かない、勝手に閉じる

**対処**:

1. CLI 版なら **`Ctrl` + `C`**、デスクトップ版ならウィンドウを閉じるボタンでいったん終了
2. パソコン自体を **再起動**
3. それでも改善しないなら、メモリ ── パソコンの作業スペース ── の不足が原因のことがあります。ほかの重そうなアプリを閉じて再挑戦
4. アプリが古いと不具合が直っていないことがあるので、**最新版にアップデート**

## B. プラグインがインストールできない

プラグインの入れ方は大きく 2 通り:

- **B-1. ローカルのフォルダから入れる** ── 自分のパソコンの中にあるフォルダを指定する方法
- **B-2. Git や GitHub などの倉庫サイトから直接入れる** ── インターネット上のリポジトリを指定する方法

それぞれで起きやすいエラーが違うので、自分のケースに合うほうを読んでください。

---

### B-1. ローカルのフォルダから入れる場合

入力するコマンドは **OS によって、パスの書き方が違います**。

**Mac の場合**:

```
/plugin install /Users/あなたのユーザー名/path/to/cc-PortfolioKit
```

**Windows の場合** ── 次のどちらでも動きます:

```
/plugin install C:\Users\あなたのユーザー名\path\to\cc-PortfolioKit
```

または

```
/plugin install C:/Users/あなたのユーザー名/path/to/cc-PortfolioKit
```

> **「区切りはスラッシュ? バックスラッシュ?」**
> Mac は **スラッシュ `/`**、Windows は **バックスラッシュ `\`** が伝統的な区切り文字です。ただし Windows でも **スラッシュ `/` を使って問題なく動く** ことがほとんどです。区切り文字でハマるくらいなら、コピーして貼り付けるのが早道。
>
> 詳しくは [I-1. パスの書き方が違う](#i-1-パスの書き方が違う) を見てください。

#### B-1-1. 「パスが見つかりません」と返ってくる

**症状の例**:

```
Error: Path does not exist: /Users/.../cc-PortfolioKit
```

**原因**: `cc-PortfolioKit` フォルダの場所 (パス) が間違っている、または途中の名前に **誤字** がある。

**対処 — Mac**:

1. Finder で `cc-PortfolioKit` フォルダを実際に探す
2. そのフォルダを **右クリック**、もしくはトラックパッドで 2 本指タップ → **`Option` キーを押しながら** メニューを見ると、「**パスをコピー**」が現れます。これを選択
3. もう一度コマンドに貼り付けて実行

**対処 — Windows**:

1. エクスプローラーで `cc-PortfolioKit` フォルダを実際に探す
2. 画面上部のアドレスバーを **クリック** すると、`C:\Users\...` のような形でパスが選択されます。`Ctrl` + `C` でコピー
3. もう一度コマンドに貼り付けて実行

> **コピペがうまくいかない**
> 単純に「`cc-PortfolioKit` フォルダはどこにありますか?」と Claude Code に聞いてしまうのも手です。教えてくれます。

#### B-1-2. インストール途中に「Permission denied」 ── 許可がありません ── と出る

**原因**: そのフォルダに対する **読み書きの権限** がない。

**対処 — Mac**:

- Finder でフォルダを右クリック → **「情報を見る」** を選ぶ → 「**共有とアクセス権**」を開き、自分が「**読み/書き**」になっているか確認
- アクセス権が変だったら、左下の鍵アイコンを押して認証 → 自分の名前を選んで「読み/書き」に変更

**対処 — Windows**:

- エクスプローラーでフォルダを右クリック → **「プロパティ」** → **「セキュリティ」** タブを開く → 自分のユーザー名を選び、「**フル コントロール**」または「**変更**」に許可が付いているか確認
- 会社支給のパソコンで権限が制限されていることがあります。その場合は **情報システム部門に相談**

> 直し方が分からない場合は、Claude Code に「`cc-PortfolioKit` フォルダの権限を確認したいです」と相談してください。一緒に直してくれます。

#### B-1-3. パスに日本語やスペースが入っているとうまくいかない

**症状**: 「途中で切れたパスが渡された」「ファイルが見つからない」など、なんとなく動かない。

**原因**: パスに **半角スペース** や **日本語文字** が含まれていると、コマンドが正しく解釈してくれないことがあります。

**対処 — 共通**:

- パスをコピペした後、**全体をダブルクォーテーション `" "` で囲む** とトラブルが減ります
  - Mac の例:
    ```
    /plugin install "/Users/たろう/デスクトップ/cc-PortfolioKit"
    ```
  - Windows の例:
    ```
    /plugin install "C:\Users\たろう\Desktop\cc-PortfolioKit"
    ```
- それでもダメなら、フォルダの場所を **半角英数字だけのフォルダ** に移してから試す
  - Mac: `/Users/your-name/dev/cc-PortfolioKit`
  - Windows: `C:\Users\your-name\dev\cc-PortfolioKit`

> **Windows ならではの落とし穴**: パス全体が **260 文字** を超えると、たとえ半角英数字でも開けないことがあります。深い階層は避けて、ホーム近くの浅い場所に置きましょう。詳しくは [I-8. Windows 特有: パスの長さ制限](#i-8-windows-特有-パスの長さ制限-260-文字) を見てください。

### B-2. Git や GitHub などから入れる場合 — ワークショップでつまずきがち

入力するコマンドはこんな形:

```
/plugin install https://github.com/ユーザー名/cc-PortfolioKit
```

> **ワークショップで実際にあった話**
> Git アカウントを持っていない方が「Git から入れようとしたらエラーが出る」と相談に来ました。**結論から言うと、Git アカウントは不要** です。公開設定になっている **パブリックリポジトリ** であれば、誰でもダウンロードできます。
>
> その方のケースは **「URL が `git@github.com:...` で始まる SSH 形式」だった** ことが原因でした。SSH 形式はアカウントと「合鍵」の事前登録が必要なので弾かれます。**`https://github.com/...` の URL を使えば、アカウント不要で通ります**。

#### B-2-1. `git: command not found` と出る

**症状の例**:

```
zsh: command not found: git
```

または

```
'git' は、内部コマンドまたは外部コマンドとして認識されていません。
```

**原因**: パソコンに **Git というツール** がそもそも入っていません。Claude Code が Git を呼び出してダウンロードしようとするのですが、本体が無いので何も始められない、という状態です。

**対処**:

- **Mac の場合**: ターミナルで以下を実行。Apple の開発ツールに同梱されている Git をインストールできます。
  ```
  xcode-select --install
  ```
  ダイアログが出てくるので「**インストール**」を選んでください。数分かかります。
- **Windows の場合**: 「**Git for Windows**」を検索して、公式サイト `git-scm.com` からダウンロードしてインストール。ウィザードはほとんど「次へ」で進めて大丈夫です。
- インストール後、ターミナルを **いったん閉じて開き直してから** もう一度 `/plugin install ...` を試してください。
- 確認のコマンド:
  ```
  git --version
  ```
  バージョン番号 ── たとえば `git version 2.39.0` ── が表示されれば OK です。

#### B-2-2. `Permission denied (publickey)` と出る ── ワークショップで遭遇したケース

**症状の例**:

```
git@github.com: Permission denied (publickey).
fatal: Could not read from remote repository.
```

**原因**: **`git@github.com:ユーザー名/リポジトリ` の形式、つまり SSH URL** でインストールしようとしています。SSH 形式は GitHub のアカウントを持っていて、かつ **「合鍵」 ── SSH キー ── を登録済み** の人だけが使える、いわば裏口の通り道です。アカウントを持っていなければ通れません。

**対処**: URL を **`https://...` 形式の HTTPS URL** に変えてください。HTTPS なら **誰でも、アカウントなしでも、パブリックリポジトリを読みに行けます**。

| 形式 | 例 | アカウント要? |
| --- | --- | --- |
| ❌ SSH | `git@github.com:miyazakiryuji/cc-PortfolioKit.git` | **必要**。合鍵の事前登録も要ります |
| ✅ HTTPS | `https://github.com/miyazakiryuji/cc-PortfolioKit.git` | 不要。パブリック設定なら誰でも OK |

**正しい URL の入手方法**:

1. ブラウザで GitHub のリポジトリページ、たとえば `https://github.com/miyazakiryuji/cc-PortfolioKit` を開く
2. 緑色の **「Code」ボタン** をクリック
3. タブが **「HTTPS」** になっているか必ず確認。SSH や GitHub CLI が選ばれていることがあります
4. 表示された URL の右にあるコピーアイコンを押す
5. その URL をコマンドに貼り付ける

```
/plugin install https://github.com/miyazakiryuji/cc-PortfolioKit
```

> **裏技**: URL の中の `git@github.com:` の部分を、自分の手で `https://github.com/` に書き換えて、末尾に `.git` を付けるだけでも変換できます。慌てているときは GitHub のページから取り直すのが安心です。

#### B-2-3. `Repository not found` と出る

**症状の例**:

```
fatal: repository 'https://github.com/miyazakiryuji/cc-portfoliokit.git/' not found
```

**原因の候補**:

1. **URL の打ち間違い**、つまりタイプミス
2. **大文字 / 小文字の違い** ── `cc-PortfolioKit` と `cc-portfoliokit` は別物として扱われます
3. リポジトリが **非公開、つまりプライベート** で、アクセス権がない
4. リポジトリが **削除 or 改名** されている

**対処**:

1. ブラウザでその URL を直接開いてみる → 404 や「Not Found」が出るなら URL が違います
2. リポジトリの **正確な綴り** をブラウザのアドレスバーからコピーする
3. プライベートリポジトリの場合は、**作成者にパブリック化してもらう** か、**アクセス権を付与してもらう** 必要があります

#### B-2-4. `could not read Username for 'https://github.com'` と出る

**症状の例**:

```
fatal: could not read Username for 'https://github.com': terminal prompts disabled
```

**原因**: HTTPS でアクセスしたとき、サーバー側が「**ユーザー名教えて**」と聞いてきたのに、Claude Code 側ではユーザー名を入力する場所が用意されていないため失敗。たいていは **プライベートリポジトリを HTTPS で開こうとしている** ときに出ます。

**対処**:

1. そもそも **パブリックリポジトリ** なら認証は必要ありません。URL に誤字がないか確認 ── B-2-3 と同じチェックです
2. 本当にプライベートリポジトリなら、作成者にパブリック化してもらう
3. どうしても自分のプライベートリポジトリから入れたい場合は、GitHub の **Personal Access Token** ── 個人用のパスワードのような文字列です ── を発行して URL に含める方法もあります。これはやや上級者向けで、普通は不要です

#### B-2-5. SSL 証明書エラー / プロキシで弾かれる ── 社内ネットワーク向け

**症状の例**:

```
fatal: unable to access 'https://github.com/...': SSL certificate problem: unable to get local issuer certificate
```

または

```
fatal: unable to access 'https://github.com/...': Could not resolve host: github.com
```

**原因**: 会社のネットワークなどで、外部サイトへの通信が **プロキシ** ── つまり中継地点 ── や **ファイアウォール** ── つまり関所 ── を通る設定になっており、Git が通信できない、または証明書を検証できない状態。

**対処**:

1. まず **自宅などの普通のネットワーク** に繋ぎ直して試す。これだけで解決することが多いです。たとえば社内 Wi-Fi からスマホのテザリングに切り替えるなど
2. 社内ネットワークから出る必要があるなら、**情報システム部門に「プロキシ設定の入れ方」を聞く** のがいちばん早道です
3. プロキシ設定が分かれば、ターミナルで以下のように設定:
   ```
   git config --global http.proxy http://プロキシのホスト:ポート
   git config --global https.proxy http://プロキシのホスト:ポート
   ```
4. 一時的な応急処置として `git config --global http.sslVerify false` で SSL 検証を切ることもできますが、**セキュリティ上のリスクがあるので推奨しません**。社内ネットワークなら情シスに相談してください。

> **「専門用語が多くて何が何だか…」**
> ここまで読んで頭がいっぱいになっても大丈夫です。**「会社のネットワーク特有の設定が必要だから、情シスの人に聞く」** とだけ覚えてもらえれば十分です。

#### B-2-6. ネットワーク タイムアウト

**症状の例**:

```
fatal: unable to access '...': Failed to connect to github.com port 443: Operation timed out
```

**原因**: 単純にネットワークが不安定で、ダウンロードが時間切れになった。

**対処**:

1. **Wi-Fi の接続** を確認
2. しばらく時間を置いてから再試行。5 〜 10 分置くと改善することもあります
3. **別のネットワーク** ── テザリング、別の Wi-Fi など ── でも試してみる
4. ファイルサイズが大きいわけではないので、まともなネットワークなら数秒〜数十秒で終わるはず。長時間止まるのは異常です

#### B-2-7. Git のバージョンが古すぎる

**症状の例**: SSL 関連の謎エラー / 「未対応のプロトコル」のような英語が出る

**確認方法**:

```
git --version
```

`git version 1.x.x` のように **1 系** だと古すぎる可能性があります。推奨は **2.x 系** 以降です。

**対処**:

- **Mac**: `xcode-select --install` で同梱の Git を更新するか、Homebrew の `brew install git` で最新版を入れる
- **Windows**: Git for Windows を最新版で入れ直す

---

### B-3. インストール後にコマンドが反応しない

**症状**: `/plugin install` 自体は成功したのに、いざ `/cc-portfoliokit:init` や `/cc-portfoliokit:create` を打っても無反応、または「コマンドが見つかりません」

**対処**:

1. Claude Code を一度終了して **起動し直す**。たいていこれで直ります
2. プラグイン一覧で `cc-portfoliokit` が入っているか確認:
   ```
   /plugin list
   ```
3. 入っていなければ、もう一度 `/plugin install` し直す
4. それでもダメなら、`/plugin list` の結果と一緒に Claude Code に「**これが入っているはずなのに動きません**」と相談

> **覚えるコマンドは 2 つだけです**
> 最初の 1 回だけ叩く `/cc-portfoliokit:init` と、HTML 生成・編集に何度でも使う `/cc-portfoliokit:create` の 2 つ。順番を逆に叩いていないか、半角コロン `:` が抜けていないかも確認してください。

<a id="c-プラグインの動作中に起きるエラー"></a>

## C. プラグインの動作中に起きるエラー — `init` / `create`

### C-1. 「テンプレートが見つかりません」と出る

**症状の例**:

```
templates/config.md が見つかりません
```

**原因**: プラグインのファイル一式が完全な状態ではない可能性があります。

**対処**:

1. `cc-PortfolioKit` フォルダの中に、本来あるべき以下のものが揃っているかチェック:
   - `templates/config.md`
   - `templates/profile.md`
   - `templates/work-history.md`
   - `templates/assets-README.md`
2. 足りないファイルがあれば、プラグインを **インストールし直す**
3. それでもダメなら、`cc-PortfolioKit` フォルダごとダウンロードし直して、新しいパスで `/plugin install` をやり直す

### C-2. 「既存のファイルがあります」と聞かれて、どうしていいか分からない

**こういう場面**:

```
既に以下が存在しています: config.md, career/profile.md
どうしますか?
  a) 既存ファイルは触らず、足りないものだけテンプレートで補う [推奨]
  b) すべてテンプレートで上書きする [注意: 既存内容は消えます]
  c) キャンセル
```

**判断のヒント**:

- **a) を選ぶのが基本** です。せっかく書いた内容を守れます。
- **b) は、いったん全部捨ててもいい場合のみ** 選んでください。書いた内容は戻ってきません。
- **迷ったら c)** でいったん中断して、フォルダの中身を Finder / エクスプローラーで確認してから判断するのも全然 OK。

### C-3. 質問の途中で接続が切れた / Claude Code が固まった

**対処**:

1. **慌てない**。これが一番大事です
2. CLI 版なら `Ctrl` + `C`、デスクトップ版なら閉じるボタンでいったん操作を止める
3. Claude Code を起動し直す
4. **init の途中で止まった場合** → もう一度 `/cc-portfoliokit:init` を実行。既存ファイルの扱いを聞かれるので、「**足りないものだけ作成する**」を選べば、書き込み済みの内容を守ったまま続きから再開できます
5. **create の途中で止まった場合** → もう一度 `/cc-portfoliokit:create` を実行。編集メニューから続きが書けます

> **「答えた内容は消えませんか?」**
> 質問の答えは、`config.md` などの Markdown ファイルに **逐一保存される作りになっている** ので、途中で中断しても大半は残ります。安心してください。

### C-4. `/cc-portfoliokit:create` を実行したら「先に init を実行してください」と言われた

**こういうメッセージが出る場面**:

```
❌ ポートフォリオの素材が見つかりません。

足りないファイル:
  - <欠けているパスを列挙>

このコマンドは HTML 生成専用です。最初に下のコマンドで対話セットアップを実行してください:
  /cc-portfoliokit:init
```

**理由**: `create` は HTML を組み立てるコマンドであり、素材 (`config.md` や `career/profile.md` など) がまだ準備されていないと動けません。

**対処**: メッセージのとおりに `/cc-portfoliokit:init` を先に実行してください。氏名やキャリアのヒアリングが終わったら、自動的に素材が揃った状態になります。続けて `/cc-portfoliokit:create` を叩けば、`portfolio.html` が出来上がります。

> **「init は前にやったはずなのに…」**
> もしかすると、**作業フォルダが違う場所に変わっている** かもしれません。Claude Code に「いまどのフォルダで作業していますか?」と聞いて、`career/profile.md` が見える場所にいるか確認してください。

### C-5. ヒアリングが途中で勝手に終わってしまった

**症状**: 全部の質問が終わる前に、突然「完了しました」と言われた / 何社か職歴が抜け落ちている。

**原因の候補**: 質問の途中で 「**もう 1 社追加しますか?**」 への返事を「**No**」「**いいえ**」「**もういいです**」のいずれかと読み取ってしまった可能性。

**対処**:

- もう一度 `/cc-portfoliokit:create` を実行 → 編集メニューで **「職歴を追加する」** を選び、追加したい職歴を入れていく
- すでにある職歴も、編集メニューから書き直せます

<a id="d-出来上がった-html-がおかしい"></a>

## D. 出来上がった HTML がおかしい

### D-1. `portfolio.html` をブラウザで開いたら真っ白

**症状**: ファイルは開けるけれど、何も表示されない。

**よくある原因**:

- **HTML 内の特殊文字 `<` `>` `&` などのエスケープ漏れ** → 中身が壊れている
- **ファイルが空** ── 生成が途中で止まった可能性

**対処**:

1. **`portfolio.html` のファイルサイズ** をチェック。極端に小さい、たとえば 0 KB なら、生成が失敗しています
2. もう一度 `/cc-portfoliokit:create` を実行して、「再生成」を選んでみる
3. それでも空白の場合、Claude Code に **「`portfolio.html` を開いたら何も表示されません」** と素直に相談 → 中身を見て原因を教えてくれます

### D-2. 顔写真が表示されない ── 画像が四角の枠だけになる

**原因の候補**:

1. `config.md` の `photo:` に書いたファイル名と、`assets/` フォルダの実際のファイル名が違う
2. 顔写真のファイルが、まだ `assets/` フォルダに置かれていない
3. ファイル名に半角スペースや日本語が混ざっていて、ブラウザがうまく読めない

**対処**:

1. `assets/` フォルダの中身を確認。**たとえば `photo.jpg` という名前で置いているか** を確認
2. `config.md` を開いて、`photo: photo.jpg` のような行があるか確認
3. ファイル名の **大文字 / 小文字も一致しているか** に注意。`Photo.JPG` と `photo.jpg` は別物として扱われます
4. ファイル名は **半角英数字のみ** にするとトラブルが減ります。たとえば `profile.jpg` のような名前です

> **「ファイル名どう変えるんだっけ?」**
> Finder / エクスプローラーでファイルを **右クリック** → 「**名前を変更**」 を選びます。

### D-3. 顔写真が大きすぎる / ページが重い

**原因**: 写真ファイルのサイズが大きすぎる。

**対処**:

- 写真ファイルを **圧縮する**。「画像 圧縮 オンライン」で検索すると無料のツールが見つかります
- 推奨サイズは **500 KB 以下** くらい
- スマホで撮った写真はそのままだと数 MB あることが多いので、必ず圧縮してから入れてください

### D-4. ページがガタガタに崩れている

**原因**: `config.md` などの Markdown ファイルの書き方を間違えた可能性があります。

**対処**:

1. `config.md` を開いて、**フロントマター** と呼ばれる先頭部分の書き方を見直す
   - 上下が 3 つのハイフン `---` で囲まれている必要があります
2. 書き方が分からなければ、`templates/config.md` の見本と見比べる
3. 「ファイルの書き方を間違えたかもしれません」と Claude Code に相談すれば、見て直してくれます

### D-5. 文字化けしている

**原因**: ブラウザが文字コードを誤認している、またはファイルの保存形式がずれている。

**対処**:

- まずブラウザを **再読み込み**。`F5` または `Command` + `R` で更新できます
- それでもダメなら、Safari から Chrome に変えるなど、別のブラウザで開いてみる
- それでもダメなら、もう一度 `/cc-portfoliokit:create` で再生成

### D-6. ダークモードのときに文字が読めない

**症状**: 夜、パソコンが暗いモード ── ダークモード ── のときに、白背景に白文字になって読めない、など。

**原因**: ブラウザがダークモード設定を反映していなかったり、テーマカラーがダークモードと相性が悪かったりします。

**対処**:

1. ブラウザのウィンドウをいったん閉じて開き直す
2. `config.md` の `theme_color` / `accent_color` を、明るい色と暗い色のどちらでも読める色味に変える
3. それでも気になる場合は、Claude Code に「**ダークモードでも読みやすい色にしてください**」と頼めば、色味を提案してくれます

### D-7. 印刷したら色が消えてしまった

**症状**: ブラウザで「印刷」を押すと、背景色や強調色が真っ白になってしまう。

**原因**: ブラウザの印刷設定の多くは、**インク節約のため背景色を自動でカットする** ようになっています。

**対処**:

- 印刷ダイアログで **「背景のグラフィック」** にチェックを入れる。Chrome / Edge ならオプションの中にあります
- もしくはそのまま印刷して、**「背景がなくても読める」設計になっている** ので大きな問題はありません。`cc-PortfolioKit` の HTML は印刷時を想定して、文字色をしっかり残すように作っています

<a id="e-やってしまった系のミス"></a>

## E. 「やってしまった」系のミス

### E-1. 間違えて `portfolio.html` を消してしまった

**安心ポイント**: `portfolio.html` は **元データ (`config.md` など) からいつでも作り直せる** ので、消えてもダメージはほぼ無しです。

**対処**:

```
/cc-portfoliokit:create
```

を実行すれば、再生成してくれます。

### E-2. 間違えて `config.md` や `career/` フォルダを消してしまった

**ダメージ度**: 中。書いた内容は戻ってきませんが、`init` でもう一度やり直せます。

**対処**:

1. ゴミ箱 / 「最近削除した項目」を確認 → 戻せるなら戻す
2. 戻せない場合は、もう一度 `/cc-portfoliokit:init` を実行してセットアップをやり直す
   - 既存ファイルが部分的に残っている場合は「**足りないものだけ作成する**」を選ぶと安全です
3. 再度内容を入力し直す
4. その後 `/cc-portfoliokit:create` で `portfolio.html` を作り直す

> **このために定期バックアップを**
> ポートフォリオを作り込んできたら、**フォルダごとコピーして別の場所に置いておく** だけでバックアップになります。月に 1 回くらいで十分です。

### E-3. 間違えて編集メニューで違う項目を上書きしてしまった

**対処**:

- もう一度 `/cc-portfoliokit:create` を実行して、編集メニューから **正しい内容を入れ直す** だけです。データは「最後に書いた内容」が残るので、書き直せばそれが正です。

### E-4. 気付いたら違うフォルダで `init` を実行してしまっていた

**症状**: 「マイポートフォリオ」フォルダに作りたかったのに、なぜか別の場所に `config.md` や `career/` ができていた。

**対処**:

1. 慌てて中身を消さない。**いったんファイル群をコピーして、本来作りたかったフォルダに移す** のが安全策
2. その後、間違ったフォルダにできた `config.md` / `career/` / `assets/` を削除
3. 移し終わったら、本来の作業フォルダに移動して `/cc-portfoliokit:create` を実行

> **「フォルダ移動でファイルが消えた!」**
> ほとんどの場合、**目的地に到着している** だけで消えてはいません。Finder / エクスプローラーで目的のフォルダを開いて確認してください。

<a id="f-パスフォルダまわりのトラブル"></a>

## F. パス・フォルダまわりのトラブル

### F-1. パスに日本語やスペースが入っているとうまくいかない

**症状**: パスが途中で切れる、ファイルが見つからない、文字化けする。

**対処**:

- パス全体を **ダブルクォーテーション `" "`** で囲む
- 可能なら、作業フォルダ自体を **半角英数字だけ** の名前に変える。たとえば `マイポートフォリオ` → `my-portfolio` のように
- フォルダの場所もシンプルに。たとえば `デスクトップ/作業/2026年/マイポートフォリオ` のような深い階層は避ける

### F-2. iCloud Drive / OneDrive の中で作業して同期が暴れる

**症状**: ファイルが勝手に消えたり戻ったりする。Claude Code が「ファイルが見つかりません」と言う / 編集してもすぐ別の内容に書き換わる。

**原因**: クラウド同期サービスが、ファイルの実体をローカルに残さず「**雲の中**」に置いていることがあり、Claude Code が読み書きするタイミングと衝突して暴れます。

**対処 — 共通**:

- 作業フォルダを **同期対象外の場所** に置く。たとえばホーム直下の `Developer/` フォルダなどです
- どうしても同期サービスの下で作業するなら、フォルダを **「常にこのデバイスに保存 / Always keep on this device」** 設定にして、雲ではなくローカルに実体を置く
- 同期サービスを **一時的に停止** してから作業するのも有効

**Mac の iCloud Drive を使っている場合**:

- 「**書類 / Documents**」フォルダや「**デスクトップ**」は、デフォルトで iCloud と同期されている設定になっていることがあります
- 同期を外す方法: `システム設定` → 左上の自分の名前の `Apple ID` → `iCloud` → `iCloud Drive` → `同期するこの Mac 上のフォルダ` から「**書類とデスクトップ**」のチェックを外す
- 雲マークが付いている iCloud 上のファイルを強制ダウンロード: Finder でファイルを **右クリック** → 「**今すぐダウンロード**」
- 念のため、作業フォルダは **`/Users/あなたのユーザー名/Developer/` のような iCloud 配下ではない場所** に作るのが安全です

**Windows の OneDrive を使っている場合**:

- 「**ドキュメント**」「**デスクトップ**」「**ピクチャ**」は、Microsoft アカウントでサインインすると勝手に OneDrive に同期される設定になっていることがあります
- 同期を外す方法: タスクトレイの **青い雲の OneDrive アイコン** → 歯車マーク → `設定` → `同期とバックアップ` → 「**重要な PC のフォルダーを OneDrive にバックアップする**」を開いて、デスクトップ / ドキュメントの **「バックアップを停止」** を選ぶ
- 雲マークが付いている OneDrive 上のファイルを強制ダウンロード: エクスプローラーでファイルを **右クリック** → 「**このデバイス上で常に保持する**」
- こちらも、作業フォルダは **`C:\Users\あなたのユーザー名\Developer\` のような OneDrive 配下ではない場所** に作るのが無難です

> **「気づかないうちに同期されていた」**
> 同期サービスは便利な反面、知らないうちに動いていて困りがち。`portfolio.html` などのファイルアイコンに **雲マーク** や **緑のチェックマーク** が付いていたら、同期下にあるサインです。

### F-3. ホームフォルダ自体に書き込み権限がない

**症状**: 何をしても「Permission denied」が消えない。

**対処**:

- 自分のユーザーが管理者権限を持っているか確認。会社支給のパソコンで権限が制限されていることがあります
- 情シスに相談するか、`/tmp/` などの誰でも書ける別のフォルダで試してみる

<a id="g-ネットワーク通信のトラブル"></a>

## G. ネットワーク・通信のトラブル

### G-1. 何をしても「通信に失敗しました」が出る

**対処**:

1. Wi-Fi のアイコンが繋がっているか目視で確認
2. ブラウザで Google など普通のサイトが開けるか確認 → 開けないならネット自体が落ちています
3. **ルーターを再起動**。5 秒以上電源を抜くのがコツです。もはや IT のおまじない

### G-2. 社内ネットワークで弾かれる

→ [B-2-5. SSL 証明書エラー / プロキシで弾かれる](#b-2-5-ssl-証明書エラー--プロキシで弾かれる-社内ネットワーク) と同じ対処です。情シスに相談するのが結局いちばん早道。

### G-3. レートリミットに引っかかった

**症状**: 「**しばらく時間をおいてからもう一度お試しください**」「**Too many requests**」のようなメッセージが出る。

**原因**: 短時間に大量の操作を行うと、サービス側が一時的にアクセスを止めることがあります。

**対処**:

- **10 〜 30 分待ってから** やり直す
- 同じ操作を連続して何度も叩かない。慌てて連打しがちですが、たいてい裏で処理は進んでいます

<a id="i-mac-と-windows-の環境差分"></a>

## I. Mac と Windows の環境差分 — まとめ早見表

ここまでの各章で OS 別の補足を散りばめてきましたが、「**結局、自分のパソコンだとどう違うの?**」がパッと見て分かるように、ここに **早見表** としてまとめました。

> **読み方**: 自分が使っているのが Mac か Windows かさえ覚えていれば OK。該当する列だけ見てください。比較表として並べていますが、両方の事情を覚えるのが目的ではありません。

### I-1. パスの書き方が違う

| | Mac | Windows |
| --- | --- | --- |
| **ホームの場所** | `/Users/あなたのユーザー名` | `C:\Users\あなたのユーザー名` |
| **区切り文字** | スラッシュ `/` | バックスラッシュ `\`。スラッシュ `/` でも動きます |
| **デスクトップ** | `/Users/.../Desktop` | `C:\Users\...\Desktop` |
| **ドライブ** | 基本 1 つしかない | `C:`, `D:`, `E:` ... |

**ありがちなトラブル**:

- Windows ユーザーが Mac 流に `~/Desktop/...` と打って動かない。Mac ではホームの省略記号として `~` を使えますが、書き方を覚える必要はないので、なるべく **コピペ** で対応してください
- Mac ユーザーが Windows のパスを **大文字で書いて** つまずく。`C:\` の `C` は大文字で書いておけば安心です

**コピーのコツ**:

- **Mac**: Finder でフォルダを右クリック → `Option` 長押し → 「**パスをコピー**」
- **Windows**: エクスプローラーのアドレスバーをクリック → `Ctrl` + `C`

### I-2. ターミナル / コマンドプロンプトの違い

| | Mac | Windows |
| --- | --- | --- |
| **黒い画面の正式名称** | ターミナル / Terminal | コマンドプロンプト / PowerShell / Windows Terminal |
| **デフォルトのシェル** | zsh ── ズィーシェルと読みます | cmd または PowerShell |
| **起動方法** | `Command` + `Space` → 「ターミナル」 | 検索欄に「コマンドプロンプト」または「PowerShell」 |
| **プロンプトの見た目** | `ponchan@MacBook ~ %` | `C:\Users\ponchan>` |

> どちらでも、Claude Code を使う分には大した違いはありません。「**`claude` と打って起動する**」というところまで一緒です。

**ありがちなトラブル**:

- Windows で「コマンドプロンプト」「PowerShell」「Windows Terminal」のうちどれを開けばいいか迷う → **どれでも大丈夫**。迷ったら「コマンドプロンプト」を開いてください
- Mac で「ターミナル」と「iTerm」のどちらを使うか迷う → **どちらでも OK**

### I-3. ファイルを開くコマンド ── `open` と `start`

ターミナルからファイルを開きたいときの命令が違います。

| やりたいこと | Mac | Windows |
| --- | --- | --- |
| `portfolio.html` を既定のブラウザで開く | `open portfolio.html` | `start portfolio.html` |
| いま居るフォルダをファイラーで開く | `open .` | `start .` または `explorer .` |
| `config.md` を既定のエディタで開く | `open config.md` | `start config.md` |

**ありがちなトラブル**:

- Mac で `start` と打って「コマンドが見つかりません」 → 正解は `open`
- Windows で `open` と打って「コマンドが見つかりません」 → 正解は `start`

> どちらの場合も、覚えるのが面倒なら **Finder / エクスプローラーで該当ファイルを開いてダブルクリック** が結局いちばん早道です。

### I-4. クラウド同期サービスの違い ── iCloud Drive と OneDrive

| | Mac | Windows |
| --- | --- | --- |
| **デフォルトの同期サービス** | iCloud Drive | OneDrive |
| **暴れがちなフォルダ** | デスクトップ / 書類 | デスクトップ / ドキュメント / ピクチャ |
| **アイコンの目印** | 雲マーク ☁️ / ダウンロード矢印 | 青い雲 ☁️ / 緑のチェックマーク ✅ |
| **「ローカルに置く」設定** | 右クリック → **「今すぐダウンロード」** | 右クリック → **「このデバイス上で常に保持する」** |

具体的な切り離し手順は [F-2. iCloud Drive / OneDrive の中で作業して同期が暴れる](#f-2-icloud-drive--onedrive-の中で作業して同期が暴れる) を見てください。

### I-5. 隠しファイル・拡張子の表示設定

cc-PortfolioKit を使っていると、`.claude-plugin/` のような **ドット (`.`) で始まるフォルダ** や、`config.md` の **`.md` 拡張子** がトラブルの原因になることがあります。表示設定で確認できるようにしておくと安心です。

**Mac**:

- 隠しファイルを表示する: Finder で **`Command` + `Shift` + `.`** ── 最後はピリオドです ── を押すと一時的にドットファイルが見えるようになります。もう一度押すと非表示に戻ります
- 拡張子を常に表示する: Finder のメニュー → `設定` → `詳細` → 「**すべてのファイル名拡張子を表示**」にチェック

**Windows**:

- 隠しファイルを表示する: エクスプローラーの上部メニュー → `表示` → 歯車のあたりの `表示` → **「隠しファイル」にチェック**
- 拡張子を表示する: 同じく `表示` → **「ファイル名拡張子」にチェック**

> **「拡張子って何?」**
> ファイル名の **末尾に付いている、点のあとの数文字** のことです。たとえば `portfolio.html` の `html` の部分。
> Windows / Mac とも初期設定では非表示になっていることがあり、`config` と `config.md` が同じに見えてしまいます。**表示しておくと、ファイルの種類が見分けやすくなります**。

### I-6. 改行コードと文字コードの違い

| | Mac | Windows |
| --- | --- | --- |
| **改行コード** | LF ── Line Feed の略 | CRLF ── Carriage Return + Line Feed の略 |
| **推奨の文字コード** | UTF-8 ── BOM なし | UTF-8 |
| **メモ帳の保存** | TextEdit は標準で UTF-8 LF | 新しめの Windows のメモ帳は UTF-8 LF も選べる |

**ありがちなトラブル**:

- Windows の **メモ帳** で `config.md` を編集して保存したら、ファイル先頭に **BOM** ── バイト オーダー マークの略です ── という見えない印が付いて、生成された HTML が変な動きをする
- 古いバージョンの Windows メモ帳で Mac 産のファイルを開いたら、**改行されずに 1 行にダラッと並ぶ**

**対処**:

- 編集は無料の **VS Code** や Mac 用の **CotEditor** など、**きちんとしたテキストエディタ** を使うのが安心
- Windows のメモ帳を使う場合は、保存時の **文字コード** を「**UTF-8**」に、**BOM なし** を選ぶ。新しめのメモ帳はこれが選べます
- 改行コードはたいてい Claude Code 側で吸収してくれるので、文字化けが起きたときに気にする程度で OK

### I-7. キー操作の早見表 ── `Command` と `Ctrl`

ターミナルや Claude Code を使うときに「あれ、Mac のあのキーって Windows では?」と迷いがちな対応表。

| やりたいこと | Mac | Windows |
| --- | --- | --- |
| コピー | `Command` + `C` | `Ctrl` + `C` ⚠️ |
| 貼り付け | `Command` + `V` | `Ctrl` + `V` |
| 全選択 | `Command` + `A` | `Ctrl` + `A` |
| やり直し (Undo) | `Command` + `Z` | `Ctrl` + `Z` |
| アプリ終了 | `Command` + `Q` | `Alt` + `F4` |
| ターミナル内で「いまの処理を止める」 | `Ctrl` + `C` | `Ctrl` + `C` |
| ターミナルからログアウト | `Ctrl` + `D` | `Ctrl` + `D` または `exit` |
| スクリーンショット ── 範囲指定 | `Command` + `Shift` + `4` | `Windows` + `Shift` + `S` |
| スクリーンショット ── 全画面 | `Command` + `Shift` + `3` | `PrintScreen` キー、PrtSc と表記されることも |

> **⚠️ Windows ユーザーが特につまずきやすいポイント**
> Windows では普段 `Ctrl` + `C` は「コピー」の意味ですが、**ターミナルの中では「処理を止める」という意味** に変わります。
> ターミナル上で文字をコピーしたいときは、Windows Terminal なら **`Ctrl` + `Shift` + `C`**、コマンドプロンプトなら **マウスで選択 → 右クリック** を使ってください。

### I-8. Windows 特有: パスの長さ制限 ── 260 文字

**症状**: ファイル名はそんなに長くないのに、なぜか「ファイルが見つかりません」と言われる。

**原因**: Windows には、**フォルダ + ファイル名を合わせて 260 文字までしか扱えない** という古い制限があります。`MAX_PATH` と呼ばれる制限です。`C:\Users\長いユーザー名\OneDrive\社内資料\2026年\マイポートフォリオ\career\work-history.md` のように深い階層に置くと、知らぬ間に超えてしまいます。

**対処**:

1. 作業フォルダを **ホームの近くの浅い場所** に置く。たとえば `C:\Users\your-name\dev\cc-PortfolioKit` のように
2. フォルダ名・ファイル名を **短くする**
3. それでも引っかかる場合は、Windows の長いパス対応をオンにする方法もありますが、まずは置き場所を変えるほうが手っ取り早いです

> **Mac の方へ**: 心配しなくて大丈夫です。macOS には実用上の制限はほぼありません。

### I-9. Mac 特有: 「開発元が未確認」 / 「壊れているため開けません」

**症状**: Claude Code やプラグイン関連のファイルを開こうとすると、「**`xxx.app` は壊れているため開けません**」「**開発元が未確認のため開けません**」と警告が出る。

**原因**: macOS のセキュリティ機能 **Gatekeeper** ── ゲートキーパーと読みます ── が、ダウンロード経由のアプリを慎重に扱おうとしているだけです。**本当にファイルが壊れているわけではない** ことがほとんど。

**対処**:

1. Finder でそのアプリを **右クリック、もしくはトラックパッドで 2 本指タップ** → **「開く」** を選ぶ → 警告ダイアログで「**開く**」をもう一度クリック
2. それでもダメな場合: `システム設定` → `プライバシーとセキュリティ` を開く → 一番下に「**`xxx.app` は開発元を確認できないため、使用がブロックされました**」と出ているので、その横の「**このまま開く**」をクリック
3. アプリを **公式サイトから直接ダウンロードし直す** と、警告が出なくなる場合もあります

> **Windows の方へ**: SmartScreen の「**WindowsによってPCが保護されました**」もよく似た警告です。詳しくは [A-2](#a-2-デスクトップアプリが起動しない--アイコンを押しても何も起きない) を参照。

## H. それでも解決しないとき

ここまで読んでも直らないときは、Claude Code に **素直に相談する** のがいちばん早道です。

### 報告するときのコツ

以下を伝えてもらえると、原因の特定が劇的に早くなります。

1. **何をしようとしたか** ── たとえば「ポートフォリオを初めて作ろうとして…」
2. **どう操作したか** ── たとえば「`/cc-portfoliokit:create` を入力しました」
3. **どんなメッセージが出たか** ── たとえば「`Error: Path does not exist` と出ました」
4. **OS とアプリのバージョン** ── たとえば「Mac の Sonoma で、デスクトップアプリ版を使っています」

これだけ伝えれば、Claude Code が原因を一緒に切り分けてくれます。

### スクショを貼る

エラー画面のスクリーンショットを撮って、デスクトップアプリ版なら入力欄にそのまま貼り付けることができます。**写真を見て判断してくれるので、説明が苦手でも大丈夫** です。

### コミュニティに頼る

公式の Claude Code 関連のフォーラムや、`cc-PortfolioKit` の **GitHub Issues** に同じ症状の報告がないかを検索してみるのも有効です。
