# 困ったときに見るページ — トラブルシューティング

ここは **エラーが出たとき・思うように動かないとき** のための駆け込み寺です。

「**やばい、なんか赤い字が出てる…**」と血の気が引いた方も、まずは深呼吸してください。**ほとんどのエラーはたった数手で元通りになります**。

---

## まず最初に: エラーが出たときの「動かない 3 つのルール」

慌てた状態で操作すると、たいてい状況が悪化します。以下 3 つを守りましょう。

1. **🌬️ 深呼吸する**
   ほぼ全てのエラーは、すぐに直さなくても大丈夫です。コーヒー 1 杯ぶんの落ち着きを取り戻してから読み始めてください。
2. **📷 画面をスクショする**
   今出ているエラーメッセージは、ほぼ確実に原因のヒントになります。**画面の写真を撮ってから** 操作を続けると、あとで Claude Code に状況を説明しやすくなります。
3. **❌ ファイルを削除しない**
   「とりあえず消してみるか」が、いちばん致命傷を作ります。**特に `config.md`・`career/` フォルダ・`assets/` フォルダ・`portfolio.html` は触らないで** ください。

---

## 言葉の確認 (ここでよく出てくる用語)

| 言葉 | 意味 |
| --- | --- |
| **エラー** | アプリが「これはうまくいかなかったよ」と教えてくれるお知らせ。怒っているわけではありません。 |
| **エラーメッセージ** | エラーの内容を文章で説明したもの。たいてい英語ですが、Claude Code に聞けば日本語にしてくれます。 |
| **パス** | フォルダやファイルがある「場所の住所」。`/Users/ponchan/Desktop/...` のような書き方をします。 |
| **URL (ユーアールエル)** | インターネット上の「住所」。`https://...` から始まる文字列のこと。 |
| **Git (ギット)** | プログラマがよく使う **「ファイルの履歴を管理する仕組み」**。GitHub などからプラグインをダウンロードするときにも使われています。 |
| **GitHub (ギットハブ)** | プログラムやプラグインを世界中の人と共有するための **倉庫サイト** のようなところ。今回のプラグインもここに置かれていることがあります。 |
| **HTTPS (エイチティーティーピーエス)** | インターネット通信の方式のひとつ。**アカウントなしでも誰でも使える、開かれた通り道** だと思ってください。 |
| **SSH (エスエスエイチ)** | こちらもインターネット通信の方式。ただし **「合鍵」を事前に登録しておく必要がある裏口**。アカウントと鍵の登録が前提です。 |
| **コマンドが見つかりません** | 「打ち込んだ命令を私は知らないので動けません」というアプリの返事。スペルミスかインストール忘れがほとんどの原因。 |
| **Permission denied** | 「**許可がないので動けません**」という英語のエラー。フォルダやサーバーの権限まわりの問題のときに出やすい。 |

<a id="a-claude-code-自体が起動しない--認識されない"></a>

## A. Claude Code 自体が起動しない / 認識されない

### A-1. ターミナルで `claude` と打ったのに「コマンドが見つかりません」と出る

**症状の例**:

```
zsh: command not found: claude
```

または

```
'claude' は、内部コマンドまたは外部コマンドとして認識されていません。
```

**原因**: Claude Code がパソコンに正しく入っていないか、入っているけれど OS が場所を見失っている状態です。

**対処**:

1. もう一度、公式ページの最新のインストール手順に沿って Claude Code を入れ直してみる
2. インストール中にエラーが出ていなかったかを思い出す (出ていたら、その内容をスクショして Claude Code に聞く)
3. それでも直らないなら、CLI 版にこだわらず **[デスクトップアプリ版](./デスクトップアプリで使う.md)** に切り替えるのも全然アリ

> **「再インストールしても直りません」**
> パソコンの再起動を一度試してみてください。インストール内容が反映されていないだけ、というオチがそこそこあります。

### A-2. デスクトップアプリが起動しない / アイコンを押しても何も起きない

**原因の候補**: アプリが壊れている / OS のバージョンが古い / セキュリティ機能にブロックされている

**対処**:

1. **パソコンを再起動** → これでだいたい直ります
2. それでもダメなら、**アプリを一度アンインストールしてから入れ直す**
3. OS のバージョンが古すぎる場合、Claude Code が要求するバージョンに上げる必要があります (公式ページに必要バージョンが書いてあります)

### A-3. ログイン画面で何度試してもサインインできない

**対処**:

- メールアドレス・パスワードが合っているか落ち着いて確認
- ブラウザの **キャッシュ (一時保存データ)** が悪さしている可能性もあるので、別のブラウザ (Chrome / Safari / Edge など) で試す
- パスワードを忘れた場合は、サインイン画面の「**パスワードを忘れた方**」リンクから再設定

### A-4. Claude Code が固まる / 突然落ちる

**症状**: 入力しても返事がない、画面が動かない、勝手に閉じる

**対処**:

1. **`Ctrl` + `C`** (CLI 版) または ウィンドウを閉じるボタン (デスクトップ版) でいったん終了
2. パソコン自体を **再起動**
3. それでも改善しないなら、メモリ (パソコンのワーキングスペース) 不足のことがあるので、ほかの重そうなアプリを閉じて再挑戦
4. アプリが古いと不具合が直っていないことがあるので、**最新版にアップデート**

<a id="b-プラグインがインストールできない"></a>

## B. プラグインがインストールできない

プラグインの入れ方は大きく 2 通り:

- **B-1. ローカル (自分のパソコンの中) のフォルダから入れる**
- **B-2. Git (GitHub などの倉庫サイト) から直接入れる**

それぞれで起きやすいエラーが違うので、自分のケースに合うほうを読んでください。

---

### B-1. ローカルのフォルダから入れる場合

入力するコマンドはこんな形:

```
/plugin install /Users/あなたのユーザー名/path/to/cc-PortfolioKit
```

#### B-1-1. 「パスが見つかりません」と返ってくる

**症状の例**:

```
Error: Path does not exist: /Users/.../cc-PortfolioKit
```

**原因**: `cc-PortfolioKit` フォルダの場所 (パス) が間違っている、または途中の名前に **誤字** がある。

**対処**:

1. Finder (Mac) / エクスプローラー (Windows) で `cc-PortfolioKit` フォルダを実際に探す
2. そのフォルダを **右クリック** → 「**パスをコピー**」 (Mac は `Option` キーを押しながら) で正しいパスを取得
3. もう一度コマンドに貼り付けて実行

> **コピペがうまくいかない**
> 単純に「`cc-PortfolioKit` フォルダはどこにありますか?」と Claude Code に聞いてしまうのも手です。教えてくれます。

#### B-1-2. インストール途中に「Permission denied」 (許可がありません) と出る

**原因**: そのフォルダに対する **読み書きの権限** がない。

**対処**:

- フォルダの権限を確認: Finder / エクスプローラーで右クリック → 「情報を見る」 / 「プロパティ」
- 自分が **読み書き可能** になっているかを確認
- 直し方が分からない場合は、Claude Code に「`cc-PortfolioKit` フォルダの権限を確認したいです」と相談してください

#### B-1-3. パスに日本語やスペースが入っているとうまくいかない

**症状**: 「途中で切れたパスが渡された」「ファイルが見つからない」など、なんとなく動かない。

**原因**: パスに **スペース** (空白) や **日本語文字** が含まれていると、コマンドが正しく解釈してくれないことがあります。

**対処**:

- パスをコピペした後、**全体をダブルクォーテーション `" "` で囲む** とトラブルが減ります
  ```
  /plugin install "/Users/たろう/デスクトップ/cc-PortfolioKit"
  ```
- それでもダメなら、フォルダの場所を **半角英数字だけのフォルダ** に移してから試す (例: `/Users/your-name/dev/cc-PortfolioKit`)

---

### B-2. Git (GitHub など) から入れる場合 — ワークショップでつまずきがち

入力するコマンドはこんな形:

```
/plugin install https://github.com/ユーザー名/cc-PortfolioKit
```

> **ワークショップで実際にあった話**
> Git アカウントを持っていない方が「Git から入れようとしたらエラーが出る」と相談に来ました。**結論から言うと、Git アカウントは不要** です。**パブリック (公開) リポジトリ** であれば、誰でもダウンロードできます。
>
> その方のケースは **「URL が `git@github.com:...` で始まる SSH 形式」だった** ことが原因でした。SSH 形式はアカウントと「合鍵」の事前登録が必要なので弾かれます。**`https://github.com/...` の URL を使えば、アカウント不要で通ります**。

#### B-2-1. `git: command not found` と出る

**症状の例**:

```
zsh: command not found: git
```

または

```
'git' は、内部コマンドまたは外部コマンドとして認識されていません。
```

**原因**: パソコンに **Git というツール** がそもそも入っていません。Claude Code が Git を呼び出してダウンロードしようとするのですが、本体が無いので何も始められない、という状態です。

**対処**:

- **Mac の場合**: ターミナルで以下を実行。Apple の開発ツールに同梱されている Git をインストールできます。
  ```
  xcode-select --install
  ```
  ダイアログが出てくるので「**インストール**」を選んでください (数分かかります)。
- **Windows の場合**: 「**Git for Windows**」を検索して、公式サイト (`git-scm.com`) からダウンロードしてインストール。ウィザードはほとんど「次へ」で進めて大丈夫です。
- インストール後、ターミナルを **いったん閉じて開き直してから** もう一度 `/plugin install ...` を試してください。
- 確認のコマンド:
  ```
  git --version
  ```
  バージョン番号 (例: `git version 2.39.0`) が表示されれば OK です。

#### B-2-2. `Permission denied (publickey)` と出る (← ワークショップで遭遇したケース)

**症状の例**:

```
git@github.com: Permission denied (publickey).
fatal: Could not read from remote repository.
```

**原因**: **`git@github.com:ユーザー名/リポジトリ` の形式 (SSH URL)** でインストールしようとしています。SSH 形式は GitHub のアカウントを持っていて、かつ **「合鍵」(SSH キー) を登録済み** の人だけが使える、いわば裏口の通り道です。アカウントを持っていなければ通れません。

**対処**: URL を **`https://...` 形式 (HTTPS URL)** に変えてください。HTTPS なら **誰でも、アカウントなしでも、パブリック (公開) リポジトリを読みに行けます**。

| 形式 | 例 | アカウント要? |
| --- | --- | --- |
| ❌ SSH | `git@github.com:miyazakiryuji/cc-PortfolioKit.git` | **必要** (合鍵の事前登録も) |
| ✅ HTTPS | `https://github.com/miyazakiryuji/cc-PortfolioKit.git` | 不要 (パブリックなら誰でも OK) |

**正しい URL の入手方法**:

1. ブラウザで GitHub のリポジトリページ (例: `https://github.com/miyazakiryuji/cc-PortfolioKit`) を開く
2. 緑色の **「Code」ボタン** をクリック
3. タブが **「HTTPS」** になっているか必ず確認 (SSH や GitHub CLI が選ばれていることがあります)
4. 表示された URL の右にあるコピーアイコンを押す
5. その URL をコマンドに貼り付ける

```
/plugin install https://github.com/miyazakiryuji/cc-PortfolioKit
```

> **裏技**: URL の中の `git@github.com:` の部分を、自分の手で `https://github.com/` に書き換えて、末尾に `.git` を付けるだけでも変換できます。慌てているときは GitHub のページから取り直すのが安心です。

#### B-2-3. `Repository not found` と出る

**症状の例**:

```
fatal: repository 'https://github.com/miyazakiryuji/cc-portfoliokit.git/' not found
```

**原因の候補**:

1. **URL の打ち間違い** (タイプミス)
2. **大文字 / 小文字の違い** (`cc-PortfolioKit` と `cc-portfoliokit` は別物として扱われる)
3. リポジトリが **プライベート (非公開)** で、アクセス権がない
4. リポジトリが **削除 or 改名** されている

**対処**:

1. ブラウザでその URL を直接開いてみる → 404 や「Not Found」が出るなら URL が違います
2. リポジトリの **正確な綴り** をブラウザのアドレスバーからコピーする
3. プライベートリポジトリの場合は、**作成者にパブリック化してもらう** か、**アクセス権を付与してもらう** 必要があります

#### B-2-4. `could not read Username for 'https://github.com'` と出る

**症状の例**:

```
fatal: could not read Username for 'https://github.com': terminal prompts disabled
```

**原因**: HTTPS でアクセスしたとき、サーバー側が「**ユーザー名教えて**」と聞いてきたのに、Claude Code 側ではユーザー名を入力する場所が用意されていないため失敗。たいていは **プライベートリポジトリを HTTPS で開こうとしている** ときに出ます。

**対処**:

1. そもそも **パブリックリポジトリ** なら認証は必要ありません。URL に誤字がないか確認 (B-2-3 と同じ確認)
2. 本当にプライベートリポジトリなら、作成者にパブリック化してもらう
3. どうしても自分のプライベートリポジトリから入れたい場合は、GitHub の **Personal Access Token (パーソナル アクセス トークン = 個人用のパスワードのような文字列)** を発行して URL に含める方法もあります (ただしこれはやや上級者向け。普通は不要)

#### B-2-5. SSL 証明書エラー / プロキシで弾かれる (社内ネットワーク)

**症状の例**:

```
fatal: unable to access 'https://github.com/...': SSL certificate problem: unable to get local issuer certificate
```

または

```
fatal: unable to access 'https://github.com/...': Could not resolve host: github.com
```

**原因**: 会社のネットワークなどで、外部サイトへの通信が **プロキシ (中継地点)** や **ファイアウォール (関所)** を通る設定になっており、Git が通信できない / 証明書を検証できない状態。

**対処**:

1. まず **自宅などの普通のネットワーク** に繋ぎ直して試す。これだけで解決することが多いです (社内 Wi-Fi → スマホのテザリング、など)
2. 社内ネットワークから出る必要があるなら、**情報システム部門に「プロキシ設定の入れ方」を聞く** のがいちばん早道です
3. プロキシ設定が分かれば、ターミナルで以下のように設定:
   ```
   git config --global http.proxy http://プロキシのホスト:ポート
   git config --global https.proxy http://プロキシのホスト:ポート
   ```
4. 一時的な検証用の応急処置として SSL 検証を切ることもできますが (`git config --global http.sslVerify false`)、**セキュリティ上のリスクがあるので推奨しません**。社内ネットワークなら情シスに相談してください。

> **「専門用語が多くて何が何だか…」**
> ここまで読んで頭がいっぱいになっても大丈夫です。**「会社のネットワーク特有の設定が必要だから、情シスの人に聞く」** とだけ覚えてもらえれば十分です。

#### B-2-6. ネットワーク タイムアウト

**症状の例**:

```
fatal: unable to access '...': Failed to connect to github.com port 443: Operation timed out
```

**原因**: 単純にネットワークが不安定で、ダウンロードが時間切れになった。

**対処**:

1. **Wi-Fi の接続** を確認
2. しばらく時間を置いてから再試行 (5 〜 10 分置くと改善することも)
3. **別のネットワーク** (テザリング、別の Wi-Fi など) でも試してみる
4. ファイルサイズが大きいわけではないので、まともなネットワークなら数秒〜数十秒で終わるはず。長時間止まるのは異常です

#### B-2-7. Git のバージョンが古すぎる

**症状の例**: SSL 関連の謎エラー / 「未対応のプロトコル」のような英語が出る

**確認方法**:

```
git --version
```

`git version 1.x.x` のように **1 系** だと古すぎる可能性があります (推奨は **2.x 系** 以降)。

**対処**:

- **Mac**: `xcode-select --install` で同梱の Git を更新するか、Homebrew (`brew install git`) などで最新版を入れる
- **Windows**: Git for Windows を最新版で入れ直す

### B-3. インストール後にコマンドが反応しない

**症状**: `/plugin install` 自体は成功したのに、いざ `/cc-portfoliokit:init` や `/cc-portfoliokit:create` を打っても無反応 (または「コマンドが見つかりません」)

**対処**:

1. Claude Code を一度終了して **起動し直す** (たいていこれで直ります)
2. プラグイン一覧で `cc-portfoliokit` が入っているか確認:
   ```
   /plugin list
   ```
3. 入っていなければ、もう一度 `/plugin install` し直す
4. それでもダメなら、`/plugin list` の結果と一緒に Claude Code に「**これが入っているはずなのに動きません**」と相談

> **覚えるコマンドは 2 つだけです**
> `/cc-portfoliokit:init` (最初の 1 回だけ) と `/cc-portfoliokit:create` (HTML 生成と編集に何度でも) の 2 つ。順番を逆に叩いていないか、半角コロン `:` が抜けていないかも確認してください。

<a id="c-プラグインの動作中に起きるエラー"></a>

## C. プラグインの動作中に起きるエラー (`init` / `create`)

### C-1. 「テンプレートが見つかりません」と出る

**症状の例**:

```
templates/config.md が見つかりません
```

**原因**: プラグインのファイル一式が完全な状態ではない可能性があります。

**対処**:

1. `cc-PortfolioKit` フォルダの中に、本来あるべき以下のものが揃っているかチェック:
   - `templates/config.md`
   - `templates/profile.md`
   - `templates/work-history.md`
   - `templates/assets-README.md`
2. 足りないファイルがあれば、プラグインを **インストールし直す**
3. それでもダメなら、`cc-PortfolioKit` フォルダごとダウンロードし直して、新しいパスで `/plugin install` をやり直す

### C-2. 「既存のファイルがあります」と聞かれて、どうしていいか分からない

**こういう場面**:

```
既に以下が存在しています: config.md, career/profile.md
どうしますか?
  a) 既存ファイルは触らず、足りないものだけテンプレートで補う (推奨)
  b) すべてテンプレートで上書きする (注意: 既存内容は消えます)
  c) キャンセル
```

**判断のヒント**:

- **a) を選ぶのが基本** です。せっかく書いた内容を守れます。
- **b) は、いったん全部捨ててもいい場合のみ** 選んでください。書いた内容は戻ってきません。
- **迷ったら c)** でいったん中断して、フォルダの中身を Finder / エクスプローラーで確認してから判断するのも全然 OK。

### C-3. 質問の途中で接続が切れた / Claude Code が固まった

**対処**:

1. **慌てない** (大事)
2. `Ctrl` + `C` (CLI 版) または閉じるボタン (デスクトップ版) でいったん操作を止める
3. Claude Code を起動し直す
4. **init の途中で止まった場合** → もう一度 `/cc-portfoliokit:init` を実行。既存ファイルの扱いを聞かれるので、「**足りないものだけ作成する**」を選べば、書き込み済みの内容を守ったまま続きから再開できます
5. **create の途中で止まった場合** → もう一度 `/cc-portfoliokit:create` を実行。編集メニューから続きが書けます

> **「答えた内容は消えませんか?」**
> 質問の答えは、Markdown ファイル (`config.md` など) に **逐一保存される作りになっている** ので、途中で中断しても大半は残ります。安心してください。

### C-4. `/cc-portfoliokit:create` を実行したら「先に init を実行してください」と言われた

**こういうメッセージが出る場面**:

```
❌ ポートフォリオの素材が見つかりません。

足りないファイル:
  - <欠けているパスを列挙>

このコマンドは HTML 生成専用です。最初に下のコマンドで対話セットアップを実行してください:
  /cc-portfoliokit:init
```

**理由**: `create` は HTML を組み立てるコマンドであり、素材 (`config.md` や `career/profile.md` など) がまだ準備されていないと動けません。

**対処**: メッセージのとおりに `/cc-portfoliokit:init` を先に実行してください。氏名やキャリアのヒアリングが終わったら、自動的に素材が揃った状態になります。続けて `/cc-portfoliokit:create` を叩けば、`portfolio.html` が出来上がります。

> **「init は前にやったはずなのに…」**
> もしかすると、**作業フォルダが違う場所に変わっている** かもしれません。Claude Code に「いまどのフォルダで作業していますか?」と聞いて、`career/profile.md` が見える場所にいるか確認してください。

### C-5. ヒアリングが途中で勝手に終わってしまった

**症状**: 全部の質問が終わる前に、突然「完了しました」と言われた / 何社か職歴が抜け落ちている。

**原因の候補**: 質問の途中で 「**もう 1 社追加しますか?**」 への返事を「**No**」「**いいえ**」「**もういいです**」と読み取ってしまった可能性。

**対処**:

- もう一度 `/cc-portfoliokit:create` を実行 → 編集メニューで **「職歴を追加する」** を選び、追加したい職歴を入れていく
- すでにある職歴も、編集メニューから書き直せます

<a id="d-出来上がった-html-がおかしい"></a>

## D. 出来上がった HTML がおかしい

### D-1. `portfolio.html` をブラウザで開いたら真っ白

**症状**: ファイルは開けるけれど、何も表示されない。

**よくある原因**:

- **HTML 内の特殊文字 (`<`, `>`, `&` など) のエスケープ漏れ** → 中身が壊れている
- **ファイルが空 (= 生成が途中で止まった)**

**対処**:

1. **`portfolio.html` のファイルサイズ** をチェック。極端に小さい (例: 0 KB) なら、生成が失敗しています。
2. もう一度 `/cc-portfoliokit:create` を実行して、「再生成」を選んでみる
3. それでも空白の場合、Claude Code に **「`portfolio.html` を開いたら何も表示されません」** と素直に相談 → 中身を見て原因を教えてくれます

### D-2. 顔写真が表示されない (画像が四角の枠だけになる)

**原因の候補**:

1. `config.md` の `photo:` に書いたファイル名と、`assets/` フォルダの実際のファイル名が違う
2. 顔写真のファイルが、まだ `assets/` フォルダに置かれていない
3. ファイル名に半角スペースや日本語が混ざっていて、ブラウザがうまく読めない

**対処**:

1. `assets/` フォルダの中身を確認。**たとえば `photo.jpg` という名前で置いているか** を確認
2. `config.md` を開いて、`photo: photo.jpg` のような行があるか確認
3. ファイル名の **大文字 / 小文字も一致しているか** に注意 (`Photo.JPG` と `photo.jpg` は別物として扱われます)
4. ファイル名は **半角英数字のみ** にするとトラブルが減ります (例: `profile.jpg`)

> **「ファイル名どう変えるんだっけ?」**
> Finder / エクスプローラーでファイルを **右クリック** → 「**名前を変更**」 を選びます。

### D-3. 顔写真が大きすぎる / ページが重い

**原因**: 写真ファイルのサイズが大きすぎる。

**対処**:

- 写真ファイルを **圧縮する** (検索「画像 圧縮 オンライン」で出てくる無料のツールが便利です)
- 推奨サイズは **500 KB 以下** くらい
- スマホで撮った写真はそのままだと数 MB あることが多いので、必ず圧縮してから入れてください

### D-4. ページがガタガタに崩れている

**原因**: `config.md` などの Markdown ファイルの書き方を間違えた可能性があります。

**対処**:

1. `config.md` を開いて、**フロントマター** と呼ばれる先頭部分の書き方を見直す
   - 上下が `---` (3 つのハイフン) で囲まれている必要があります
2. 書き方が分からなければ、`templates/config.md` の見本と見比べる
3. 「ファイルの書き方を間違えたかもしれません」と Claude Code に相談すれば、見て直してくれます

### D-5. 文字化けしている

**原因**: ブラウザが文字コードを誤認している、またはファイルの保存形式がずれている。

**対処**:

- まずブラウザを **再読み込み (`F5` または `Command` + `R`)**
- それでもダメなら、別のブラウザ (Safari → Chrome など) で開いてみる
- それでもダメなら、もう一度 `/cc-portfoliokit:create` で再生成

### D-6. ダークモードのときに文字が読めない

**症状**: 夜、パソコンが暗いモード (ダークモード) のときに、白背景に白文字になって読めない、など。

**原因**: ブラウザがダークモード設定を反映していなかったり、テーマカラーがダークモードと相性が悪かったりします。

**対処**:

1. ブラウザのウィンドウをいったん閉じて開き直す
2. `config.md` の `theme_color` / `accent_color` を、明るい色と暗い色のどちらでも読める色味に変える
3. それでも気になる場合は、Claude Code に「**ダークモードでも読みやすい色にしてください**」と頼めば、色味を提案してくれます

### D-7. 印刷したら色が消えてしまった

**症状**: ブラウザで「印刷」を押すと、背景色や強調色が真っ白になってしまう。

**原因**: ブラウザの印刷設定の多くは、**インク節約のため背景色を自動でカットする** ようになっています。

**対処**:

- 印刷ダイアログで **「背景のグラフィック」** にチェックを入れる (Chrome / Edge ならオプションの中にあります)
- もしくはそのまま印刷して、**「背景がなくても読める」設計になっている** ので大きな問題はありません。`cc-PortfolioKit` の HTML は印刷時を想定して、文字色をしっかり残すように作っています

<a id="e-やってしまった系のミス"></a>

## E. 「やってしまった」系のミス

### E-1. 間違えて `portfolio.html` を消してしまった

**安心ポイント**: `portfolio.html` は **元データ (`config.md` など) からいつでも作り直せる** ので、消えてもダメージはほぼ無しです。

**対処**:

```
/cc-portfoliokit:create
```

を実行すれば、再生成してくれます。

### E-2. 間違えて `config.md` や `career/` フォルダを消してしまった

**ダメージ度**: 中。書いた内容は戻ってきませんが、`init` でもう一度やり直せます。

**対処**:

1. ゴミ箱 / 「最近削除した項目」を確認 → 戻せるなら戻す
2. 戻せない場合は、もう一度 `/cc-portfoliokit:init` を実行してセットアップをやり直す
   - 既存ファイルが部分的に残っている場合は「**足りないものだけ作成する**」を選ぶと安全です
3. 再度内容を入力し直す
4. その後 `/cc-portfoliokit:create` で `portfolio.html` を作り直す

> **このために定期バックアップを**
> ポートフォリオを作り込んできたら、**フォルダごとコピーして別の場所に置いておく** だけでバックアップになります。月に 1 回くらいで十分です。

### E-3. 間違えて編集メニューで違う項目を上書きしてしまった

**対処**:

- もう一度 `/cc-portfoliokit:create` を実行して、編集メニューから **正しい内容を入れ直す** だけです。データは「最後に書いた内容」が残るので、書き直せばそれが正です。

### E-4. 気付いたら違うフォルダで `init` を実行してしまっていた

**症状**: 「マイポートフォリオ」フォルダに作りたかったのに、なぜか別の場所に `config.md` や `career/` ができていた。

**対処**:

1. 慌てて中身を消さない。**いったんファイル群をコピーして、本来作りたかったフォルダに移す** のが安全策
2. その後、間違ったフォルダにできた `config.md` / `career/` / `assets/` を削除
3. 移し終わったら、本来の作業フォルダに移動して `/cc-portfoliokit:create` を実行

> **「フォルダ移動でファイルが消えた!」**
> ほとんどの場合、**目的地に到着している** だけで消えてはいません。Finder / エクスプローラーで目的のフォルダを開いて確認してください。

<a id="f-パスフォルダまわりのトラブル"></a>

## F. パス・フォルダまわりのトラブル

### F-1. パスに日本語やスペースが入っているとうまくいかない

**症状**: パスが途中で切れる、ファイルが見つからない、文字化けする。

**対処**:

- パス全体を **ダブルクォーテーション `" "`** で囲む
- 可能なら、作業フォルダ自体を **半角英数字だけ** の名前に変える (例: `マイポートフォリオ` → `my-portfolio`)
- フォルダの場所もシンプルに (例: `デスクトップ/作業/2026年/マイポートフォリオ` のような深い階層は避ける)

### F-2. iCloud Drive / OneDrive の中で作業して同期が暴れる

**症状**: ファイルが勝手に消えたり戻ったりする。Claude Code が「ファイルが見つかりません」と言う / 編集してもすぐ別の内容に書き換わる。

**原因**: クラウド同期サービスが、ファイルの実体をローカルに残さず「**雲の中**」に置いていることがあり、Claude Code が読み書きするタイミングと衝突して暴れます。

**対処**:

- 作業フォルダを **同期対象外** (例: ホームの `Developer/`、`Documents` 直下ではなくデスクトップなど) に置く
- どうしても iCloud / OneDrive の下で作業するなら、フォルダを **「常にこのデバイスに保存」** 設定にして、雲ではなくローカルに実体を置く
- 同期サービスを **一時的に停止** してから作業するのも有効

> **iCloud に気づかず保存してしまっているケース**
> Mac の「**書類**」フォルダや「**デスクトップ**」は、デフォルトで iCloud と同期されている設定になっていることがあります。設定で「**書類とデスクトップ**」のチェックを外せば、ローカル保管に戻せます。

### F-3. ホームフォルダ自体に書き込み権限がない

**症状**: 何をしても「Permission denied」が消えない。

**対処**:

- 自分のユーザーが管理者権限を持っているか確認 (会社支給のパソコンで権限が制限されていることがあります)
- 情シスに相談 / 別のフォルダ (`/tmp/` などの誰でも書ける場所) で試してみる

<a id="g-ネットワーク通信のトラブル"></a>

## G. ネットワーク・通信のトラブル

### G-1. 何をしても「通信に失敗しました」が出る

**対処**:

1. Wi-Fi のアイコンが繋がっているか目視で確認
2. ブラウザで普通のサイト (例: Google) が開けるか確認 → 開けないならネット自体が落ちています
3. **ルーターを再起動** (5 秒以上電源を抜く)。もはや IT のおまじない

### G-2. 社内ネットワークで弾かれる

→ [B-2-5. SSL 証明書エラー / プロキシで弾かれる](#b-2-5-ssl-証明書エラー--プロキシで弾かれる-社内ネットワーク) と同じ対処です。情シスに相談するのが結局いちばん早道。

### G-3. レートリミットに引っかかった

**症状**: 「**しばらく時間をおいてからもう一度お試しください**」「**Too many requests**」のようなメッセージが出る。

**原因**: 短時間に大量の操作を行うと、サービス側が一時的にアクセスを止めることがあります。

**対処**:

- **10 〜 30 分待ってから** やり直す
- 同じ操作を連続して何度も叩かない (慌てて連打しがちですが、たいてい裏で処理は進んでいます)

<a id="h-それでも解決しないとき"></a>

## H. それでも解決しないとき

ここまで読んでも直らないときは、Claude Code に **素直に相談する** のがいちばん早道です。

### 報告するときのコツ

以下を伝えてもらえると、原因の特定が劇的に早くなります。

1. **何をしようとしたか** (例: 「ポートフォリオを初めて作ろうとして…」)
2. **どう操作したか** (例: 「`/cc-portfoliokit:create` を入力しました」)
3. **どんなメッセージが出たか** (例: 「`Error: Path does not exist` と出ました」)
4. **OS とアプリのバージョン** (例: 「Mac の Sonoma で、デスクトップアプリ版を使っています」)

これだけ伝えれば、Claude Code が原因を一緒に切り分けてくれます。

### スクショを貼る

エラー画面のスクリーンショットを撮って、デスクトップアプリ版なら入力欄にそのまま貼り付けることができます。**写真を見て判断してくれるので、説明が苦手でも大丈夫** です。

### コミュニティに頼る

公式の Claude Code 関連のフォーラムや、`cc-PortfolioKit` の **GitHub Issues** に同じ症状の報告がないかを検索してみるのも有効です。
