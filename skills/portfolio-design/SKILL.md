# portfolio-design — cc-PortfolioKit 専用のフロントエンドスキル

このスキルは `/cc-portfoliokit:create` から呼び出される **HTML / CSS デザイン担当** です。`create` コマンド側はデータ収集とパース、Edit、状態管理に集中し、見た目のことはすべてこのスキルが受け持ちます。

> **位置づけ**: cc-PortfolioKit プラグイン内蔵のフロントエンド専門スキル。`create.md` から `Skill` ツール経由で呼び出される前提です。手動で呼ぶことも可能ですが、通常は `create` の HTML 生成ステップから呼ばれます。

---

## 1. このスキルが受け持つもの

- **HTML の構造テンプレート** ── `<header> / <main> / <footer>` の骨格と各 `<section>` の中身
- **CSS デザインシステム** ── レスポンシブ / ダークモード / 印刷対応 / タイムラインのスタイル
- **配色パレット** ── 雰囲気ごとの推奨カラーセット
- **職業に応じた表示ラベルの差し替えルール** ── 「使用技術」「担当業界・商材」「研究分野」など
- **Markdown → HTML 変換のサポート範囲**
- **XSS 防止のためのエスケープルール**

`create.md` 側で行う「データの読み込み」「テーマウィザードの対話」「ファイル書き出し」には関与しません。

---

## 2. 呼び出され方

`create.md` の B-3 HTML 生成フェーズで、以下の入力を受け取って HTML 文字列を組み立てます。

### 入力 (`create.md` から渡される想定)

| 項目 | 例 | 出どころ |
|---|---|---|
| `name` / `name_kana` / `name_en` | 山田 太郎 / やまだ たろう / Taro Yamada | `career/profile.md` |
| `profession` | エンジニア / IT | `career/profile.md` の `## 職業` |
| `career_years` | 5 年 | `career/profile.md` の `## キャリア総年数` |
| `short_bio` | (任意) | `career/profile.md` の `## 自己紹介 (短く)` |
| `birthday` / `location` / `languages` | (任意・拡張) | `career/profile.md` |
| `entries` | エントリ配列 | `career/work-history.md` を `## 名称` で分割し `{ name, type, period, role, tasks[], tech, achievements[] }` に整形 |
| `site_title` / `tagline` | 山田太郎 — Portfolio / フルスタックエンジニア | `config.md` |
| `theme_color` / `accent_color` | `#4F46E5` / `#F59E0B` | `config.md` |
| `language` | `ja` | `config.md` |
| `photo_path` | `assets/photo.jpg` | `config.md` の `## 顔写真のファイル名` |
| `contact` | `{ email, github, x, linkedin, website }` | `config.md` の `## 連絡先` の `###` サブ項目 |
| `sections` | `["Profile", "About", "Work History", "Contact"]` | `config.md` の `## 表示するセクションと順番` |
| `about_md` / `skills_md` / `education_md` | (Markdown 本文) | `config.md` の対応セクション |
| `today` | `YYYY-MM-DD` | `create.md` 側で生成 |

### 出力

`portfolio.html` の **完全な HTML 文字列**。`create.md` 側はそれを `Write` で書き出すだけ。

## 3. HTML 構造テンプレート

`sections` の配列順で `<section>` を出力します。配列に無いキーは出力しません。

```html
<!doctype html>
<html lang="{{language}}">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width,initial-scale=1">
  <title>{{site_title}}</title>
  <style>/* §4 の CSS をインライン化 */</style>
</head>
<body>
  <header>
    <img src="{{photo_path}}" alt="{{name}}" class="hero-photo">
    <h1>{{name}}</h1>
    <p class="tagline">{{tagline}}</p>
  </header>

  <main>
    <!-- sections[] の順で以下を出し分ける -->

    <section id="profile">
      <h2>Profile</h2>
      <dl class="profile-grid">
        <dt>氏名</dt><dd>{{name}}<span class="kana">({{name_kana}})</span></dd>
        <dt>職業</dt><dd>{{profession}}</dd>
        <dt>キャリア</dt><dd>{{career_years}}</dd>
        <!-- birthday / location / languages があれば出す。空なら省く -->
      </dl>
    </section>

    <section id="about">
      <h2>About</h2>
      <!-- about_md を Markdown→HTML 変換した結果を埋め込む -->
    </section>

    <section id="work-history">
      <h2>Career / 経歴</h2>
      <!--
        entries[] を type ("本業" / "副業" / "活動") でグループ化し、
        本業 → 副業 → 活動 の順で <h3> + <ol class="timeline"> を出力。
        該当エントリが 0 件のカテゴリは <h3> ごと出力しない。
      -->
      <h3>本業</h3>
      <ol class="timeline"><!-- type=本業 のエントリ --></ol>
      <h3>副業</h3>
      <ol class="timeline"><!-- type=副業 のエントリ --></ol>
      <h3>活動</h3>
      <ol class="timeline"><!-- type=活動 のエントリ --></ol>
    </section>

    <section id="skills">
      <h2>Skills</h2>
      <!-- skills_md を Markdown→HTML 変換 -->
    </section>

    <section id="education">
      <h2>Education</h2>
      <!-- education_md を Markdown→HTML 変換 -->
    </section>

    <!--
      Contact セクションは contact が全て空の場合は <section> ごと出力しない。
      sections[] に "Contact" が含まれていても、空ならスキップする。
      外部リンクは必ず target="_blank" rel="noopener noreferrer" を併記する (§8.2)。
      mailto: には target="_blank" / rel は付けない。
    -->
    <section id="contact">
      <h2>Contact</h2>
      <ul class="contact-list">
        <li>Email: <a href="mailto:{{contact.email}}">{{contact.email}}</a></li>
        <li>GitHub: <a href="{{contact.github}}" target="_blank" rel="noopener noreferrer">{{contact.github}}</a></li>
        <!-- x / linkedin / website も同じ形 (target="_blank" rel="noopener noreferrer")。空文字なら <li> ごと省く -->
      </ul>
    </section>
  </main>

  <footer>
    <small>Generated by cc-PortfolioKit · {{today}}</small>
  </footer>
</body>
</html>
```

### 各エントリの内側 `<li>` テンプレート

```html
<li class="timeline-item">
  <div class="timeline-head">
    <h4>{{entry.name}}</h4>
    <span class="timeline-period">{{entry.period}}</span>
  </div>
  <p class="timeline-role">{{entry.role}}</p>   <!-- role が空ならこの行ごと出力しない -->
  <ul class="timeline-tasks">
    <!-- entry.tasks[] を <li> で展開 -->
  </ul>
  <p class="timeline-tech"><strong>{{tech_label}}:</strong> {{entry.tech}}</p>  <!-- tech が空ならこの行ごと出力しない -->
  <ul class="timeline-achievements">
    <!-- entry.achievements[] を <li> で展開。0 件なら <ul> ごと出力しない -->
  </ul>
</li>
```

> `{{tech_label}}` は §5 の対応表で `profession` から引いた表示ラベル。

## 4. CSS デザインシステム

`<style>` タグ内にインライン埋め込み。外部 CSS / フォント CDN は使いません。

### 4.1 CSS 変数とリセット

```css
:root {
  --theme:    {{theme_color}};
  --accent:   {{accent_color}};
  --fg:       #1f2937;
  --fg-mute:  #4b5563;
  --bg:       #ffffff;
  --bg-mute:  #f3f4f6;
  --border:   #e5e7eb;
  --radius:   12px;
  --shadow:   0 1px 3px rgba(0,0,0,.06), 0 1px 2px rgba(0,0,0,.04);
  --font:     "Hiragino Sans", "Yu Gothic", "Helvetica Neue", system-ui, sans-serif;
}

* { box-sizing: border-box; }
html, body { margin: 0; padding: 0; }
body {
  font-family: var(--font);
  color: var(--fg);
  background: var(--bg);
  line-height: 1.7;
  font-size: 16px;
}
```

### 4.2 レイアウト要件

- **コンテナ幅**: `max-width: 760px; margin: 0 auto; padding: 24px;`
- **`<header>`**: 上下に余白 48px。顔写真は中央配置で `border-radius: 50%; width: 160px; height: 160px; object-fit: cover;`
- **`<h1>`**: 氏名、`font-size: 28px;` 中央寄せ
- **`.tagline`**: `color: var(--fg-mute); text-align: center;`
- **`<section>`**: 上下に 32px 余白、`<h2>` は `border-bottom: 2px solid var(--theme); padding-bottom: 6px; margin-top: 0;`
- **`.profile-grid`**: `<dl>` を CSS Grid で 2 列 (`grid-template-columns: max-content 1fr; gap: 8px 16px;`)
- **`<h3>`** (本業/副業/活動): `color: var(--theme); margin-top: 24px;`

```css
a { color: var(--accent); text-decoration: none; }

```

> **HTML 出力ルール**: 外部 URL ── `http://` / `https://` で始まる href ── を出力する `<a>` には、テンプレート上で必ず `target="_blank" rel="noopener noreferrer"` を併記する。`mailto:` / 内部アンカー (`#`) には付けない。ルールは §8.2 を参照。

```css

```

### 4.6 ダークモード

```css
@media (prefers-color-scheme: dark) {

    --fg:      #f3f4f6;
    --fg-mute: #9ca3af;

```

### 4.7 印刷対応

```css
@media print {
  body { font-size: 11pt; }
  header, section { page-break-inside: avoid; }
  a { color: inherit; text-decoration: none; }
  a[href]::after { content: " (" attr(href) ")"; font-size: 9pt; color: #555; }

  .timeline-item::before { background: #333; box-shadow: none; }
}
```

> 印刷時は背景色が消えても読めるよう、文字色とコントラストに頼った設計にすること。

## 7. Markdown → HTML 変換のサポート範囲

外部ライブラリは使わず、以下のサブセットを Claude が直接変換します。

| Markdown | HTML |
|---|---|
| `## 〇〇` | `<h2>〇〇</h2>` |
| `### 〇〇` | `<h3>〇〇</h3>` |
| `- 項目` | `<ul><li>項目</li>...</ul>` |
| `1. 項目` | `<ol><li>項目</li>...</ol>` |
| `**強調**` | `<strong>強調</strong>` |
| `*強調*` / `_強調_` | `<em>強調</em>` |
| `` `コード` `` | `<code>コード</code>` |
| `[テキスト](URL)` | `<a href="URL">テキスト</a>` |
| 連続した段落 | `<p>段落</p>` で囲む |
| HTML コメント `<!-- ... -->` | 出力しない |

> ネストしたリストや表は **このスキルでは扱いません**。入力 Markdown でそれが現れた場合は、見た目を崩さない最低限の整形 ── たとえばインデント付きの `<ul>` ── にとどめます。

## 8. XSS / 安全のためのルール (必須)

ユーザー入力は最終的に **3 つの異なるコンテキスト** に流れます。コンテキストごとに防御が違うので、**「とりあえず HTML エスケープ」では足りません**。順番に守ってください。

### 8.1 HTML テキストコンテキスト

ユーザー入力のうち HTML に流し込むすべての値で `<`, `>`, `&`, `"`, `'` を必ずエスケープする。

| 元 | 置換後 |
|---|---|
| `<` | `&lt;` |
| `>` | `&gt;` |
| `&` | `&amp;` |
| `"` | `&quot;` |
| `'` | `&#39;` |

加えて:

- **`<script>` / `<style>` タグは出力 HTML に絶対に含めない** (このスキル自身が §4 で定義する `<style>` を除く)
- **`on*=` 属性 (`onclick` 等) を出力 HTML に含めない**

### 8.2 URL コンテキスト (`href` / `src`)

**`href` に流し込むすべての URL に適用する**。対象は次の経路すべて:

- `contact.email` / `contact.github` / `contact.x` / `contact.linkedin` / `contact.website`
- §7 の Markdown 変換で `[テキスト](URL)` から生成される `<a href="URL">` の URL ── つまり `about_md` / `skills_md` / `education_md` / `entries[].tasks[]` / `entries[].achievements[]` などすべての自由記述に潜むインラインリンク
- 将来追加されうるあらゆる `href` 出力箇所

検証ルール:

1. **スキームのブロックリスト**: `javascript:` / `data:` / `vbscript:` / `file:` で始まる値は弾く。比較は **小文字化 + 前後の空白除去** したうえで前方一致
2. **許可スキーム**: `https://` / `http://` / `mailto:` / `#` で始まる、または `/` で始まる相対パス、または `assets/` で始まる相対パスのみ通す
3. **マッチしない値は出力 HTML に含めない** ── リンク自体を出さない、もしくはテキストとして出す
4. **`target="_blank"` を付ける外部リンクには必ず `rel="noopener noreferrer"` を併記する** (§3 / §4.4 のテンプレに反映済み)

`src` 属性に流し込む値は同様にホワイトリスト ── `assets/` で始まる相対パスのみ ── でフィルタする。`http://` / `https://` / `data:` / 絶対パス / `..` を含むパスはすべて拒否。

### 8.3 CSS コンテキスト (`theme_color` / `accent_color`)

`theme_color` / `accent_color` は `<style>` 内の CSS 変数値 `--theme` / `--accent` に展開される。**HTML エスケープでは CSS インジェクションを防げない** ことに注意。

検証ルール:

1. 値を `^#[0-9A-Fa-f]{6}$` または `^#[0-9A-Fa-f]{3}$` の正規表現でマッチング
2. マッチしない場合は **そのフィールドだけフォールバック値** を使う:
   - `theme_color` 不正 → `#4F46E5`
   - `accent_color` 不正 → `#F59E0B`
3. フォールバックを使った場合、`create.md` 側に「`config.md` の HEX が不正だったのでデフォルトに戻した」旨を返し、ユーザーに通知してもらう
4. **CSS 内に流す前に正規表現を通す** ── パース時のチェックを信用しない。`config.md` を手書きで編集された後、もしくは並行セッションで書き換えられたケースに備える

> CSS インジェクションが成立すると、`} body{background:url(https://evil)` のような値で `<style>` ブロックを任意に書き換えられる。HTML エスケープでは値の `}` や `;` を防げない。CSS 変数値に流し込む値は **必ず形式検証** を通すこと。

### 8.4 言語属性 (`lang`)

`<html lang="...">` に流し込む `language` の値は BCP 47 形式 (`ja` / `en` / `ja-JP` / `zh-TW` など) を期待する。

- **検証**: `^[a-zA-Z]{2,3}(-[a-zA-Z0-9]{2,8})*$` にマッチするか確認
- **マッチしないとき**: `ja` にフォールバックし、`create.md` 側に通知

「日本語」のような自由テキストや、空文字、絵文字混入をそのまま `lang` に出すと invalid HTML になる。

### 8.5 適用順序

`create.md` から渡された値は **常にこの §8 のルールを最初に通してから** §3 のテンプレートに埋め込むこと。「`create` 側で検証されているはず」という前提は持たない ── ファイルが並行セッションや手書き編集で変わっている可能性があるため、スキル側で **必ず自前のガード** を入れる。

## 9. 出力時の健全性チェック

最終 HTML を返す前に、以下を満たしているか自己チェックする。

- [ ] `<!doctype html>` で始まっている
- [ ] `<title>` の中身が空でなく、`site_title` を含む
- [ ] `<h1>` の中身が `name` を含む
- [ ] `sections` に含まれる各セクションが対応する `<section>` として出力されている
- [ ] `sections` に含まれない名前のセクションは出力されていない
- [ ] `<script>` タグ / `on*=` 属性が含まれていない
- [ ] 顔写真が指定されていれば `<img>` が、無ければ顔写真要素は出力されていない
- [ ] 経歴は本業 → 副業 → 活動 の順で並び、空カテゴリは見出しごと省略されている

## 10. このスキルが扱わないこと

明示的に責務外なので、`create.md` 側で処理してください。

- 状態判定 (`HAS_CONFIG`, `HAS_HTML` などのフラグ)
- Markdown ファイルの `Read` 自体
- テーマウィザードの **対話進行** (このスキルはパレット辞書を提供するだけで、Q&A 進行は `create.md` 側)
- `config.md` への `Edit`
- `portfolio.html` への `Write`
- 完了報告メッセージ

このスキルは **「HTML 文字列を組み立てる純粋関数」** に近い責務だと考えてください。
