## ブランチ B: 初回 HTML 生成

入力 Markdown は揃っているが `portfolio.html` がまだ無い状態です。**生成前にテーマ方向性を一度だけ確認** したうえで HTML を作ります (`init` は中身を聞かない・`hearing` は経歴だけ集める設計なので、見た目はテンプレ初期値のまま。ここで一度ユーザーに方向性を選んでもらう)。

### B-1. Markdown のパース

3 つの Markdown ファイルを `Read` し、以下を取り出します。

> **重要 — フォーマットについて**: cc-PortfolioKit の入力ファイルは **YAML フロントマターを使いません**。すべてのデータは `## 見出し` ブロック構造で表現されています。各 `## 〇〇` 見出しの **直下の値 (空行を挟んだあとの本文)** が、その項目の値です。HTML コメント (`<!-- ... -->`) はパース時に必ず無視してください。

#### 共通パースルール

- ファイル全体を `## ` 行で分割し、各ブロックを `{ "label": "<見出しテキスト>", "body": "<見出し下の本文>" }` の形にする
- `body` から HTML コメント (`<!-- ... -->`) を除去
- `body` の前後の空白行を `trim`
- 値が **入れ子になっている項目 (`## 連絡先`)** は、さらに `### ` で分割して同じ要領で扱う
- ブロックが存在しない項目は **その項目を出力しない** (空値で埋めない)
- 見出しは表記揺れに寛容に扱う (`## 氏名` / `## 氏名 / Name` / `## Name` のいずれもマッチ)

#### config.md から取り出す項目

| 期待する見出し (例) | 値の意味 |
|---|---|
| `## サイトタイトル` | `site_title` |
| `## キャッチコピー` | `tagline` |
| `## テーマカラー` | `theme_color` (HEX) |
| `## アクセントカラー` | `accent_color` (HEX) |
| `## 表示言語` | `language` (`ja` / `en` など) |
| `## 顔写真のファイル名` | `photo` (相対パス) |
| `## 連絡先` | 入れ子。下表のサブ項目を全部試して、ブロックが存在するものだけ取得する |
| `## 表示するセクションと順番` | 番号付きリストをそのままパースして `sections` の配列に |
| `## 自己紹介 (About)` | 本文セクション |
| `## スキル / Skills` | 本文セクション (任意) |
| `## 学歴 / Education` | 本文セクション (任意) |

**`## 連絡先` のサブ項目 (10 種類すべてに対応):**

| サブ見出し | キー名 | 注意 |
|---|---|---|
| `### メールアドレス` | `email` | `mailto:` で出す |
| `### GitHub` | `github` | URL またはハンドル |
| `### Website` | `website` | URL |
| `### X / Twitter` (旧 `### X (Twitter)` も後方互換で受ける) | `x` | URL またはハンドル |
| `### Instagram` | `instagram` | URL またはハンドル |
| `### LinkedIn` | `linkedin` | URL |
| `### Facebook` | `facebook` | URL |
| `### YouTube` | `youtube` | URL |
| `### TikTok` | `tiktok` | URL またはハンドル |
| `### note` | `note` | URL |

`### X (Twitter)` という旧表記 (括弧付き) は **そのまま受ける** (後方互換)。新規生成では `### X / Twitter` を使う。値が空 / ブロックが存在しない / 値が `<!-- ... -->` のコメントのみ ── これらはすべて「無し」として扱い、HTML には出力しない。

#### career/profile.md から取り出す項目

| 期待する見出し (例) | 値の意味 |
|---|---|
| `## 氏名` | `name` |
| `## ふりがな` | `name_kana` (任意) |
| `## 英語表記` | `name_en` (任意) |
| `## 職業` | `profession` (本業の主な職業。HTML レンダリング時のラベル選択に使う) |
| `## キャリア総年数` | `career_years` (任意。新仕様では init / hearing が聞かないので空のことが多い。あれば表示) |
| `## 自己紹介 (短く)` | プロフィールカード下の短い bio (任意) |
| `## 生年月日` | `birthday` (任意・拡張) |
| `## 居住地` | `location` (任意・拡張) |
| `## 話せる言語` | `languages` (任意・拡張、箇条書きを配列化) |

#### career/work-history.md から取り出す項目

- `## ` 行で全エントリに分割 ── 1 件 = 1 エントリ、名称は会社名・案件名・イベント名など
- 各エントリ内をさらに `### ` で分割し、以下を取り出す:
  - `### 種別` → `type` (**本業 / 副業 / 活動** のいずれか。省略されているエントリは本業として扱う ── 後方互換)
  - `### 期間` → `period`
  - `### 役職` → `role`
  - `### 業務内容` → `tasks` (箇条書きを配列化)。本業で使う見出し
  - `### やったこと` → `tasks` (箇条書きを配列化)。副業・活動で使う見出し。**本業に `### やったこと` が来た場合、または副業・活動に `### 業務内容` が来た場合も `tasks` に統合して扱う** (表記揺れ吸収)
  - `### 全体の成果` → `overall_achievements` (箇条書きを配列化)。本業のみ。任意
  - `### 使ったツール・スキル` → `tools`。**旧表記 `### 使用技術` も後方互換で受ける** (フィールド名は `tools` に統一)
  - `### 成果` → `achievements` (箇条書きを配列化)
- **本業の `### プロジェクト: <PJ 名>` ブロック** ── 本業のみに現れる二段構造。`### ` の値が `プロジェクト:` で始まる場合は PJ ブロックとして扱う:
  - `<PJ 名>` (見出しの `プロジェクト:` より後ろの文字列を `trim`) → `projects[].name`
  - PJ ブロック内の `#### 使ったツール・スキル` → `projects[].tools` (任意)
  - PJ ブロック内の `#### 成果` → `projects[].achievements` (箇条書きを配列化、任意)
  - `projects[]` は本業エントリにのみ持たせる配列。副業・活動では空 or 未定義
- 並び順は Markdown 上の順 (hearing で決めた順番)。種別の混在順は保持しつつ、レンダリング時に種別ごとにグループ化する
- `### 〇〇` ブロックが存在しないフィールドは出力時に **その行ごと省略**

> パースに失敗したファイルがあれば、ユーザーに **具体的なファイル名と原因** を伝えて中断してください。「## 見出しが見つからない」「期待した値が空」などは具体的に。空値で勝手に埋めないこと。
>
> **表記揺れ吸収のまとめ**: `### 使用技術` ↔ `### 使ったツール・スキル`、`### 業務内容` ↔ `### やったこと`、`### X (Twitter)` ↔ `### X / Twitter` ── これらは新旧どちらでも同じフィールドに格納する。新規生成は新表記を使う。

### B-1.5. テーマ方向性のヒアリング

`portfolio.html` がまだ無い状態なので、HTML 生成の前に **デザインの方向性** を一度ユーザーに確認します。

まず、現在 `config.md` に書かれている設定を提示します:

```
今 config.md にはこんな設定が入っています:

  サイトタイトル:   <site_title>
  キャッチコピー:   <tagline>
  テーマカラー:     <theme_color>
  アクセントカラー: <accent_color>
  含めるセクション: <sections のカンマ区切り>

このまま生成しますか? それともここで方向性を決め直しますか?

  1) このまま生成する (テンプレートの初期値で OK な人向け)
  2) テーマ・色・構成を決め直したい
  3) イメージがない (こちらから案を提案します)
```

#### 選択 1) - そのまま B-2 へ

特に何もせず、`### B-2. 顔写真の処理` に進みます。

#### 選択 2) - 方向性を決め直す対話

順番に聞いていきます。**1 問ずつ短く**。「スキップ」と言われた項目は現状値のままにします。

**Step a. 雰囲気のヒアリング**

```
どんな雰囲気のポートフォリオにしたいですか?
  1) 落ち着き / プロフェッショナル (ビジネスライク)
  2) カジュアル / 親しみやすい
  3) クリエイティブ / 個性的
  4) シンプル / ミニマル
  5) ダーク / モダン
  6) その他 (自由記入: 「和風」「春っぽく」など何でも)
```

選ばれた雰囲気を `$VIBE` として保持。`6)` の場合は自由記入をそのまま `$VIBE` に格納します。

**Step b. カラー候補の提示**

`$VIBE` に応じて、テーマカラー + アクセントカラーの組を **3〜4 個** 提案します。各候補は HEX で表示し、簡単な日本語の説明を添えてください。

> **配色の辞書は専用スキルに集約済み**: 雰囲気ごとの推奨パレットは `cc-portfoliokit:portfolio-design` スキルの §6 にあります。Step b を実行する前に `Skill` ツールで該当スキルを読み、`$VIBE` に対応する 3〜4 組を取り出して提示してください。`6)` の自由入力の場合は、その記述に合わせて Claude が即興で組み立てます (たとえば「和風」→ 藍 + 朱、「春っぽく」→ 桜ピンク + 若葉、など)。

ユーザーが選んだ番号の組を `theme_color` / `accent_color` として保持。`4)` の場合は HEX を 2 つ聞き取る (例: `#1E40AF`)。HEX 形式 (`#` + 6 桁の 16 進) でなければ「`#` で始まる 6 桁の英数字で教えてください」と再確認すること。

**Step c. サイトタイトルの提案**

`career/profile.md` の氏名と `career/work-history.md` の最新の役職から、自動でタイトル案を 2〜3 個作って提示します:

```
サイトタイトルは何にしますか? (このままでも OK)

  現在: <site_title>
  案 1: <name> — Portfolio
  案 2: <name> | <最新の役職>
  案 3: <name> の自己紹介
```

選択 or 自由入力を受け取って `site_title` に格納。スキップなら現状維持。

**Step d. キャッチコピーの提案**

最新の役職・業務・成果から、キャッチコピー案を 2〜3 個提案します:

```
キャッチコピー (一言の肩書き) を 1 行で。ピンとくる案があれば選んでください。

  現在: <tagline>
  案 1: <最新の役職>
  案 2: <キャリア年数> 年の <推定領域>
  案 3: <成果から抽出した強み> を専門にしています
```

選択 or 自由入力 or スキップ。スキップなら現状維持。

**Step e. セクション構成の確認**

```
ポートフォリオに表示するセクションと順番です。これでよいですか?

  現在:
    1. <sections[0]>
    2. <sections[1]>
    ...

  1) このままで OK
  2) 順番を入れ替える / セクションを追加・削除する
```

`2)` を選ばれた場合は、追加できる候補 (profile / about / skills / education / work-history / contact など) を提示し、ユーザーに新しい順序を番号付きリストで答えてもらいます。最終形を `sections` 配列として保持。

**Step f. config.md への反映**

ここまでで決まった値を `Edit` で `config.md` の該当ブロック直下に書き込みます:

| 値 | 編集するブロック |
|---|---|
| `site_title` | `## サイトタイトル` |
| `tagline` | `## キャッチコピー` |
| `theme_color` | `## テーマカラー` |
| `accent_color` | `## アクセントカラー` |
| `sections` | `## 表示するセクションと順番` (番号付きリストに展開) |

> **必ず守る**: 見出し行 (`## ...`) / HTML コメント (`<!-- ... -->`) / 空行は絶対に消さない。値の行のみを書き換えます。スキップされた項目はそもそも `Edit` しないこと。

#### 選択 3) - 「イメージなし、提案して」

`career/work-history.md` を Claude が読み、業務領域・最新の役職・キャリア年数から **方向性ごと提案** します。例:

```
お仕事の内容を見ました。たとえばこんな方向性はいかがですか?

  案 A 「落ち着きエンジニア」
     雰囲気:        落ち着き / プロフェッショナル
     色:            テーマ #1E40AF / アクセント #F59E0B
     サイトタイトル: <name> — Portfolio
     キャッチコピー: <最新の役職> · <キャリア年数> 年

  案 B 「ミニマル」
     雰囲気:        シンプル / ミニマル
     色:            テーマ #475569 / アクセント #84CC16
     サイトタイトル: <name>
     キャッチコピー: <得意領域>

  案 C 「ダークモダン」
     雰囲気:        ダーク / モダン
     色:            テーマ #0F172A / アクセント #38BDF8
     サイトタイトル: <name> · Works
     キャッチコピー: <最新の役職>

  案 D 自分で決め直す (= 2) の対話フローへ)
```

ユーザーが案を選んだら、その内容を 2) の **Step f.** と同じ手順で `config.md` に書き込みます。「もう少し明るく」「青系がいい」などの要望が出たら、その方向で再提案するか、Step a〜e の対話に切り替えます。`案 D` が選ばれたら 2) の Step a から開始します。

### B-1.6. 反映の確認

書き換えが完了したら、書き換え後の `config.md` の該当ブロックを `Read` し直して、想定どおりに保存されていることを確認します (見出しやコメントが壊れていないかも合わせて)。問題があれば再度 `Edit` で修正してから B-2 に進みます。

### B-2. 顔写真の処理

`config.md` の `## 顔写真のファイル名` ブロックの値 (相対パス) を確認:

- 存在し、サイズ < 500KB → そのまま `<img src="assets/photo.jpg">` で参照
- 存在し、サイズ >= 500KB → 警告 (「圧縮を推奨」) を出して同じく相対パス参照
- 存在しない / `## 顔写真のファイル名` ブロックが無い / 値が空 → 顔写真を出さず、警告メッセージを出力
- パス検証: `## 顔写真のファイル名` の値が `assets/` で始まる相対パスでない、もしくは `..` を含む場合は **顔写真を出さず警告**。許可形式: `assets/<filename>`

> base64 埋め込みはしない。`portfolio.html` と `assets/` をセットで配布すれば表示できる前提とする。
>
> **顔写真がある場合は、B-5 の完了報告に必ず次の 2 つを含めること** (詳細は §B-5 参照):
>   1. メール添付 / USB 配布のときは `assets/` フォルダごと一緒に運ぶ必要があること ── HTML 単体だと写真が消える
>   2. スマートフォンで撮影した画像は **EXIF (撮影場所・日時・機種など)** を含むことがあるので、気になる場合は事前に除去を勧めること

### B-3. HTML 生成 — 専用デザインスキルに委譲

このフェーズでは **`cc-portfoliokit:portfolio-design` スキルを `Skill` ツールで呼び出して** HTML 文字列を組み立てます。HTML 構造 / CSS / 配色 / 職業別ラベル / Markdown 変換 / XSS 対策 は **すべてスキル側に集約済み** なので、ここで詳細を再掲しません。

#### B-3-1. スキル呼び出し

`Skill` ツールを使って `cc-portfoliokit:portfolio-design` を起動します。スキルに渡す入力 (引数 or 文脈共有) は B-1 でパースした以下の値です:

| 項目 | 出どころ |
|---|---|
| `name` / `name_kana` / `name_en` | `career/profile.md` |
| `profession` | `career/profile.md` の `## 職業` |
| `career_years` | `career/profile.md` の `## キャリア総年数` (任意、新仕様では多くの場合空) |
| `short_bio` / `birthday` / `location` / `languages` | `career/profile.md` (任意項目はあれば渡す) |
| `entries[]` | `career/work-history.md` を `## 名称` で分割、`### サブ項目` から `{ name, type, period, role, tasks[], tools, achievements[], overall_achievements[], projects[] }` に整形した配列。本業エントリは `overall_achievements` と `projects[]` を持つ可能性あり。副業・活動では `projects[]` は空配列または未定義 |
| `site_title` / `tagline` / `theme_color` / `accent_color` / `language` | `config.md` (B-1.5 で書き換え済みなら最新値) |
| `photo_path` | `config.md` の `## 顔写真のファイル名`。B-2 で「存在しない / 空」と判定された場合は `null` を渡す |
| `contact` | `config.md` の `## 連絡先` の `###` サブ項目を `{ email, github, website, x, instagram, linkedin, facebook, youtube, tiktok, note }` 形式で。値の無いキーは省略 |
| `sections` | `config.md` の `## 表示するセクションと順番` を配列化 |
| `about_md` / `skills_md` / `education_md` | `config.md` の対応セクションの本文 (任意項目はあれば渡す) |
| `today` | 現在日 (`YYYY-MM-DD`) |

> **`entries[]` の `projects[]` 構造**: 各 PJ は `{ name, tools, achievements[] }` の形。`tools` は文字列 (任意)、`achievements[]` は箇条書き配列 (任意)。スキル側は本業エントリで `projects[].length > 0` のとき、PJ ごとに小見出しを付けて HTML レンダリングする。

> 各値はすでに HTML エスケープ前の生の文字列で渡します。エスケープはスキル側の責務です。

#### B-3-2. スキルから返ってきた HTML を受け取る

スキルは `portfolio.html` の完全な HTML 文字列を返します。それをそのまま B-4 の書き出しに渡すだけ。**ここで構造を改造したり追加のスタイルを差し込んだりしないこと**。デザイン変更が必要なら `skills/portfolio-design/SKILL.md` を編集します。

> **性別 (gender) フィールドは渡さない / スキルも出力しない**。古いテンプレートに残っていても無視。
> **エラー時の挙動**: スキルが何らかの理由で HTML を返せなかった場合は、ユーザーに「デザインスキルが利用できません」と伝えて中断します。`create` 側で HTML を自前で組み立てて代替しないこと。デザインの単一情報源を守るためです。

### B-4. 書き出しと検証

1. `Write` で `./portfolio.html` を作成
2. `Bash` で `wc -c portfolio.html` を実行し、ファイルサイズを確認
3. 健全性チェック (詳細は SKILL.md §9):
   - `<title>` が空でないか、`<h1>` が `name` を含むか、各 `<section>` が出力されているか
   - `<script>` タグや `on*=` 属性が紛れていないか
   - 外部リンク (`http://` / `https://`) の `<a>` に `target="_blank" rel="noopener noreferrer"` が両方付いているか ── `Bash` で `grep -E '<a [^>]*href="https?://' portfolio.html | grep -v 'rel="noopener'` を試し、ヒットが 0 件であることを確認
   - `mailto:` リンクには `target` / `rel` が **付いていない** こと
   - `--theme` / `--accent` の値が `#[0-9A-Fa-f]{3,6}` 形式に合致しているか ── `Bash` で `grep -E -- "--theme:\\s+#" portfolio.html` 等で確認
   - スキル側のフォールバック (HEX 不正 → デフォルト復帰、lang 不正 → ja 復帰) が発動した場合は、B-5 でユーザーに通知

### B-5. 完了報告

#### B-5-1. 「知っておくと事故が減るメモ」 — 状況に応じて追記

完了メッセージの末尾に、以下の **該当する項目だけ** を「📝 知っておくと安心」セクションとして付け足してください。すべてを毎回出す必要はありません。

| 条件 | 出力するメモ |
|---|---|
| 顔写真を埋め込んだ | **写真を一緒に送りたいとき**: `portfolio.html` だけを添付すると、受け取った人の画面で顔写真が表示されません。`assets/` フォルダごとセットで送ってください ── ZIP にまとめると確実です |
| 顔写真を埋め込んだ | **撮影場所が気になる方へ**: スマートフォンで撮った写真には、撮影場所や日時の情報 ── EXIF と呼ばれます ── がついていることがあります。気になる場合は、写真共有アプリの「位置情報を削除」機能や、無料の EXIF 除去ツールで取り除いてから差し替えるとより安全です |
| Contact セクションに mailto: が含まれる | **印刷 / PDF 化するとき**: 連絡先のメールアドレスは、印刷物に「クリックできない平文」としては展開されません。HTML 上では普通にクリックできるリンクのままなので、紙で配るときも安心です |
| `birthday` / `location` / `languages` が `profile.md` に書かれていた | **掲載される項目について**: `profile.md` に `## 生年月日` / `## 居住地` / `## 話せる言語` を書かれている場合、これらは Profile セクションにそのまま掲載されています。意図したものか念のためご確認ください |
| スキル側で HEX フォールバックが発動した | **テーマカラーについて**: `config.md` のカラー指定 ── `<元の値>` ── が正しい形式ではなかったため、デフォルト色に戻して生成しました。`#` + 6 桁の英数字 (例: `#4F46E5`) の形式で書き直してから再生成してください |
| スキル側で lang フォールバックが発動した | **表示言語について**: `## 表示言語` の値 ── `<元の値>` ── が `ja` / `en` のような言語コードではなかったため、`ja` に戻して生成しました |
| 顔写真の指定パスが規約外 (`assets/` で始まらない、または `..` を含む) | **顔写真について**: 指定されたパス ── `<元の値>` ── は読み込めない場所を指していたので、写真なしで生成しました。`assets/<ファイル名>` の形式で書き直してから再生成してください |

> これらは **非エンジニアを驚かせないため** のメモです。「えっ、知らなかった!」が起きやすい挙動だけを、その状況になったときだけ静かに伝える、というスタンスでお願いします。長文のセキュリティ説明にしないこと。
