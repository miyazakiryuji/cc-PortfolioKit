---

「とりあえずこれだけ覚えれば大丈夫」というコマンドの使い分けと、現在の作業ディレクトリの状況診断を兼ねた **道案内コマンド** です。プラグインを初めて触る人や、しばらく経って何をすればよいか忘れた人のために用意しました。困ったらこれを叩けば、次の一手だけは必ず指し示してくれます。

> **このコマンドの責任範囲**: `Read` と `Bash ls` で状態を診断するだけ。**何も書き換えません**。`init` や `create` を勝手に実行することもありません。

最初に下記の **短い導入** だけ表示してから Step 1 に進んでください (長い前置きは禁止)。

```
【cc-PortfolioKit へようこそ!】
いまの状況を見て、次に何をしたらいいか教えますね。
```

---

## Step 1: プラグインの正体 (3 行サマリー)

そのまま以下を出力します (Markdown としてそのまま整形)。

```
■ cc-PortfolioKit がやること
  - お名前 / 職歴を Markdown に書き込み
  - その内容から 1 ページの自己紹介サイト (portfolio.html) を自動生成

■ 覚えるコマンドは 2 つだけ
  /cc-portfoliokit:init   … 最初の 1 回。氏名・職歴を対話でヒアリングして保存
  /cc-portfoliokit:create … それ以降ずっと。HTML を作る or 編集する
```

## Step 2: 現状を診断

`Bash` (例: `ls -la`) で cwd の以下のパスの存在を確認します。

- `./config.md`
- `./career/profile.md`
- `./career/work-history.md`
- `./portfolio.html`

判定:

- `INPUTS_FULL` = 3 つの素材 Markdown **すべて** が揃っている
- `INPUTS_PARTIAL` = 1〜2 つの素材 Markdown が揃っている (= 中途半端)
- `INPUTS_EMPTY` = 素材 Markdown が **1 つも** ない
- `HAS_HTML` = `./portfolio.html` が存在する

## Step 3: 状態別の案内 (4 ブランチ)

### ブランチ A: `INPUTS_EMPTY` (まっさら)

```
■ いまの状況: まっさら ✨ (これから始めるところ)

次に打つコマンド:
  /cc-portfoliokit:init

🎙️ このコマンドが何をしてくれるか
  - 作業フォルダにファイル一式を生成
  - 氏名・キャリア年数・職歴を 1 つずつ質問していく
  - 答えた内容をその場で Markdown に保存

🕐 所要時間
  3〜10 分くらい (職歴の数によって前後します)
```

### ブランチ B: `INPUTS_PARTIAL` (素材が一部だけ)

存在するファイルと欠けているファイルを列挙して以下を出力。

```
■ いまの状況: 素材ファイルが一部だけあります。
  あるもの: <存在するパスを列挙>
  ないもの: <欠けているパスを列挙>

次に打つコマンド:
  /cc-portfoliokit:init

🎙️ ご安心を: 既存ファイルは触らず、足りないものだけ補ってくれます。
   (実行すると「足りないものだけ作る / 全部上書き / キャンセル」を選べます)
```

### ブランチ C: `INPUTS_FULL && !HAS_HTML` (素材は揃った、あとは HTML だけ)

```
■ いまの状況: 素材はある、あと HTML を作るだけ! 🚀

次に打つコマンド:
  /cc-portfoliokit:create

🎙️ このコマンドが何をしてくれるか
  - 入力 Markdown を読み込み、portfolio.html を生成
  - 何も聞かれずに完成

完成後は portfolio.html をダブルクリックでブラウザに表示できます。
```

### ブランチ D: `INPUTS_FULL && HAS_HTML` (ポートフォリオ完成済み)

```
■ いまの状況: ポートフォリオ完成済み! 🎉

次にできること (お好きにどうぞ):
  1) ブラウザで見る
     → portfolio.html をダブルクリック (macOS: open / Windows: start)
  2) 編集メニューを開く
     → /cc-portfoliokit:create
        (1 つ前と同じコマンドが、2 回目以降は編集モードに切り替わります)
  3) Markdown を自分で開いて編集
     → config.md / career/profile.md / career/work-history.md を
        メモ帳や VS Code で直接書き換えて、もう一度 /cc-portfoliokit:create
        詳しくは docs/手順書.md の「ステップ 5」を参照
```

## Step 4: 困ったときの逃げ先

最後に以下のドキュメント案内を出力します (常に表示)。

```
📚 もっと詳しく / つまずいたとき
  - docs/手順書.md                  … 使い方の本編 (一から優しく)
  - docs/トラブルシューティング.md   … エラーが出たときの逃げ場
  - docs/はじめてのClaude Code.md    … Claude Code 自体が初めての方向け
  - docs/デスクトップアプリで使う.md … 黒い画面 (CLI) が苦手な方向け

それでも詰まったら、Claude Code にそのまま「困っています」と伝えてください。
状況を一緒に整理しながら次の一手を考えます。
```

> ファイルが存在しない場合は、その項目を出さなくて OK (本リポジトリの `docs/` には今のところ上記 4 つが入っている想定)。

---

## このコマンドの制約

- **何も実行しない、何も書き換えない**: `Read` と `Bash ls` だけで完結する診断コマンド。`init` / `create` を代理実行しないこと。
- ユーザーから「じゃあそれをやってみる」と続けて言われた場合のみ、該当コマンドを **ユーザー自身が叩く** ことを案内する (代理実行ではなく、コマンド文字列を提示する)。
- 詳細な手順説明は手順書 (`docs/手順書.md`) に任せ、このコマンドは **「次の 1 手」だけを** 短く出すことに徹する。
- 並行セッションで他の Claude Code が同じディレクトリを編集している可能性がある。診断結果は **このコマンドが実行された時点のスナップショット** であることを念頭に。
