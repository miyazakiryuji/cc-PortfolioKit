---
description: ポートフォリオを作るためのファイルとフォルダを用意し、これからの流れを案内する
---

このコマンドは cc-PortfolioKit を **初めて使うとき** に叩くセットアップコマンドです。やることは 3 つだけ。

1. プロジェクト側にファイルとフォルダを用意する
2. 「アイコン画像を入れてね」「プロフィールを書いてね」と促す
3. これからの流れ ── hearing → create ── を案内する

**ヒアリングはしません / HTML も生成しません**。中身は別コマンドや手編集で埋めていきます。詳しい仕様は [`docs/specs/init-command.md`](../docs/specs/init-command.md) を参照。

> **入力 Markdown のフォーマットについて**: cc-PortfolioKit の入力ファイル (profile.md / work-history.md / config.md) は **YAML フロントマターを使わない、純粋な Markdown** です。各データは `## 見出し` の下に値を書く形で表現します。あとから人間が手で編集することを最優先にした設計。

最初に下の **短い導入** だけ表示してから Step 1 に進んでください。長い前置きは禁止。

```
【ポートフォリオの準備を始めます!】
ファイルとフォルダを用意して、これからの流れを案内しますね。
中身を埋めるのはこのあと、別のコマンドや手編集でやっていきます。
```

---

## Step 1: 衝突チェック

cwd に対して以下のパスが既に存在するか `Bash` (例: `ls -la`) で確認します。

- `./config.md`
- `./career/`
- `./career/profile.md`
- `./career/work-history.md`
- `./assets/`

### 何も存在しない場合

何も尋ねず Step 2 に進む。

### 1 件以上存在する場合

ユーザーに同意を取る。

```
すでに次のファイルやフォルダが用意されているみたいです:

  <存在するパスを列挙>

どうしましょうか?

  1) 足りないものだけ作る ── おすすめ。既存のファイルには触りません
  2) すべて作り直す ── 既存の中身は捨てて、まっさらなテンプレに入れ替えます
  3) いったんやめる
```

| 選択 | 挙動 |
|---|---|
| 1) | 既存パスはスキップ、新規パスだけ作成して Step 2 へ |
| 2) | 既存も含めて全部上書き。**ただし念のためもう 1 回確認**: 「本当にいいですか? これまで書いた内容は消えます」を Yes/No で聞いてから実行 |
| 3) | 「では、また呼んでください」と一言伝えて終了 |

「やめる」「キャンセル」「戻る」などの言葉も `3)` 相当として扱う。

---

## Step 2: ベーステンプレートの展開

プラグイン側 `templates/` から、プロジェクト側の対応パスへコピーします。

| プラグイン側 | プロジェクト側 |
|---|---|
| `templates/config.md` | `./config.md` |
| `templates/profile.md` | `./career/profile.md` |
| `templates/work-history.md` | `./career/work-history.md` |
| `templates/assets-README.md` | `./assets/README.md` |

### 2.1 取得元の解決

`CLAUDE_PLUGIN_ROOT` が解決できる場合は `$CLAUDE_PLUGIN_ROOT/templates/` を起点に `Read` する。解決できない場合は、プラグインがインストールされている既知のディレクトリから取得する。**プラグイン側のファイルは絶対に書き換えない**。コピー先は cwd 配下に限定。

### 2.2 ディレクトリの準備

書き出し前に `Bash mkdir -p ./career ./assets` を 1 回実行する。`Write` ツールが親ディレクトリを自動作成しない場合のセーフティ。

### 2.3 Step 1 で `1)` (足りないものだけ) が選ばれた場合

既存パスはスキップ、新規パスだけコピーする。どのファイルを「新しく作った / 既存だった」かをメモリに記録 (Step 3 の完了報告で使う)。

### 2.4 Step 1 で `2)` (全上書き) が選ばれた場合

全パスを上書きで書き出す。全ファイルが「上書きした」として記録される。

---

## Step 3: 完了報告と流れ案内

Step 2 が終わったら、ユーザーに **作ったもの** と **これからの流れ** を温かいトーンで伝えます。

### 3.1 完了報告 (新規セットアップの場合)

Step 1 で「何も存在しない」または `2)` 全上書きが選ばれた場合。

```
✅ ファイルとフォルダ、ひととおり用意できました。

  ./config.md             — サイト設定 (タイトル / 配色 / 連絡先 / 自己紹介)
  ./career/profile.md     — プロフィール (氏名 / 職業 / 趣味など)
  ./career/work-history.md — 経歴 (本業 / 副業 / 活動)
  ./assets/               — アイコン画像を入れるおうち
  ./assets/README.md      — assets フォルダの使い方ガイド

このあとの流れはこんな感じです:

  ステップ 1: ./assets/ にアイコン画像を 1 枚入れる
     顔写真でも、似顔絵でも、お気に入りの 1 枚でも大丈夫です。
     ファイル名は何でも OK。あとで自動で拾います。

  ステップ 2: ./config.md と ./career/profile.md を開いて、プロフィールを書き込む
     お名前、職業、自己紹介、連絡先、趣味など。
     エディタやメモ帳で開いて、ファイル先頭のコメントに沿って書いていけば OK。

  ステップ 3: /cc-portfoliokit:hearing
     経歴 ── 本業・副業・活動 ── を対話で聞いていきます。
     1 件ずつ、書きたい分だけ。

  ステップ 4: /cc-portfoliokit:create
     ここまでの素材から、ポートフォリオの HTML を作ります。

迷ったら /cc-portfoliokit:guide が次の一手を教えてくれますよ。
```

`2)` 全上書きが選ばれた場合のみ、冒頭を次のように変える:

```
✅ まっさらなテンプレで入れ替えました。これまでの内容は消えています。
```

### 3.2 完了報告 (一部のみ補完した場合)

Step 1 で `1)` が選ばれた場合。新しく作ったファイルと既存だったファイルを区別して列挙する。

```
✅ 足りなかったファイルを補いました。

  ./config.md             (新しく作りました)
  ./career/profile.md     (すでにありました — 触っていません)
  ./career/work-history.md (新しく作りました)
  ./assets/               (すでにありました — 触っていません)
  ./assets/README.md      (新しく作りました)

そろそろ次へ進めそうです。
```

その後、§3.1 と同じ「このあとの流れ」案内を続ける。

### 3.3 すべて既存だった場合

`1)` が選ばれて、何もコピーするものが無かった場合。

```
すでに必要なファイルは全部そろっていました。
/cc-portfoliokit:guide で次の一手を確認できます。
```

これだけ表示して終了。流れ案内は出さない (すでに進んでいる人向けの想定なので、無駄な情報を出さない)。

## 注意 — このコマンドの絶対ルール

- **ヒアリングしない**: 氏名・職業・経歴などの中身は一切聞かない。中身は `hearing` と手編集に任せる。
- **HTML を生成しない**: `portfolio.html` の作成は `create` の責務。
- **既存ファイルを勝手に上書きしない**: Step 1 で同意を取らない限り、既存内容は守る。`2)` 選択時は念のため再確認。
- **プラグイン側のファイルは書き換えない**: `templates/` を `Read` するだけ。`Edit` / `Write` の対象は cwd 配下のみ。
- **入力 Markdown は YAML フロントマターを使わない `## 見出し` 構造**: テンプレ展開時に内容を改変しない。コメントや空行は維持。
- **対話文は温かいトーン**: CLAUDE.md「文体のトーン」と memory `feedback_warm-tone.md` に従う。事務的命令形を避ける。`( )` で補足を書くスタイル ── たとえば `(任意)` `(例: 〇〇)` ── は質問文・選択肢ラベルから一切排除する。
- **「フォルダ」を使う**: ユーザー向け対話文に「ディレクトリ」を出さない。仕様書では「`./assets/`」のようにパス記法で書いても、対話文は「`./assets/` フォルダ」と言う。
- **並行セッション対策**: ファイルの存在確認は `Bash ls` か `Read` の試行で。会話前半の記憶のままで Edit / Write しない。
- **ユーザーが「やめる」「キャンセル」と言ったらすぐ中断**: そこまでの作業は保持。何が作られたかを短く伝えて終了。
- **詳しくは [`docs/specs/init-command.md`](../docs/specs/init-command.md) を参照**。実装時はこの仕様書を **必ず読んでから** 作業を始めること。
