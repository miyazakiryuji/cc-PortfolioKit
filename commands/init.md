description: フォルダ・ファイルを作成し、氏名とキャリア (総年数・本業/副業/活動の各エントリ) を対話形式でヒアリングして Markdown に書き込む
---

このコマンドは cc-PortfolioKit を **初めて使うとき** に実行するセットアップコマンドです。フォルダとテンプレートを作りつつ、**対話形式で名前とキャリアをヒアリング** し、その場で `career/profile.md` と `career/work-history.md` に書き込みます。

> **入力 Markdown のフォーマットについて**: cc-PortfolioKit の入力ファイル (profile.md / work-history.md / config.md) は **YAML フロントマターを使わない、純粋な Markdown** です。各データは `## 見出し` の下に値を書く形で表現します。これは「あとから人間が手で編集する」ことを最優先にした設計です。詳しくは `templates/*.md` 内のコメントを参照。

最初に以下の **短い導入** だけ表示してから Step 1 に進んでください (長文の前置きは禁止)。

```
【ポートフォリオの初期セットアップを始めます!】
これから順番に「お名前」「本業」「副業」「活動」を質問していきますね。
気軽に答えてもらえれば、こちらで Markdown に整理して書き込みます。
副業や活動は無ければスキップで OK です。
```

---

## Step 1: 衝突チェック

cwd に対して以下のパスが既に存在するか `Bash` (例: `ls -la`) で確認します。

- `./config.md`
- `./career/`
- `./career/profile.md`
- `./career/work-history.md`
- `./assets/`

**何も存在しない場合**: 何も聞かずに Step 2 に進む。

**1 件以上存在する場合**: ユーザーに以下を尋ねる。

```
既に以下のファイル/フォルダが存在しています:
  - <存在するもののリスト>

どうしますか?
  a) 既存ファイルは触らず、足りないものだけ作成する (推奨)
  b) すべて上書きして最初からやり直す (注意: 既存内容は消えます)
  c) キャンセル
```

- a) → 既存はスキップ。新規部分だけ作成。
- b) → 全部上書き。
- c) → 「キャンセルしました」と表示して終了。

## Step 2: ベーステンプレートの展開

プラグインのテンプレートディレクトリから以下を `Read` し、プロジェクト側に `Write` します。Step 1 で a) を選ばれた場合は **既存パスはスキップ** してください。

| プラグイン側 | プロジェクト側 |
|---|---|
| `templates/config.md` | `./config.md` |
| `templates/profile.md` | `./career/profile.md` |
| `templates/work-history.md` | `./career/work-history.md` |
| `templates/assets-README.md` | `./assets/README.md` |

> `CLAUDE_PLUGIN_ROOT` が解決できない場合は、プラグインがインストールされているディレクトリの `templates/` を直接読む。プラグイン側ファイルは絶対に書き換えないこと。

`career/work-history.md` だけはこの後の Step 4 で **全面的に上書き** するので、Step 1 で a) を選ばれていてもユーザーに同意を取って必ず置き換える対象に含めてください。同意が得られなかった場合は、Step 4 をスキップして「職歴ヒアリングをスキップしました」と報告します。

## Step 3: 氏名・職業ヒアリング

**1 つずつ短く** 質問してください。一度にまとめて聞かないこと。回答が空欄や「スキップ」だった場合は、テンプレートの該当ブロックを **そのまま残します** (削除も上書きもしない)。

1. 「お名前 (フルネーム) を教えてください」 → `name`
2. 「ふりがな (ひらがな) を教えてください。スキップでも OK です」 → `name_kana`
3. 「英語表記 (例: Taro Yamada) があれば教えてください。スキップでも OK です」 → `name_en`
4. 「あなたの主な職業はどれが一番近いですか? **1 つだけ** 選んでください」 → `profession`

   選択肢を提示する:

   ```
     1) エンジニア / IT
     2) デザイナー / クリエイティブ (イラスト・写真・映像・音楽 等)
     3) 営業 / セールス
     4) マーケティング / PR / 広報 (ライター・編集 含む)
     5) コンサルタント / 専門アドバイザー
     6) 研究職 / アカデミア
     7) 公務員 / 行政
     8) 医療 / ヘルスケア (医師・看護師・薬剤師 等)
     9) 教育 / 講師
    10) 小売 / 接客 / サービス業 (飲食・宿泊 等)
    11) 金融 / 経理 / 法務
    12) 製造業 / 現場技術
    13) 管理職 / 経営
    14) その他 (自由記入)
   ```

   選ばれた選択肢のラベル文字列 (例: `エンジニア / IT`) を **そのまま** `$PROFESSION` として保持し、`career/profile.md` の `## 職業` ブロック直下に `Edit` で書き込む。`14) その他` の場合は、ユーザーが自由記入した文字列を `$PROFESSION` に格納する。複数職種にまたがる方には「**いま一番メインの 1 つ**」を選んでもらえば OK と添える。

### 書き換え方 (重要)

`career/profile.md` は YAML ではなく、`## 見出し` の下に値を置く構造です。各回答について、次のように `Edit` で **見出し直下の 1 行を値の置換** で書き換えます。コメント (`<!-- ... -->`) や他のブロックは保持してください。

例 — 「## 氏名」ブロックの場合、テンプレートの初期状態:

```markdown
## 氏名

山田 太郎

<!-- フルネームで書いてください。... -->
```

ユーザーの回答が「田中 花子」だったとき、`Edit` で `山田 太郎` の 1 行を `田中 花子` に置き換えます (コメント `<!--` 行は触らない)。

> 「## 〇〇」見出しと値の間の空行は **必ず保持** してください。空行が消えるとパースに影響します。

## Step 4: キャリアヒアリング

> **`$PROFESSION` に応じた質問文の調整**: Step 4-3 / 4-4 / 4-5 のヒアリングのうち、**Q3 役職 / Q4 業務内容 / Q5 使用技術 / Q6 成果** の 4 つは、Step 3 で選ばれた `$PROFESSION` に応じて質問文と例示を切り替えてください。差し替え内容は本ファイル末尾の [職業別 質問文ガイド](#職業別-質問文ガイド-profession-対応表) を参照。Markdown 上の見出し名 (`### 使用技術` など) は **変更しないこと** ── HTML 生成側でラベルを職業対応に差し替えるので、ストレージ用の見出しは固定で OK。

### Step 4-1. 総キャリア年数

```
これまでのキャリアは合計で何年くらいですか? (例: 8 年)
```

回答を受け取り、`career/profile.md` の `## キャリア総年数` ブロック直下の値を `Edit` で書き換えます。回答が「分からない / スキップ」なら初期値 (`5 年`) のままにします。

> 回答が「8 年」のように単位込みでも、「8」のように数字だけでも、どちらもそのまま書き込んで OK です (HTML 生成側で柔軟に扱います)。

### Step 4-2. 並び順の確認

```
職歴は新しい順 (現職から) と古い順 (新卒から)、どちらで聞いていきましょうか?
  1) 新しい順 (おすすめ)
  2) 古い順
```

選ばれた順序を `$ORDER` として保持。

### Step 4-3. 本業のヒアリング (ループ)

`$MAIN_ENTRIES` を空のリストとして用意し、以下を `i = 1, 2, 3, ...` の順で繰り返します。

```
【本業 $i 社目】について教えてください。
```

続けて以下を **1 つずつ** 質問:

1. 「会社名を教えてください」 → `name`
2. 「在籍期間を教えてください (例: 3 年 / 2020-04 〜 2023-03 / 現在も在籍中 など、書きやすい形で OK)」 → `period`
3. 「役職や肩書きはありましたか? (例: ソフトウェアエンジニア / マネージャー)。なければスキップで OK」 → `role`
4. 「具体的にどんな業務をされましたか? 主なものを **3〜5 個** 箇条書きで教えてください。1 つずつ言ってもらってもいいし、まとめて言ってもらってもいいです」 → `tasks` (配列)
5. 「使用していた技術スタックがあれば教えてください (例: TypeScript, AWS)。スキップでも OK」 → `tech` (任意)
6. 「成果や数字で言える実績があれば教えてください (例: レスポンス時間を 50% 改善)。スキップでも OK」 → `achievements` (任意)

これらを 1 エントリ (種別 `本業`) として `$MAIN_ENTRIES` に追加。

そのあと:

```
本業をもう 1 社追加しますか? (Yes / No)
```

Yes → ループ続行。No → ループ終了して Step 4-4 へ。

### Step 4-4. 副業のヒアリング (任意・ループ)

まず副業の有無を尋ねます。

```
副業 (業務委託 / フリーランス / 個人開発 / 顧問など、本業以外でお金が動いた仕事) はありますか?
  1) ある — ヒアリングする
  2) なし — スキップする
```

「なし」を選ばれたら `$SIDE_ENTRIES` は空のままで Step 4-5 へ。

「ある」なら `$SIDE_ENTRIES` を空のリストとして用意し、以下を `i = 1, 2, 3, ...` の順で繰り返します。

```
【副業 $i 件目】について教えてください。
```

続けて以下を **1 つずつ** 質問:

1. 「案件名 / クライアント名を教えてください (例: 〇〇社、個人開発の △△)」 → `name`
2. 「期間を教えてください (例: 2 年 / 2022-04 〜 2024-03 / 現在も継続中)」 → `period`
3. 「立場や役職は? (例: 技術アドバイザー / フリーランスエンジニア)。なければスキップで OK」 → `role`
4. 「具体的にどんな業務をされましたか? 主なものを **1〜3 個** で OK」 → `tasks` (配列)
5. 「使用していた技術スタックがあれば教えてください (例: Node.js, AWS)。スキップでも OK」 → `tech` (任意)
6. 「成果や数字で言える実績があれば教えてください。スキップでも OK」 → `achievements` (任意)

これらを 1 エントリ (種別 `副業`) として `$SIDE_ENTRIES` に追加。

そのあと:

```
副業をもう 1 件追加しますか? (Yes / No)
```

Yes → ループ続行。No → ループ終了して Step 4-5 へ。

### Step 4-5. 活動のヒアリング (任意・ループ)

まず活動の有無を尋ねます。

```
イベント運営・コミュニティ活動 (主催 / 登壇 / OSS / 執筆など、お金が直接動かないものも含む) はありますか?
  1) ある — ヒアリングする
  2) なし — スキップする
```

「なし」を選ばれたら `$ACTIVITY_ENTRIES` は空のままで Step 4-6 へ。

「ある」なら `$ACTIVITY_ENTRIES` を空のリストとして用意し、以下を `i = 1, 2, 3, ...` の順で繰り返します。

```
【活動 $i 件目】について教えてください。
```

続けて以下を **1 つずつ** 質問:

1. 「活動名 / イベント名を教えてください (例: 〇〇 Meetup、△△ OSS プロジェクト)」 → `name`
2. 「期間を教えてください」 → `period`
3. 「自分の役割は? (例: 主催 / 運営メンバー / 登壇者 / コミッター)。なければスキップで OK」 → `role`
4. 「具体的にどんなことをされましたか? 主なものを **1〜3 個** で OK」 → `tasks` (配列)
5. 「関連するスキルや技術があれば教えてください (例: イベント運営、TypeScript)。スキップでも OK」 → `tech` (任意)
6. 「成果や規模感があれば教えてください (例: 参加者 500 名、Star 100)。スキップでも OK」 → `achievements` (任意)

これらを 1 エントリ (種別 `活動`) として `$ACTIVITY_ENTRIES` に追加。

そのあと:

```
活動をもう 1 件追加しますか? (Yes / No)
```

Yes → ループ続行。No → ループ終了して Step 4-6 へ。

### Step 4-6. work-history.md への書き出し

3 つのリスト `$MAIN_ENTRIES` / `$SIDE_ENTRIES` / `$ACTIVITY_ENTRIES` を **本業 → 副業 → 活動 の順** で並べて、`career/work-history.md` の **本文を全面置換** で書き出します。各リスト内は `$ORDER` (Step 4-2 で決めた順序) で並べます。

**書式は以下に統一してください** (`## 名称` + `### サブ項目` の 2 階層構造)。

```markdown
# 職歴・副業・活動 / Career & Activities

<!--
  /cc-portfoliokit:init で生成された経歴です。
  追記・修正はこのファイルを直接編集するか、/cc-portfoliokit:create の編集メニューから行えます。

  構造のルール:
    ## 名称       ← 1 件 = 1 つの ## ブロック (会社名・案件名・イベント名など)
      ### 種別    ← 本業 / 副業 / 活動 のいずれか (必須)
      ### 期間
      ### 役職
      ### やったこと
      ### 使用技術
      ### 成果

  新しいエントリを追加するときは「## 名称」のブロックを丸ごとコピペして書き換えてください。
-->


## <name>

### 種別

<type>   ← 本業 / 副業 / 活動 のいずれか (必須)

### 期間

<period>

### 役職

<role>

### やったこと

- <task 1>
- <task 2>
- <task 3>

### 使用技術

<tech>

### 成果

- <achievement 1>
- <achievement 2>


## <次の name>
...
```

> **入力なしフィールドは「### 見出し」ブロックごと省略する** こと。「役職: (なし)」のような空欄を残さない。
> 例: `role` が空 → `### 役職` の見出し行と値の行を **両方とも書き出さない**。
> 例: `achievements` が空 → `### 成果` ブロックを丸ごと書き出さない。

> 1 社のブロックと次の 1 社のブロックの間は **空行 2 つ** で区切ると、人間が手編集するときに境目が分かりやすくなります。

## Step 5: 完了報告

ユーザーに以下のフォーマットで完了を報告します。

```
✅ 初期セットアップが完了しました!

作成したファイル:
  - config.md
  - career/profile.md      ← 氏名・ふりがな・キャリア総年数を書き込み済み
  - career/work-history.md ← ヒアリングした $N 件の職歴を書き込み済み
  - assets/README.md       ← 顔写真の置き方ガイド

書き込んだ経歴 (合計 $TOTAL 件):
  本業 $M 件:
    1. <名称> (<期間>)
    ...
  副業 $S 件 (該当なしならこのブロックごと省略):
    1. <名称> (<期間>)
    ...
  活動 $A 件 (該当なしならこのブロックごと省略):
    1. <名称> (<期間>)
    ...

次のステップ:
  1. 顔写真を assets/ に置き、config.md の「## 顔写真のファイル名」を書き換える
  2. config.md の About / スキル / 連絡先 / テーマカラー を編集
  3. /cc-portfoliokit:create を実行して portfolio.html を生成

📝 手編集について:
  config.md / career/profile.md / career/work-history.md は YAML を使わず、
  「## 見出し」の下に値を書くだけの素朴なフォーマットです。
  各ファイルの先頭コメントに編集ルールが書いてあるので、お好みでどうぞ。
```
