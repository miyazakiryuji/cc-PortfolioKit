---
description: 入力 Markdown から portfolio.html を生成する。既存生成物がある場合は編集メニューを表示
---

このコマンドは、`/cc-portfoliokit:init` で作成・記入された Markdown 入力から **1 ページ HTML ポートフォリオ** を生成します。既に `portfolio.html` がある場合は編集メニューを表示します。

> 初回セットアップ (フォルダ作成 + ヒアリング) は `/cc-portfoliokit:init` の責務です。このコマンドは **HTML 生成と既存ポートフォリオの編集** に専念します。

最初に以下の **短い導入** を表示してから Step 1 に進んでください。

```
【ポートフォリオを生成します!】
現在の状態を確認しています…
```

---

## Step 1: 状態判定

cwd に対して以下 4 つの存在を `Bash` (例: `ls -la`) または `Read` 試行で確認し、状態フラグを取得します。

| フラグ | 対象 | 内容 |
|---|---|---|
| `HAS_CONFIG` | `./config.md` | サイト設定の有無 |
| `HAS_PROFILE` | `./career/profile.md` | プロフィールの有無 |
| `HAS_WORK` | `./career/work-history.md` | 職歴の有無 |
| `HAS_HTML` | `./portfolio.html` | 既存出力の有無 |

`HAS_CONFIG && HAS_PROFILE && HAS_WORK` を `INPUTS_READY` と呼びます。

ブランチ分岐:

| 状況 | ブランチ |
|---|---|
| `INPUTS_READY` 不成立 (= 入力が 1 つでも欠ける) | **A. init 誘導** |
| `INPUTS_READY && !HAS_HTML` | **B. 初回 HTML 生成** |
| `INPUTS_READY && HAS_HTML` | **C. 編集メニュー** |

---

## ブランチ A: init 誘導

入力 Markdown が揃っていない状態。このコマンドではテンプレートを作らず、init コマンドの実行を案内するだけにとどめます。

### A-1. 案内表示

```
❌ ポートフォリオの素材が見つかりません。

足りないファイル:
  - <欠けているパスを列挙>

このコマンドは HTML 生成専用です。最初に下のコマンドで対話セットアップ
(フォルダ作成 + 氏名・キャリアのヒアリング) を実行してください:

  /cc-portfoliokit:init

セットアップ後にもう一度 /cc-portfoliokit:create を実行すると HTML が生成されます。
```

→ それ以上は何もせず終了。**勝手にテンプレートを作らないこと**。

---

## ブランチ B: 初回 HTML 生成

入力 Markdown は揃っているが `portfolio.html` がまだ無い状態です。何も聞かずに生成に入ります。

### B-1. Markdown のパース

3 つの Markdown ファイルを `Read` し、以下を取り出します。

**config.md から**
- フロントマター (YAML): `site_title`, `tagline`, `theme_color`, `accent_color`, `language`, `photo`, `contact.*`, `sections`
- 本文の `## About` / `## スキル` / `## 学歴` などのセクション

**career/profile.md から**
- フロントマター: `name`, `name_kana`, `name_en`, `career_years`, `birthday`, `location`, `languages`
- 本文の `## 自己紹介 (短め)` セクション (任意)

**career/work-history.md から**
- 本文を `## <会社名>` 単位で分割
- 各エントリの `期間 / 役職 / 業務内容 / 使用技術 / 実績` を抽出
- 並び順は Markdown 上の順 (init 時に決めた順番)

> パースに失敗したフィールドがあれば、ユーザーに **具体的なファイル名と原因** を伝えて中断してください。空値で勝手に埋めないこと。

### B-2. 顔写真の処理

`config.md` の `photo:` を確認:

- 存在し、サイズ < 500KB → そのまま `<img src="assets/photo.jpg">` で参照
- 存在し、サイズ >= 500KB → 警告 (「圧縮を推奨」) を出して同じく相対パス参照
- 存在しない or `photo:` が空 → 顔写真を出さず、警告メッセージを出力

> base64 埋め込みはしない。`portfolio.html` と `assets/` をセットで配布すれば表示できる前提とする。

### B-3. HTML 生成

以下の構造で 1 ファイルの HTML を組み立てます。CSS は `<style>` でインライン、JavaScript は使いません。

```html
<!doctype html>
<html lang="{{language}}">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width,initial-scale=1">
  <title>{{site_title}}</title>
  <style> /* theme_color / accent_color を CSS 変数化 */ </style>
</head>
<body>
  <header>
    <img src="{{photo}}" alt="{{name}}" class="hero-photo">
    <h1>{{name}}</h1>
    <p class="tagline">{{tagline}}</p>
  </header>

  <main>
    <!-- config.md の sections の順序で出し分け -->
    <section id="profile">
      <h2>Profile</h2>
      <dl>
        <dt>氏名</dt><dd>{{name}} ({{name_kana}})</dd>
        <dt>キャリア</dt><dd>{{career_years}} 年</dd>
        <!-- birthday / location / languages があれば出す。空文字なら省く -->
      </dl>
    </section>

    <section id="about">
      <h2>About</h2>
      <!-- config.md の ## About を Markdown → HTML 変換 -->
    </section>

    <section id="work-history">
      <h2>Work History</h2>
      <ol class="timeline"><!-- 各エントリ --></ol>
    </section>

    <section id="contact">
      <h2>Contact</h2>
      <ul>
        <li>Email: <a href="mailto:{{email}}">{{email}}</a></li>
        <!-- github / x / linkedin / website があれば出す。空文字なら省く -->
      </ul>
    </section>
  </main>

  <footer>
    <small>Generated by cc-PortfolioKit · {{今日の日付 YYYY-MM-DD}}</small>
  </footer>
</body>
</html>
```

> **性別 (gender) フィールドは HTML に一切出力しないこと**。たとえ古いテンプレートで残っていても無視する。

**CSS 要件**:
- レスポンシブ (スマホで縦並び、PC で横並びになる箇所がある)
- `theme_color` を主色、`accent_color` をアクセントに使う
- フォント: `"Hiragino Sans", "Yu Gothic", system-ui, sans-serif`
- 顔写真は `border-radius: 50%; width: 160px;`
- タイムラインは左にラインを引いて各エントリにドットを置く
- リンクは `accent_color`、hover で下線
- ダークモード対応 (`@media (prefers-color-scheme: dark)`)
- 印刷時に背景色が消えても読める (`@media print`)

**Markdown → HTML 変換のサポート範囲** (外部ライブラリ不使用):
- `## ` → `<h2>`、`### ` → `<h3>`
- `- ` → `<ul><li>`
- `**text**` → `<strong>`、`*text*` / `_text_` → `<em>`
- `` `code` `` → `<code>`
- `[text](url)` → `<a href="url">`
- 連続段落は `<p>` で囲む
- HTML コメント (`<!-- ... -->`) は出力に含めない

**XSS 対策 (必須)**:
- ユーザー入力の `<`, `>`, `&`, `"`, `'` を必ずエスケープしてから HTML に流し込む
- `script` / `style` タグ、`on*` 属性は出力 HTML に含めない

### B-4. 書き出しと検証

1. `Write` で `./portfolio.html` を作成
2. `Bash` で `wc -c portfolio.html` を実行し、ファイルサイズを確認
3. 健全性チェック: `<title>` が空でないか、`<h1>` が `name` を含むか、各 `<section>` が出力されているか

### B-5. 完了報告

```
✅ portfolio.html を生成しました!

  パス: ./portfolio.html
  サイズ: <N KB>
  含めたセクション: profile, about, work-history, contact
  顔写真: <埋め込んだ / 警告内容>

確認方法:
  open portfolio.html        # macOS
  start portfolio.html       # Windows

内容を編集したい場合は、もう一度 /cc-portfoliokit:create を実行してください。
編集メニューが出てきます!
```

## ブランチ C: 編集メニュー

入力 Markdown も `portfolio.html` も揃っている状態。ユーザーは「内容を変えたい」「再生成だけしたい」のいずれかを期待しています。

### C-1. メニュー表示

```
ポートフォリオは既に生成済みです (portfolio.html)。

何をしますか?
  1) Markdown を編集済みなので、もう一度 HTML を生成する (再生成)
  2) いまここで内容を変更する (対話で項目を指定して編集 → 再生成)
  3) なにもしない (キャンセル)
```

ユーザーの回答に応じて C-2 / C-3 / 終了 のいずれかに進みます。

### C-2. 単純再生成

ブランチ B の Step B-1 以降をそのまま実行します。完了報告は B-5 と同様ですが、冒頭を `✅ portfolio.html を更新しました!` に変えてください。可能であれば旧 `portfolio.html` の `<footer>` から前回生成日付を抽出し、「前回 YYYY-MM-DD → 今回 YYYY-MM-DD」と併記します。

### C-3. 対話で項目編集

以下のメニューを表示します。

```
どの項目を編集しますか? (複数選んでも OK、番号をカンマ区切りで)

  1) サイトタイトル / キャッチコピー
  2) テーマカラー
  3) 自己紹介 (About)
  4) 氏名 / ふりがな / キャリア総年数
  5) 連絡先 (email / github / その他)
  6) 顔写真のファイル名
  7) 職歴を追加する
  8) 既存の職歴を編集する
  9) 戻る
```

各項目で、ユーザーから新しい値を聞き取り、対応する Markdown ファイルを `Edit` で **値の置換のみ** で書き換えます (他のフィールドや本文構造は保持)。書き換え対象の対応表:

| メニュー | 編集対象 |
|---|---|
| 1) | `config.md` フロントマター `site_title` / `tagline` |
| 2) | `config.md` フロントマター `theme_color` / `accent_color` |
| 3) | `config.md` 本文 `## About` セクション |
| 4) | `career/profile.md` フロントマター `name` / `name_kana` / `career_years` |
| 5) | `config.md` フロントマター `contact.*` |
| 6) | `config.md` フロントマター `photo` |
| 7) | `career/work-history.md` の **先頭** に新しい `## <会社名>` ブロックを追加 (init と同じ形式で 会社名 / 期間 / 役職 / 業務内容 / 使用技術 / 実績 をヒアリング) |
| 8) | `career/work-history.md` の既存エントリを 1 つ選んで該当部分を `Edit` |

編集が終わったら必ずユーザーに「他に変更したい項目はありますか?」と尋ね、無ければ B-1 以降を実行して再生成します。

完了報告は C-2 と同様。加えて「今回編集した項目」のリストも併記してください。

> **性別 (gender) の編集項目は提供しない**。この設計では性別は扱わない。

---

## 共通の制約

- **JavaScript は使わない**
- **外部 CSS / フォント CDN は使わない** (オフライン表示可)
- **portfolio.html 以外のファイルは、ユーザーが明示的に指示した編集 (ブランチ C-3) のときだけ書き換える**
- **入力に書かれていない情報を勝手に作らない** (氏名・経歴を捏造しない)
- **テンプレートを勝手に作らない** — 素材ファイルが無い場合は必ず init コマンドへ誘導する
- 空欄のフィールドは、その項目ごと HTML から省く
- ユーザー入力は必ず HTML エスケープしてから出力
- 性別 (gender) は HTML 出力にも編集メニューにも含めない
