description: 入力 Markdown から portfolio.html を生成する。既存生成物がある場合は編集メニューを表示
---

このコマンドは、`/cc-portfoliokit:init` で作成・記入された Markdown 入力から **1 ページ HTML ポートフォリオ** を生成します。既に `portfolio.html` がある場合は編集メニューを表示します。

> 初回セットアップ (フォルダ作成 + ヒアリング) は `/cc-portfoliokit:init` の責務です。このコマンドは **HTML 生成と既存ポートフォリオの編集** に専念します。

最初に以下の **短い導入** を表示してから Step 1 に進んでください。

```
【ポートフォリオを生成します!】
現在の状態を確認しています…
```

---

## Step 1: 状態判定

cwd に対して以下 4 つの存在を `Bash` (例: `ls -la`) または `Read` 試行で確認し、状態フラグを取得します。

| フラグ | 対象 | 内容 |
|---|---|---|
| `HAS_CONFIG` | `./config.md` | サイト設定の有無 |
| `HAS_PROFILE` | `./career/profile.md` | プロフィールの有無 |
| `HAS_WORK` | `./career/work-history.md` | 職歴の有無 |
| `HAS_HTML` | `./portfolio.html` | 既存出力の有無 |

`HAS_CONFIG && HAS_PROFILE && HAS_WORK` を `INPUTS_READY` と呼びます。

ブランチ分岐:

| 状況 | ブランチ |
|---|---|
| `INPUTS_READY` 不成立 (= 入力が 1 つでも欠ける) | **A. init 誘導** |
| `INPUTS_READY && !HAS_HTML` | **B. 初回 HTML 生成** |
| `INPUTS_READY && HAS_HTML` | **C. 編集メニュー** |

## ブランチ A: init 誘導

入力 Markdown が揃っていない状態。このコマンドではテンプレートを作らず、init コマンドの実行を案内するだけにとどめます。

### A-1. 案内表示

```
❌ ポートフォリオの素材が見つかりません。

足りないファイル:
  - <欠けているパスを列挙>

このコマンドは HTML 生成専用です。最初に下のコマンドで対話セットアップ
(フォルダ作成 + 氏名・キャリアのヒアリング) を実行してください:

  /cc-portfoliokit:init

セットアップ後にもう一度 /cc-portfoliokit:create を実行すると HTML が生成されます。
```

→ それ以上は何もせず終了。**勝手にテンプレートを作らないこと**。

## ブランチ B: 初回 HTML 生成

入力 Markdown は揃っているが `portfolio.html` がまだ無い状態です。**生成前にテーマ方向性を一度だけ確認** したうえで HTML を作ります (`init` は中身を聞いただけで、見た目はテンプレ初期値のままなので、ここで一度ユーザーに方向性を選んでもらう)。

### B-1. Markdown のパース

3 つの Markdown ファイルを `Read` し、以下を取り出します。

> **重要 — フォーマットについて**: cc-PortfolioKit の入力ファイルは **YAML フロントマターを使いません**。すべてのデータは `## 見出し` ブロック構造で表現されています。各 `## 〇〇` 見出しの **直下の値 (空行を挟んだあとの本文)** が、その項目の値です。HTML コメント (`<!-- ... -->`) はパース時に必ず無視してください。

#### 共通パースルール

- ファイル全体を `## ` 行で分割し、各ブロックを `{ "label": "<見出しテキスト>", "body": "<見出し下の本文>" }` の形にする
- `body` から HTML コメント (`<!-- ... -->`) を除去
- `body` の前後の空白行を `trim`
- 値が **入れ子になっている項目 (`## 連絡先`)** は、さらに `### ` で分割して同じ要領で扱う
- ブロックが存在しない項目は **その項目を出力しない** (空値で埋めない)
- 見出しは表記揺れに寛容に扱う (`## 氏名` / `## 氏名 / Name` / `## Name` のいずれもマッチ)

#### config.md から取り出す項目

| 期待する見出し (例) | 値の意味 |
|---|---|
| `## サイトタイトル` | `site_title` |
| `## キャッチコピー` | `tagline` |
| `## テーマカラー` | `theme_color` (HEX) |
| `## アクセントカラー` | `accent_color` (HEX) |
| `## 表示言語` | `language` (`ja` / `en` など) |
| `## 顔写真のファイル名` | `photo` (相対パス) |
| `## 連絡先` | 入れ子。`### メールアドレス` / `### GitHub` / `### X (Twitter)` / `### LinkedIn` / `### Website` をそれぞれ取得 |
| `## 表示するセクションと順番` | 番号付きリストをそのままパースして `sections` の配列に |
| `## 自己紹介 (About)` | 本文セクション |
| `## スキル / Skills` | 本文セクション (任意) |
| `## 学歴 / Education` | 本文セクション (任意) |

#### career/profile.md から取り出す項目

| 期待する見出し (例) | 値の意味 |
|---|---|
| `## 氏名` | `name` |
| `## ふりがな` | `name_kana` (任意) |
| `## 英語表記` | `name_en` (任意) |
| `## キャリア総年数` | `career_years` |
| `## 自己紹介 (短く)` | プロフィールカード下の短い bio (任意) |
| `## 生年月日` | `birthday` (任意・拡張) |
| `## 居住地` | `location` (任意・拡張) |
| `## 話せる言語` | `languages` (任意・拡張、箇条書きを配列化) |

#### career/work-history.md から取り出す項目

- `## ` 行で全エントリに分割 (1 件 = 1 エントリ。名称は会社名・案件名・イベント名など)
- 各エントリ内をさらに `### ` で分割し、以下を取り出す:
  - `### 種別` → `type` (**本業 / 副業 / 活動** のいずれか。**省略されているエントリは本業として扱う** — 後方互換)
  - `### 期間` → `period`
  - `### 役職` → `role`
  - `### やったこと` → `tasks` (箇条書きを配列化)
  - `### 使用技術` → `tech`
  - `### 成果` → `achievements` (箇条書きを配列化)
- 並び順は Markdown 上の順 (init 時に決めた順番)。種別の混在順は保持しつつ、レンダリング時に種別ごとにグループ化する
- `### 〇〇` ブロックが存在しないフィールドは出力時に **その行ごと省略**

> パースに失敗したファイルがあれば、ユーザーに **具体的なファイル名と原因** を伝えて中断してください。「## 見出しが見つからない」「期待した値が空」などは具体的に。空値で勝手に埋めないこと。

### B-1.5. テーマ方向性のヒアリング

`portfolio.html` がまだ無い状態なので、HTML 生成の前に **デザインの方向性** を一度ユーザーに確認します。init で集めたのは「中身」(氏名・職歴) だけなので、ここで「見た目」を一緒に決めます。

まず、現在 `config.md` に書かれている設定を提示します:

```
今 config.md にはこんな設定が入っています:

  サイトタイトル:   <site_title>
  キャッチコピー:   <tagline>
  テーマカラー:     <theme_color>
  アクセントカラー: <accent_color>
  含めるセクション: <sections のカンマ区切り>

このまま生成しますか? それともここで方向性を決め直しますか?

  1) このまま生成する (テンプレートの初期値で OK な人向け)
  2) テーマ・色・構成を決め直したい
  3) イメージがない (こちらから案を提案します)
```

#### 選択 1) - そのまま B-2 へ

特に何もせず、`### B-2. 顔写真の処理` に進みます。

#### 選択 2) - 方向性を決め直す対話

順番に聞いていきます。**1 問ずつ短く**。「スキップ」と言われた項目は現状値のままにします。

**Step a. 雰囲気のヒアリング**

```
どんな雰囲気のポートフォリオにしたいですか?
  1) 落ち着き / プロフェッショナル (ビジネスライク)
  2) カジュアル / 親しみやすい
  3) クリエイティブ / 個性的
  4) シンプル / ミニマル
  5) ダーク / モダン
  6) その他 (自由記入: 「和風」「春っぽく」など何でも)
```

選ばれた雰囲気を `$VIBE` として保持。`6)` の場合は自由記入をそのまま `$VIBE` に格納します。

**Step b. カラー候補の提示**

`$VIBE` に応じて、テーマカラー + アクセントカラーの組を **3〜4 個** 提案します。各候補は HEX で表示し、簡単な日本語の説明を添えてください。例 (落ち着き系の場合):

```
落ち着いた雰囲気には、こんな配色がよく合います:

  1) コーポレートブルー   テーマ #1E40AF / アクセント #F59E0B
  2) チャコール & ゴールド テーマ #1F2937 / アクセント #D4A35F
  3) ネイビー & ベージュ   テーマ #1E3A8A / アクセント #E0C9A6
  4) 自分で HEX を指定する
```

ユーザーが選んだ番号の組を `theme_color` / `accent_color` として保持。`4)` の場合は HEX を 2 つ聞き取る (例: `#1E40AF`)。HEX 形式 (`#` + 6 桁の 16 進) でなければ「`#` で始まる 6 桁の英数字で教えてください」と再確認すること。

> 候補は `$VIBE` に応じて変える: カジュアル → 暖色寄り / クリエイティブ → 鮮やか / シンプル → モノトーン寄り / ダーク → 黒+発色アクセント、など。`6)` の自由入力には、その記述に合わせて Claude が候補を即興で組み立てる (例: 「和風」→ 藍色 + 朱色)。

**Step c. サイトタイトルの提案**

`career/profile.md` の氏名と `career/work-history.md` の最新の役職から、自動でタイトル案を 2〜3 個作って提示します:

```
サイトタイトルは何にしますか? (このままでも OK)

  現在: <site_title>
  案 1: <name> — Portfolio
  案 2: <name> | <最新の役職>
  案 3: <name> の自己紹介
```

選択 or 自由入力を受け取って `site_title` に格納。スキップなら現状維持。

**Step d. キャッチコピーの提案**

最新の役職・業務・成果から、キャッチコピー案を 2〜3 個提案します:

```
キャッチコピー (一言の肩書き) を 1 行で。ピンとくる案があれば選んでください。

  現在: <tagline>
  案 1: <最新の役職>
  案 2: <キャリア年数> 年の <推定領域>
  案 3: <成果から抽出した強み> を専門にしています
```

選択 or 自由入力 or スキップ。スキップなら現状維持。

**Step e. セクション構成の確認**

```
ポートフォリオに表示するセクションと順番です。これでよいですか?

  現在:
    1. <sections[0]>
    2. <sections[1]>
    ...

  1) このままで OK
  2) 順番を入れ替える / セクションを追加・削除する
```

`2)` を選ばれた場合は、追加できる候補 (profile / about / skills / education / work-history / contact など) を提示し、ユーザーに新しい順序を番号付きリストで答えてもらいます。最終形を `sections` 配列として保持。

**Step f. config.md への反映**

ここまでで決まった値を `Edit` で `config.md` の該当ブロック直下に書き込みます:

| 値 | 編集するブロック |
|---|---|
| `site_title` | `## サイトタイトル` |
| `tagline` | `## キャッチコピー` |
| `theme_color` | `## テーマカラー` |
| `accent_color` | `## アクセントカラー` |
| `sections` | `## 表示するセクションと順番` (番号付きリストに展開) |

> **必ず守る**: 見出し行 (`## ...`) / HTML コメント (`<!-- ... -->`) / 空行は絶対に消さない。値の行のみを書き換えます。スキップされた項目はそもそも `Edit` しないこと。

#### 選択 3) - 「イメージなし、提案して」

`career/work-history.md` を Claude が読み、業務領域・最新の役職・キャリア年数から **方向性ごと提案** します。例:

```
お仕事の内容を見ました。たとえばこんな方向性はいかがですか?

  案 A 「落ち着きエンジニア」
     雰囲気:        落ち着き / プロフェッショナル
     色:            テーマ #1E40AF / アクセント #F59E0B
     サイトタイトル: <name> — Portfolio
     キャッチコピー: <最新の役職> · <キャリア年数> 年

  案 B 「ミニマル」
     雰囲気:        シンプル / ミニマル
     色:            テーマ #475569 / アクセント #84CC16
     サイトタイトル: <name>
     キャッチコピー: <得意領域>

  案 C 「ダークモダン」
     雰囲気:        ダーク / モダン
     色:            テーマ #0F172A / アクセント #38BDF8
     サイトタイトル: <name> · Works
     キャッチコピー: <最新の役職>

  案 D 自分で決め直す (= 2) の対話フローへ)
```

ユーザーが案を選んだら、その内容を 2) の **Step f.** と同じ手順で `config.md` に書き込みます。「もう少し明るく」「青系がいい」などの要望が出たら、その方向で再提案するか、Step a〜e の対話に切り替えます。`案 D` が選ばれたら 2) の Step a から開始します。

### B-1.6. 反映の確認

書き換えが完了したら、書き換え後の `config.md` の該当ブロックを `Read` し直して、想定どおりに保存されていることを確認します (見出しやコメントが壊れていないかも合わせて)。問題があれば再度 `Edit` で修正してから B-2 に進みます。

### B-2. 顔写真の処理

`config.md` の `## 顔写真のファイル名` ブロックの値 (相対パス) を確認:

- 存在し、サイズ < 500KB → そのまま `<img src="assets/photo.jpg">` で参照
- 存在し、サイズ >= 500KB → 警告 (「圧縮を推奨」) を出して同じく相対パス参照
- 存在しない / `## 顔写真のファイル名` ブロックが無い / 値が空 → 顔写真を出さず、警告メッセージを出力

> base64 埋め込みはしない。`portfolio.html` と `assets/` をセットで配布すれば表示できる前提とする。

### B-3. HTML 生成

以下の構造で 1 ファイルの HTML を組み立てます。CSS は `<style>` でインライン、JavaScript は使いません。

```html
<!doctype html>
<html lang="{{language}}">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width,initial-scale=1">
  <title>{{site_title}}</title>
  <style> /* theme_color / accent_color を CSS 変数化 */ </style>
</head>
<body>
  <header>
    <img src="{{photo}}" alt="{{name}}" class="hero-photo">
    <h1>{{name}}</h1>
    <p class="tagline">{{tagline}}</p>
  </header>

  <main>
    <!-- config.md の sections の順序で出し分け -->
    <section id="profile">
      <h2>Profile</h2>
      <dl>
        <dt>氏名</dt><dd>{{name}} ({{name_kana}})</dd>
        <dt>キャリア</dt><dd>{{career_years}} 年</dd>
        <!-- birthday / location / languages があれば出す。空文字なら省く -->
      </dl>
    </section>

    <section id="about">
      <h2>About</h2>
      <!-- config.md の ## About を Markdown → HTML 変換 -->
    </section>

    <!-- 経歴セクション: 本業 / 副業 / 活動 を 3 つのサブブロックに分けて表示 -->
    <!-- エントリが 1 件もないカテゴリは、その <h3> + <ol> ブロックごと出力しない -->
    <section id="work-history">
      <h2>Career / 経歴</h2>

      <h3>本業</h3>
      <ol class="timeline"><!-- 種別=本業 のエントリ --></ol>

      <h3>副業</h3>
      <ol class="timeline"><!-- 種別=副業 のエントリ --></ol>

      <h3>活動</h3>
      <ol class="timeline"><!-- 種別=活動 のエントリ --></ol>
    </section>

    <section id="contact">
      <h2>Contact</h2>
      <ul>
        <li>Email: <a href="mailto:{{email}}">{{email}}</a></li>
        <!-- github / x / linkedin / website があれば出す。空文字なら省く -->
      </ul>
    </section>
  </main>

  <footer>
    <small>Generated by cc-PortfolioKit · {{今日の日付 YYYY-MM-DD}}</small>
  </footer>
</body>
</html>
```

> **性別 (gender) フィールドは HTML に一切出力しないこと**。たとえ古いテンプレートで残っていても無視する。

**CSS 要件**:
- レスポンシブ (スマホで縦並び、PC で横並びになる箇所がある)
- `theme_color` を主色、`accent_color` をアクセントに使う
- フォント: `"Hiragino Sans", "Yu Gothic", system-ui, sans-serif`
- 顔写真は `border-radius: 50%; width: 160px;`
- タイムラインは左にラインを引いて各エントリにドットを置く
- リンクは `accent_color`、hover で下線
- ダークモード対応 (`@media (prefers-color-scheme: dark)`)
- 印刷時に背景色が消えても読める (`@media print`)

**Markdown → HTML 変換のサポート範囲** (外部ライブラリ不使用):
- `## ` → `<h2>`、`### ` → `<h3>`
- `- ` → `<ul><li>`
- `**text**` → `<strong>`、`*text*` / `_text_` → `<em>`
- `` `code` `` → `<code>`
- `[text](url)` → `<a href="url">`
- 連続段落は `<p>` で囲む
- HTML コメント (`<!-- ... -->`) は出力に含めない

**XSS 対策 (必須)**:
- ユーザー入力の `<`, `>`, `&`, `"`, `'` を必ずエスケープしてから HTML に流し込む
- `script` / `style` タグ、`on*` 属性は出力 HTML に含めない

### B-4. 書き出しと検証

1. `Write` で `./portfolio.html` を作成
2. `Bash` で `wc -c portfolio.html` を実行し、ファイルサイズを確認
3. 健全性チェック: `<title>` が空でないか、`<h1>` が `name` を含むか、各 `<section>` が出力されているか

### B-5. 完了報告

```
✅ portfolio.html を生成しました!

  パス: ./portfolio.html
  サイズ: <N KB>
  含めたセクション: profile, about, work-history, contact
  顔写真: <埋め込んだ / 警告内容>

確認方法:
  open portfolio.html        # macOS
  start portfolio.html       # Windows

内容を編集したい場合は、もう一度 /cc-portfoliokit:create を実行してください。
編集メニューが出てきます!
```

## ブランチ C: 編集メニュー

入力 Markdown も `portfolio.html` も揃っている状態。ユーザーは「内容を変えたい」「再生成だけしたい」のいずれかを期待しています。

### C-1. メニュー表示

```
ポートフォリオは既に生成済みです (portfolio.html)。
何をしますか?

  1) 細かい項目を変えたい (氏名・連絡先・職歴など、項目別に対話で編集)
  2) テーマを決め直したい (雰囲気・色・タイトル等を一通り見直し)
  3) 色だけ変えたい (テーマカラー / アクセントカラー)
  4) 内容を変えずに再生成だけしたい (Markdown を手で編集済みの場合など)
  5) イメージがない、提案してほしい (こちらから方向性を提案します)
  6) キャンセル
```

ユーザーの回答に応じて以下に分岐:

| 選択 | 進む先 |
|---|---|
| 1) | **C-3** (詳細編集メニュー) |
| 2) | **C-4** (テーマ決め直しウィザード) |
| 3) | **C-5** (色だけ変更) |
| 4) | **C-2** (単純再生成) |
| 5) | **C-6** (AI 提案) |
| 6) | 「キャンセルしました」と表示して終了 |

> どの分岐に進んでも、最後は B-1 以降を実行して `portfolio.html` を再生成します (キャンセルを除く)。

> ユーザーが「決められない」「迷う」と言ったら、`5) イメージがない` を勧めると親切です。提案を見てから選ぶほうが心理的負担が低いので。

### C-2. 単純再生成

ブランチ B の Step B-1 以降をそのまま実行します。完了報告は B-5 と同様ですが、冒頭を `✅ portfolio.html を更新しました!` に変えてください。可能であれば旧 `portfolio.html` の `<footer>` から前回生成日付を抽出し、「前回 YYYY-MM-DD → 今回 YYYY-MM-DD」と併記します。

### C-3. 対話で項目編集

以下のメニューを表示します。

```
どの項目を編集しますか? (複数選んでも OK、番号をカンマ区切りで)

  1) サイトタイトル / キャッチコピー
  2) テーマカラー
  3) 自己紹介 (About)
  4) 氏名 / ふりがな / キャリア総年数
  5) 連絡先 (email / github / その他)
  6) 顔写真のファイル名
  7) 経歴を追加する (本業 / 副業 / 活動 から選択)
  8) 既存の経歴を編集する (種別変更も可)
  9) 戻る
```

各項目で、ユーザーから新しい値を聞き取り、対応する Markdown ファイルを `Edit` で **値の置換のみ** で書き換えます (見出し / コメント / 他のブロックは保持)。書き換え対象の対応表:

| メニュー | 編集対象 (すべて YAML ではなく `## 見出し` ブロック直下の値) |
|---|---|
| 1) | `config.md` の `## サイトタイトル` / `## キャッチコピー` ブロック |
| 2) | `config.md` の `## テーマカラー` / `## アクセントカラー` ブロック |
| 3) | `config.md` の `## 自己紹介 (About)` ブロック |
| 4) | `career/profile.md` の `## 氏名` / `## ふりがな` / `## キャリア総年数` ブロック |
| 5) | `config.md` の `## 連絡先` 配下の `### メールアドレス` / `### GitHub` / `### X (Twitter)` / `### LinkedIn` / `### Website` |
| 6) | `config.md` の `## 顔写真のファイル名` ブロック |
| 7) | `career/work-history.md` に新規 `## 名称` ブロックを追加。**最初に「本業 / 副業 / 活動」のどれか** を尋ね、選ばれた種別の同一カテゴリブロックの末尾に挿入する。続けて init と同じ `### 種別 / ### 期間 / ### 役職 / ### やったこと / ### 使用技術 / ### 成果` 形式でヒアリングして書き出す |
| 8) | `career/work-history.md` の既存 `## 名称` ブロックを 1 つ選び、該当する `### サブ項目` 直下の値を `Edit`。**種別 (本業 / 副業 / 活動) の変更も可能**。種別を変更した場合は、ブロックを該当カテゴリの並び順位置に移動する |

> **編集時のルール**: 「## 見出し」行・「### サブ見出し」行・空行・HTML コメント (`<!-- ... -->`) は絶対に消さない。値の行だけを書き換える。ブロック自体を削除したい場合 (例: ふりがな不要) は、ユーザーが明示的に指示したときだけ、見出しから次の見出しの直前までを丸ごと削除する。

編集が終わったら必ずユーザーに「他に変更したい項目はありますか?」と尋ね、無ければ B-1 以降を実行して再生成します。

完了報告は C-2 と同様。加えて「今回編集した項目」のリストも併記してください。

> **性別 (gender) の編集項目は提供しない**。この設計では性別は扱わない。

### C-4. テーマ決め直しウィザード

ブランチ B の **B-1.5 の 2) (Step a〜f)** をそのまま実行します。完了したら C-2 (単純再生成) に合流して `portfolio.html` を更新します。

> 「テーマを根本から見直したい」というユーザー向け。色だけでなく、サイトタイトル / キャッチコピー / セクション順までまとめて整え直すフェーズ。

### C-5. 色だけ変更

短い対話で色だけ変えます。サイトタイトルや構成には触りません。

```
今のテーマカラー:     <theme_color>
今のアクセントカラー: <accent_color>

新しい色をどう決めますか?
  1) 雰囲気を選んで候補から決める (おすすめ)
  2) HEX で直接指定する
```

- `1)` → ブランチ B の **B-1.5 の Step a (雰囲気) と Step b (カラー候補)** だけを実行し、選ばれた組を `theme_color` / `accent_color` として保持。
- `2)` → テーマカラーとアクセントカラーの HEX をそれぞれ聞き取る (HEX 形式バリデーション付き)。

決まった値を `Edit` で `config.md` の `## テーマカラー` / `## アクセントカラー` ブロック直下に書き込みます (見出し・コメント・空行を壊さない)。書き込み後は B-1.6 と同様に `Read` で確認 → C-2 (単純再生成) に合流。

### C-6. AI 提案

ブランチ B の **B-1.5 の 3) (AI 提案)** をそのまま実行します。Claude が `career/work-history.md` を読み、案 A / B / C を提示。ユーザーが選んだ案を `config.md` に書き込んだあと、C-2 (単純再生成) に合流。

> ここでもユーザーが「もう少しこういう感じが…」と要望を出したら、その方向で再提案するか、対話 (C-4) に切り替えてかまいません。「迷ったら提案してもらえる」がこのモードの存在意義です。

## 共通の制約

- **JavaScript は使わない**
- **外部 CSS / フォント CDN は使わない** (オフライン表示可)
- **portfolio.html 以外のファイルは、ユーザーが明示的に指示した編集 (ブランチ C-3) のときだけ書き換える**
- **入力に書かれていない情報を勝手に作らない** (氏名・経歴を捏造しない)
- **テンプレートを勝手に作らない** — 素材ファイルが無い場合は必ず init コマンドへ誘導する
- 空欄のフィールドは、その項目ごと HTML から省く
- ユーザー入力は必ず HTML エスケープしてから出力
- 性別 (gender) は HTML 出力にも編集メニューにも含めない
- **入力ファイルは YAML フロントマターを使わない `## 見出し` 構造**。パース時も `Edit` 時もこの前提で扱う。ユーザーが手編集する前提なので、見出し / コメント / 空行を勝手に壊さない
